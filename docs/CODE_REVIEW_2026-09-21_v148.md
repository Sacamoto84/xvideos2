## 1. Контекст и цели прохода

В рамках прохода 170 проведён детальный аудит стабильности жизненного цикла превью-карточек видео и ниш в модулях Red (`:feature-r`) и X (`:feature-x`):

1. **Исправление вычисления пути постера в TikTok-режиме (`RedUrlVideoImageAndLongClickTikTok.kt` в `:feature-r`)**:
   - **Проблема**: Значение `imageUrl` рассчитывалось через `remember { mutableStateOf(run { ... }) }` без передачи ключей зависимости. При переиспользовании элементов в вертикальном пейджере (TikTok-лента) или смене элемента `imageUrl` оставался неизменным и отображал постер предыдущего видео. Кроме того, обёртка в `mutableStateOf` была избыточной для производного вычисляемого значения.
   - **Решение**: Приведено к единому эталонному виду (как в `RedUrlVideoImageAndLongClick.kt`):
     ```kotlin
     val imageUrl = remember(item.id, item.userName) {
         val imagePath = "${AppPath.r_cache_download}/${item.userName}/${item.id}.jpg"
         if (File(imagePath).exists()) {
             imagePath
         } else {
             item.urls.poster ?: item.urls.thumbnail
         }
     }
     ```

2. **Оптимизация ключа зависимости подписки на нишу (`NichePreview2.kt` в `:feature-r`)**:
   - **Проблема**: В вызове `remember(niches()) { derivedStateOf { ... } }` в качестве ключа передавался результат вызова лямбды `niches()`. Это приводило к повторному лишнему выполнению функции-поставщика аргументов на каждом цикле рекомпозиции.
   - **Решение**: Вызов переведён на прямой стабильный строковый идентификатор `niche.id`: `remember(niche.id) { derivedStateOf { ... } }`.

3. **Связывание списка отслеживаемых ниш в экране детального просмотра (`ScreenNiche.kt` в `:feature-r`)**:
   - **Проблема**: В `ScreenNiche.kt` вычисление `isFollowed` через `derivedStateOf` было привязано только к `vm.niche.id`: `remember(vm.niche.id)`. При подмене или обновлении ссылки на коллекцию `followedList` состояние могло не обновиться.
   - **Решение**: Добавлен ключ зависимости: `remember(vm.niche.id, followedList) { derivedStateOf { ... } }`.

4. **Сброс состояния видеоплеера при переиспользовании ячеек в ленте X (`UrlVideoImageAndLongClickX.kt` в `:feature-x`)**:
   - **Проблема**: Флаг активности встроенного превью-видео `isVideo` хранился в неключевом `remember { mutableStateOf(false) }`. При скролле и переиспользовании ячеек грида видеоплеер мог оставаться активным для нового видео, показывая рассинхронизированный контент.
   - **Решение**: Добавлен ключ `item.id`: `remember(item.id) { mutableStateOf(false) }`, гарантирующий сброс в режим постера при смене контента ячейки.

5. **Инварианты**:
   - P2P модуль (`core/.../p2p/`) строго заморожен и не изменялся.

## 2. Изменения по файлам

### 2.1. Модуль `:feature-r`
- **`feature-r/src/main/java/com/client/xvideos/r/ui/video/player_row_mini/RedUrlVideoImageAndLongClickTikTok.kt`**:
  - `imageUrl`: удалена лишняя `mutableStateOf` обёртка, добавлены ключи `remember(item.id, item.userName)`.
- **`feature-r/src/main/java/com/client/xvideos/r/ui/explorer/tab/niches/NichePreview2.kt`**:
  - `isFollowed`: оптимизирован ключ на `remember(niche.id)` без повторного вызова лямбды `niches()`.
- **`feature-r/src/main/java/com/client/xvideos/r/ui/niche/ScreenNiche.kt`**:
  - `isFollowed`: добавлен ключ зависимости `followedList` в `remember(vm.niche.id, followedList)`.

### 2.2. Модуль `:feature-x`
- **`feature-x/src/main/java/com/client/xvideos/x/screens/common/UrlVideoImageAndLongClickX.kt`**:
  - `isVideo`: добавлен ключ `item.id` в `remember(item.id) { mutableStateOf(false) }` для надёжного сброса состояния при рециркуляции.
