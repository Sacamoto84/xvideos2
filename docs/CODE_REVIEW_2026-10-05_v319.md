## Находки

Все находки — по чтению кода: на устройствах ничего не запускалось и не
замерялось, тестов нет.

### S1 — Плейлист X запрашивается с заголовками сайта R. Средняя.

[core/.../videoplayer/util/M3U8Helper.kt:70](../core/src/main/java/com/client/xvideos/common/videoplayer/util/M3U8Helper.kt:70)

Разбор HLS-плейлиста при отсутствии заголовков подставляет набор с `Referer` и
`Origin` сайта R (строка 41). Экраны X создают `MediaPlayerHost` без заголовков
([VideoPlayerContentView.kt:149](../feature-x/src/main/java/com/client/xvideos/x/screens/videoplayer/molecule/VideoPlayerContentView.kt:149)).
При открытии ролика X приложение само запрашивает master-плейлист ради списка
качеств и шлёт серверу раздачи X заголовки другого сайта. Один сайт узнаёт о
другом; сервер, проверяющий `Referer`, ответит отказом — список качеств
останется пустым.

Само воспроизведение идёт другим клиентом без этих заголовков. Константа
одного раздела лежит в общем модуле `core`.

Чего у находки нет: запрос не перехватывался, ответ сервера не проверялся.

### C1 — Эффект поворота выставляется даже при нулевом повороте. Средняя.

[core/.../videoplayer/util/CMPlayer2.kt:88](../core/src/main/java/com/client/xvideos/common/videoplayer/util/CMPlayer2.kt:88)

Каждый плеер получает `setVideoEffects` со списком из одного преобразования
поворота, в том числе когда автоповорот выключен и угол равен нулю. Непустой
список включает конвейер обработки кадров — и у мини-плееров в списках, и у
плееров ленты R
([RedPooledVideoPlayer.kt:157](../feature-r/src/main/java/com/client/xvideos/r/ui/video/RedPooledVideoPlayer.kt:157)).
Пустой список при выключенном повороте этого не требует.

Чего у находки нет: как media3 обрабатывает тождественное преобразование, не
проверялось; нагрузка на устройстве не замерялась.

### T1 — Смена адреса не отменяет разбор прежнего плейлиста. Низкая.

[core/.../videoplayer/host/MediaPlayerHost.kt:88](../core/src/main/java/com/client/xvideos/common/videoplayer/host/MediaPlayerHost.kt:88)

`loadUrl()` запускает новый разбор, не отменяя предыдущий; оба пишут списки
качеств, дорожек и субтитров в один хост. Ответ для старого адреса, пришедший
позже, подменит список качеств нового ролика.

### C2 — Дорожки с языком вида `pt-BR` отбрасываются. Низкая.

[core/.../videoplayer/util/M3U8Helper.kt:35](../core/src/main/java/com/client/xvideos/common/videoplayer/util/M3U8Helper.kt:35)

`LANGUAGE="(\w+)"` не принимает дефис, а без языка `extractAudioTrack()` и
`extractSubtitleTrack()` возвращают `null`. Аудиодорожки и субтитры с
региональным тегом не попадают в список выбора.

### C3 — Эффекты плеера привязаны не ко всем своим входам. Низкая.

[core/.../videoplayer/rememberExoPlayerWithLifecycle.kt:105](../core/src/main/java/com/client/xvideos/common/videoplayer/rememberExoPlayerWithLifecycle.kt:105)

Загрузка источника перезапускается только по смене `url`, хотя читает
`headers`, `drmConfig` и `isLiveStream`. Эффекты повтора, качества и поворота
не привязаны к экземпляру плеера. `trackSelector` запомнен без ключа, плеер — с
ключом `context`. Сейчас вызывающие меняют только адрес, дефект скрытый.

### T2 — Пул плееров освобождается раньше снятия foreground-режима. Низкая.

[core/.../videoplayer/feed/FeedPlayerState.kt:306](../core/src/main/java/com/client/xvideos/common/videoplayer/feed/FeedPlayerState.kt:306)

В `rememberFeedPlayerState` эффект `release()` объявлен после
`LifecycleStartEffect`. Эффекты снимаются в обратном порядке: сначала
`release()`, затем `setForegroundMode(false)` на уже освобождённом пуле.

Чего у находки нет: падения не наблюдалось — иначе его видели бы при каждом
выходе из ленты. Порядок держится на том, что пул терпит вызовы после
освобождения; поведение `PlayerPool` не проверялось.

### C4 — `modifier` плеера применяется не к корню. Низкая.

[core/.../videoplayer/util/CMPlayer2.kt:124](../core/src/main/java/com/client/xvideos/common/videoplayer/util/CMPlayer2.kt:124)

`CMPPlayer2` применяет `modifier` к вложенному `ContentFrame`, корневой `Box`
всегда `fillMaxSize()` с чёрным фоном. Заданный вызывающим размер получает
рамка видео, а подложка занимает всё доступное место.

### A1 — Master-плейлист скачивается дважды. Низкая.

[core/.../videoplayer/host/MediaPlayerHost.kt:77](../core/src/main/java/com/client/xvideos/common/videoplayer/host/MediaPlayerHost.kt:77)

Хост сам качает и разбирает плейлист ради списка качеств, затем тот же плейлист
качает плеер. Список дорожек плеер отдаёт после подготовки — второй запрос,
отдельный клиент и разборщик на регулярных выражениях не нужны. Это же снимает
S1 и C2.

### C5 — Адреса потоков с именем сайта в логе. Низкая.

[core/.../videoplayer/util/M3U8Helper.kt:75](../core/src/main/java/com/client/xvideos/common/videoplayer/util/M3U8Helper.kt:75)

Строки 75 и 83 пишут в лог полный адрес потока при каждом сбое загрузки

### A2 — Мёртвые перегрузки и параметры. Низкая.

[core/.../videoplayer/util/ExoPlayerLifecycle.kt:41](../core/src/main/java/com/client/xvideos/common/videoplayer/util/ExoPlayerLifecycle.kt:41)

Две из трёх перегрузок `getExoPlayerLifecycleObserver` и вторая перегрузка
`createPlayerListener` в боевом коде не вызываются; параметр `sourceUrl`
слушателя не используется; в `MediaPlayerHost` остались закомментированные
методы и устаревший `seekTo(Int)`.

Чего у находки нет: используются ли перегрузки в тестах, не проверялось.

### Проверено, находок нет

- **Повторная перемотка в ту же точку.** `StaticPlayer` сбрасывает `seekToTime`
  на ближайшем обновлении позиции, поэтому «в начало» дважды подряд работает.
- **Освобождение одиночного плеера.** Слушатель снимается и воспроизведение
  останавливается до `release()`, владелец плеера один.
- **Экран не гаснет.** Счётчик играющих на слабых ключах, захват и
  освобождение парные.
- **Прогрев ленты.** Замена элемента снимает старый перед добавлением нового,
  добавление сопровождается пересборкой очереди, методы проверяют главный поток.
- **Дисковый кэш ленты.** Один экземпляр на процесс, вытеснение по давности,
  предел 256 МБ.
- **Таймауты видео.** Общего таймаута запроса нет, только на соединение и на
  паузу между байтами.
