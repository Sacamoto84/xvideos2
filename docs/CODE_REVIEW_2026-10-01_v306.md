## Находки

### C1 — Плеер при открытии записывает в историю позицию 0. Средняя.

[VideoPlayerContentView.kt:201](../feature-x/src/main/java/com/client/xvideos/x/screens/videoplayer/molecule/VideoPlayerContentView.kt:201),
[LocalVideoPlayerContent.kt:87](../feature-x/src/main/java/com/client/xvideos/x/screens/videoplayer/molecule/LocalVideoPlayerContent.kt:87)

`LaunchedEffect(host.isPaused)` при открытии сразу вызывает `onSaveProgress`,
а `MediaPlayerHost` ещё ничего не сообщил: `currentTime = 0`, `totalTime = 0`
(позиция старта лежит отдельно, в `playFromTime`). Ролик уже есть в истории,
поэтому `updateProgress` не отсекает позицию меньше секунды и записывает
`lastPositionMs = 0`. Текущий сеанс продолжает с нужного места: позицию плеер
получил при создании, и ExoPlayer сразу после `seekTo` отдаёт её как текущую.
Но до следующего сохранения через 3 секунды в истории лежит 0: если процесс
завершится в это окно (смахнули из недавних, нехватка памяти, падение),
«Продолжить просмотр» для ролика пропадает. Каждое открытие — лишняя запись
файла истории.

Уточнено при исправлении: в первой редакции отчёта потеря позиции
приписывалась закрытию плеера во время буферизации — это неверно, после
`seekTo` текущая позиция уже равна позиции старта.

### C2 — Сбой подгрузки индекса моделей зацикливает запросы. Средняя.

[ScreenX_ActressesIndex.kt:100](../feature-x/src/main/java/com/client/xvideos/x/screens/actresses/ScreenX_ActressesIndex.kt:100)

После `53bc3255` сбой сети не завершает список, только сбрасывает

Без сети запросы идут друг за другом без паузы, ошибки на экране нет.

### C3 — Страница 0 канала загружается дважды. Средняя.

[ChannelVideosPager.kt:71](../feature-x/src/main/java/com/client/xvideos/x/screens/channel/molecule/ChannelVideosPager.kt:71)

`loadInitial` грузит страницу 0 сам и не отмечает её в `loadingPages`. Пейджер
показан сразу (имя шапки не пустое), его эффект видит пустую страницу без
загрузки и вызывает `loadPage(0)`. При открытии канала и каждой смене сортировки
или фильтра — два одинаковых запроса, с перебором models/channels — до четырёх.

### C4 — Ошибка первой загрузки канала не показывается. Средняя.

[ScreenX_Channel.kt:187](../feature-x/src/main/java/com/client/xvideos/x/screens/channel/ScreenX_Channel.kt:187)

фильтр моделей) так и остаётся заглушкой. Ветка загрузки, вынесенная в

## Что осталось открытым

Все находки закрыты в `0222cb9b`.

Замечено вне объёма прохода (не Compose UI): `fetchHtml` в сетевом слое
пишет в лог полный адрес каждого запроса — то же правило GEMINI.md о логах,
что и L1.

Отрицательные результаты:

- Правила Atomic UI проверены скриптом по всем файлам `screens/`: у каждого
  файла в `atom/` и `molecule/` есть `@Preview`, молекулы и атомы не принимают
  ScreenModel; нарушения п. 1 — только A1.
- Правило `CLAUDE.md` про `remember` с ключом-`SnapshotStateList` не нарушено:
  `selectedIds` истории читается внутри лямбд в момент вызова.
- Регрессий переноса `f07eb47e` в физике шапки канала не найдено: порядок
  модификаторов `scrollable`/`onSizeChanged` эквивалентен прежнему, состояние
  смещения по-прежнему `rememberSaveable`.
- `OrientationAndSystemBarsEffect` возвращает портрет при уходе с экрана;
  активность объявлена `portrait` с `configChanges`, плеер при повороте не
  пересоздаётся.
