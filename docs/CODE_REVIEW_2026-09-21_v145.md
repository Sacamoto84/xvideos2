## 1. Контекст и цели прохода

Проведён глобальный аудит контейнеров `Scaffold` и Edge-to-Edge верстки во всех модулях приложения (`:app`, `:feature-x`, `:feature-l`, `:feature-r`):

1. **Сквозная изоляция `Scaffold` от неявного внедрения системных инсетов**:
   - В Compose Material 3 `Scaffold` по умолчанию рассчитывает `contentWindowInsets` на базе строки состояния и панели навигации (`ScaffoldDefaults.contentWindowInsets`).
   - В многоуровневой навигации (Voyager + главный Scaffold + таб Scaffold + субтабы) это приводило к паразитным повторным отступам, скачкам разметки и рассинхронизации высот элементов.
   - **Решение**: Во всех оставшихся `Scaffold` во всех модулях проекта явно задан сброс `contentWindowInsets = WindowInsets(0, 0, 0, 0)`. Контроль над верхними и нижними отступами передан конкретным контейнерам экранов.

2. **Нормализация отступов сетки в табе «Группы» раздела R (`R_ScreenNichesTab.kt`)**:
   - Ранее список категорий использовал `contentPadding = WindowInsets.displayCutout.asPaddingValues()`, что добавляло отступы со всех 4 сторон (включая боковые стороны в альбомной ориентации).
   - **Решение**: Список переведён на стандартный `contentPadding = PaddingValues(top = getTopInsetDp())`, аналогично `R_ScreenGifsTab.kt`.

3. **Гигиена кода и очистка устаревших комментариев**:
   - В `ScreenAlbum.kt` удалён закомментированный вызов `//.displayCutoutPadding()`.
