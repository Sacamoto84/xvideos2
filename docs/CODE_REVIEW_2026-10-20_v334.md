## Находки

Классы: `S` безопасность и приватность, `C` корректность, `T` конкурентность и
жизненный цикл, `A` архитектура и учёт.

### S1 — При возврате в заблокированное приложение плеер около 0,1 с играет под экраном замка. Низкая.

[ExoPlayerLifecycle.kt:19](../core/src/main/java/com/client/xvideos/common/videoplayer/util/ExoPlayerLifecycle.kt:19) ·
[RedPooledVideoPlayer.kt:150](../feature-r/src/main/java/com/client/xvideos/r/ui/video/RedPooledVideoPlayer.kt:150) ·
[MainActivity.kt:326](../app/src/main/java/com/client/xvideos/MainActivity.kt:326)

Плееры гасятся при закрытом сеансе по `LocalAppLockActive`. Это значение
композиции: `MainActivity` ставит `isAppLocked` в `onStart`, а до плееров
оно доходит только со следующей перекомпоновкой.

События жизненного цикла приходят раньше неё. Вот что получается:

- ядро плеера (`rememberExoPlayerWithLifecycle`, им пользуются X и L) на
  `ON_RESUME` ставит `playWhenReady = !isPause()`, а замок не смотрит
  вовсе;
- лента R в `LifecycleStartEffect` на `ON_START` читает `isAppLockActive` из
  прошлой композиции, где замка ещё нет.

Итог: вернувшаяся под замок `MainActivity` запускает ролик, и он играет до
её `onPause`, то есть пока поднимается `LockActivity`.

На эмуляторе, сборка среза. Замок включён, автоблокировка «Сразу при
выходе», «Защита в диспетчере задач» выключена. Плеер X открыт на ролике,
«Домой», через 2,6 с — возврат тем же интентом запуска:

```
05:38:04.457  MainActivity onStart (сеанс закрыт → запрос LockActivity)
05:38:04.467  MainActivity onResume
05:38:04.470  AudioTrack плеера: started
05:38:04.564  MainActivity onPause
05:38:04.567  AudioTrack плеера: paused
05:38:04.604  LockActivity onResume
```

Около 97 мс воспроизведения. Пауза пришла от `ON_PAUSE`, а не от флага
замка: перекомпоновка за это время не успела. Картинку не видно, содержимое
под замком закрыто чёрной заглушкой. Слышно ли звук, зависит от громкости:

- у X звук выключен всегда (`isMuted = true`), измеренное воспроизведение
  беззвучно;
- если «Защита в диспетчере задач» включена (так у владельца), флаг замка
  стоит ещё со сворачивания, громкость плеера уже 0 — тоже беззвучно;
- если защита выключена, а плеер со звуком (видео L, лента R), громкость
  всё это время прежняя. Получается короткий обрывок звука из-под экрана
  замка.

Чего у находки **нет**:

- звук не измерен: на эмуляторе не нашлось плеера со звуком (X всегда без
  звука, превью ленты R без звуковой дорожки, видео L не искалось). Вывод
  про звук сделан по коду громкости в `CMPlayer2` и `RedPooledVideoPlayer`:
  её сбрасывает тот же эффект композиции;
- путь R (`ON_START`) прочитан по коду, не измерен;
- телефон не проверялся.

Как чинить — на выбор владельца:

1. Отдавать плеерам состояние замка не значением композиции, а объектом
   состояния (`State<Boolean>` поверх `isAppLocked` / `isAppMinimized`).
   Обработчики `ON_RESUME` и `ON_START` тогда читают его в момент события,
   а после `onStart` там уже `true`.
2. В тех же обработчиках спрашивать источник правды напрямую
   (`AppLockRepository.shouldShowLock`).

### A1 — `LandscapeOrientation` в core нигде не вызывается. Низкая.

[util.android.kt:38](../core/src/main/java/com/client/xvideos/common/videoplayer/util/util.android.kt:38)

Composable из старого плеера: при `isLandscape` ставит `SENSOR_LANDSCAPE`, а в
`reset()` — `SCREEN_ORIENTATION_UNSPECIFIED`. Поиск по всем модулям — ноль
вызовов. Повернуть экран плеера сейчас может только
`OrientationAndSystemBarsEffect` в X.

Вред сейчас — лишний код. Если функцию снова подключат, после выхода из
полноэкранного режима она отменит портретный замок манифеста: при снятой
системной блокировке приложение начнёт поворачиваться целиком. Удалять или
нет — решение владельца (уборка без просьбы не делается).

## Правки

Обе находки исправлены по слову владельца после отчёта: S1 — вариантом 1
(`e4915cdd`), A1 — удалением (`f7a933dd`). Число тестов в README — `7833be9e`.

**S1.**

- `LocalAppLockActive` отдаёт `State<Boolean>` вместо значения.
  `MainActivity` даёт `derivedStateOf { isAppLocked || (isAppMinimized &&
  blurRecentTasks) }` — то же условие, что раньше, но объектом.
- В композиции плееры читают `.value`, поэтому при смене замка
  перекомпонуются как прежде (`CMPlayer2`, громкость и удержание экрана в
  R).
- Обработчики жизненного цикла читают `.value` в момент события:
  - наблюдатель ядра (`getExoPlayerLifecycleObserver`) получил параметр
    `isAppLocked`, и на `ON_RESUME` воспроизведение включается, только если
    замка нет. Значение ему передаёт `rememberExoPlayerWithLifecycle`;
  - лента R в `LifecycleStartEffect` на `ON_START` берёт
    `appLockActive.value`, а не значение из прошлой композиции.
- Чтение объекта состояния вне композиции даёт значение, записанное в
  `onStart` до события: `ON_START` и `ON_RESUME` рассылаются после тел
  `onStart` и `onResume`.
- Тесты наблюдателя: под замком `ON_RESUME` воспроизведение не включает,
  после снятия замка — включает (+2).

**A1.** `LandscapeOrientation` удалена вместе с десятью импортами, которые
были нужны только ей.

## Проверено, замечаний нет

- **Правка T1 прохода 200 (`38585514`).**
  - Сигнал `onTopResumedActivityChanged` приходит на главном потоке, поэтому
    `lockedAtTop` гонок не знает.
  - Переход `MainActivity` → `LockActivity` даёт `false`, потом `true`
    (видно в журнале выше: потеря верха в 04.557, `LockActivity` получила
    его в 04.617).
  - `SplashActivity`, которая закрывает себя в `onCreate`, верхней не
    становится и сигналов не шлёт.
  - Хранитель — `@Singleton` в графе Hilt. `EntryPointAccessors` достаёт
    его из Application-графа, который готов к первому `onCreate` любой
    Activity.
  - Страж `ActivityRotationLockTest` ищет наследников `*Activity(` в
    `src/main` всех модулей. Он не увидит класс, у которого перед Activity
    в списке супертипов стоит интерфейс (`class X : I, ComponentActivity()`);
    сейчас таких нет.
- **Ориентация.** `requestedOrientation` меняет только
  `OrientationAndSystemBarsEffect`:
  - при уходе из полноэкранного режима он возвращает прежнюю ориентацию;
  - при уходе плеера из композиции ставит портрет.

  Если в полноэкранном режиме закрылся сеанс, `LockActivity` встаёт
  портретом по манифесту. После кода плеер снова в альбомной: ориентацию
  держит `MainActivity`. Так и задумано.
- **Системные панели** в полноэкранных экранах L и R прячет
  `HideStatusBarEffect` — заявка, которую снимает уход экрана, а не
  прямой вызов окна.
- **Под замком при работающем приложении** (по коду; сеанс закрылся по событию,
  `MainActivity` на экране). `onSessionLocked` → `isAppLocked` → плеер
  гасится перекомпоновкой, и `ON_RESUME` между этим не приходит. Щель S1
  есть только при возврате из фона.
