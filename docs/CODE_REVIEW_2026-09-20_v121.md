## Находки

### C1 — Преждевременный выход из списка заблокированных в ScreenRedManageBlock. Средняя.

[feature-r/src/main/java/com/client/xvideos/r/ui/manager_block/ScreenRedManageBlock.kt:50-75, 95-105](file:///g:/xvideos2/feature-r/src/main/java/com/client/xvideos/r/ui/manager_block/ScreenRedManageBlock.kt#L50-L75)

В `ScreenRedManageBlock` обработчик системной кнопки «Назад» безусловно вызывал `navigator.pop()`. При этом `rememberLazyListState()` был локализован внутри блока `else` тела списка. При длинном списке заблокированных пользователей и прокрутке вниз нажатие системной кнопки «Назад» или стрелки в тулбаре сразу закрывало экран вместо предварительной плавной прокрутки к началу списка.

**Решение:**
1. `rememberLazyListState()` и `rememberCoroutineScope()` подняты на уровень функции `Content()`.
2. Внедрена двухступенчатая цепочка `BackHandler`:
   ```kotlin
   val isScrolled = blockList.isNotEmpty() && listState.firstVisibleItemIndex > 0
   BackHandler(enabled = isScrolled) {
       scope.launch { listState.animateScrollToItem(0) }
   }
   BackHandler(enabled = !isScrolled) {
       navigator.pop()
   }
   ```
3. В кнопке тулбара `IconButton` обеспечен паритет поведения: при `isScrolled` запускается плавный скролл к началу, иначе — `navigator.pop()`.
4. Состояние `listState` передано в `LazyColumn(state = listState)`.

### C2 — Перехват кнопки «Назад» фоновыми страницами пейджера в DashboardsPaginatedListScreen. Средняя.

[feature-x/src/main/java/com/client/xvideos/x/screens/dashboards/DashboardsPaginatedListScreen.kt:93-115](file:///g:/xvideos2/feature-x/src/main/java/com/client/xvideos/x/screens/dashboards/DashboardsPaginatedListScreen.kt#L93-L115)
[feature-x/src/main/java/com/client/xvideos/x/screens/dashboards/ScreenXDashBoards.kt:148-160](file:///g:/xvideos2/feature-x/src/main/java/com/client/xvideos/x/screens/dashboards/ScreenXDashBoards.kt#L148-L160)

В главном экране раздела XVideos `HorizontalPager` использует `beyondViewportPageCount = 1`, из-за чего соседние страницы компонуются заранее в фоне. Каждая страница в `DashboardsPaginatedListScreen` регистрировала собственный `BackHandler`:
```kotlin
BackHandler(enabled = videoItems.isNotEmpty() && gridState.firstVisibleItemIndex > 0)
```
без проверки, является ли данная страница текущей активной страницей и выбран ли основной таб ленты. В результате при прокрутке на странице 1 и последующем переходе на страницу 0 или во вкладку Savable («Избранное / Сохранённое») фоновый обработчик страницы 1 мог оставаться активным и перехватывать системный «Назад», прокручивая скрытый список вместо навигации по активному разделу.

**Решение:**
1. В `DashboardsPaginatedListScreen` добавлен параметр `isCurrentPage: Boolean = true`.
2. Условие `BackHandler` усилено проверкой активности страницы:
   ```kotlin
   BackHandler(enabled = isCurrentPage && videoItems.isNotEmpty() && gridState.firstVisibleItemIndex > 0) {
       scope.launch { gridState.animateScrollToItem(0) }
   }
   ```
3. В `ScreenXDashBoards.kt` явно передаётся флаг `isCurrentPage = vm.mainTab == 0 && vm.pagerState.currentPage == pageIndex`.

### C3 — Отсутствие скролла к началу страницы тегов в TagsPaginatedListScreen. Средняя.

[feature-x/src/main/java/com/client/xvideos/x/screens/tags/atom/TagsPaginatedListScreen.kt:45-65, 105-125](file:///g:/xvideos2/feature-x/src/main/java/com/client/xvideos/x/screens/tags/atom/TagsPaginatedListScreen.kt#L45-L65)
[feature-x/src/main/java/com/client/xvideos/x/screens/tags/ScreenTags.kt:135-142](file:///g:/xvideos2/feature-x/src/main/java/com/client/xvideos/x/screens/tags/ScreenTags.kt#L135-L142)

В экране просмотра тега XVideos (`ScreenTags`) при пролистывании списка видео вниз на текущей странице нажатие кнопки «Назад» не скроллило список к началу: родительский экран сразу переключал пейджер на страницу 0 (`pagerState.currentPage > 0`) либо немедленно закрывал экран тега (`navigator.pop()`), заставляя пользователя терять просмотренные позиции. Кроме того, `LazyColumn` в `TagsPaginatedListScreen` не сохранял собственное состояние списка.

**Решение:**
1. В `TagsPaginatedListScreen` внедрено явное `listState = rememberLazyListState()`, переданное в `LazyColumn(state = listState)`.
2. Добавлен параметр `isCurrentPage: Boolean = true` и обработчик:
   ```kotlin
   val isScrolled = isCurrentPage && loaded != null && loaded.isNotEmpty() && listState.firstVisibleItemIndex > 0
   BackHandler(enabled = isScrolled) {
       scope.launch { listState.animateScrollToItem(0) }
   }
   ```
3. В `ScreenTags.kt` пейджер передаёт `isCurrentPage = pagerState.currentPage == pageIndex`. При прокрученном списке системный «Назад» сначала плавно скроллит текущую страницу к началу, затем возвращает на страницу 0 пейджера, и только после этого закрывает экран тега.

### C4 — Потенциальные коллизии ключей в LazyColumn разделов Luscious. Средняя.

[feature-l/src/main/java/com/client/xvideos/l/ui/screens/albumLandingTag/ScreenLAlbumLandingTag.kt:133, 279](file:///g:/xvideos2/feature-l/src/main/java/com/client/xvideos/l/ui/screens/albumLandingTag/ScreenLAlbumLandingTag.kt#L133)
[feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/albumTopHits/L_ScreenAlbumTopHits.kt:92](file:///g:/xvideos2/feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/albumTopHits/L_ScreenAlbumTopHits.kt#L92)
[feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/albumSearch/L_ScreenAlbumSearch.kt:159](file:///g:/xvideos2/feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/albumSearch/L_ScreenAlbumSearch.kt#L159)

В экранах `ScreenLAlbumLandingTag`, `L_ScreenAlbumTopHits` и `L_ScreenAlbumSearch` для элементов секций списков использовалось выражение ключа `key = { items?.get(it)?.title ?: it }` или `key = { data.sections[it].title }`.
При совпадении заголовков секций (например, несколько секций с одинаковым или пустым заголовком) Compose выбрасывал критическое исключение:
`IllegalArgumentException: Key was already used. If you are using LazyColumn/LazyRow please make sure you provide a unique key for each item.`

**Решение:**
Ключи переведены на гарантированно уникальный композитный формат с префиксом индекса:
- В `ScreenLAlbumLandingTag.kt`: `key = { index -> "${index}_${items?.get(index)?.title.orEmpty()}" }` и `key = { index -> "${index}_${data.sections.getOrNull(index)?.title.orEmpty()}" }`.
- В `L_ScreenAlbumTopHits.kt`: `key = { index -> "${index}_${items?.get(index)?.title.orEmpty()}" }`.
- В `L_ScreenAlbumSearch.kt`: `key = { index -> "${index}_${sections?.get(index)?.title.orEmpty()}" }`.
- Добавлен модульный тест `композитные ключи секций уникальны при одинаковых или пустых заголовках` в `L_ScreenAlbumTopHitsTest.kt`.
