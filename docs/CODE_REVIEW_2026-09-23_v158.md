## 2. Выявленные проблемы и решения

### Проход 180: Паритет FloatingScrollButtons в L-галерее и нормализация геометрии

1. **Паритет плавающих кнопок скролла (`L_LazyRowPictureDetails.kt`, `:feature-l`)**:
   - **Проблема**: Компонент `LazyRow123` (`:feature-r`) поддерживал флаг управления видимостью `showScrollButtons: Boolean = true`, тогда как его аналог `L_LazyRowPictureDetails` (`:feature-l`) не предоставлял внешнего управления кнопками, всегда пытаясь их отрисовать.
   - **Решение**: В сигнатуру `L_LazyRowPictureDetails` добавлен параметр `showScrollButtons: Boolean = true`, транслируемый в `FloatingScrollButtons(visible = showScrollButtons, ...)`.

2. **Идиоматичный Compose state delegate**:
   - **Проблема**: `Settings.thumbalistSize.field.collectAsStateWithLifecycle().value` читался напрямую через свойство `.value`.
   - **Решение**: Переведён на стандартный делегат `by Settings.thumbalistSize.field.collectAsStateWithLifecycle()`.

3. **Очистка синтаксиса HapticFeedback**:
   - Упрощён многословный вызов `androidx.compose.ui.hapticfeedback.HapticFeedbackType.Confirm` до лаконичного `HapticFeedbackType.Confirm` по уже имеющемуся импорту.

4. **Нормализация высоты сетки `LazyRow123` в [`ScreenNiche.kt`](file:///g:/xvideos2/feature-r/src/main/java/com/client/xvideos/r/ui/niche/ScreenNiche.kt)**:
   - В контейнере экрана `ScreenNicheContent` для `LazyRow123` был задан модификатор `Modifier.fillMaxWidth()` вместо `Modifier.fillMaxSize()`, что отличало его от всех остальных экранов лент (`ScreenRedProfile`, `R_ScreenGifsTab`). Приведён к `fillMaxSize()`.

---

### Проход 181: Стандартизация реактивного состояния и очистка навигации в R Saved

1. **Устранение прямого чтения `.value` во всех вкладках сохранённого (`:feature-r` и `:feature-l`)**:
   - В [`feature-l/.../ScreenSaved.kt`](file:///g:/xvideos2/feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/saved/ScreenSaved.kt): `columnLikes` и `columnCollection` переведены на `by Settings.*.field.collectAsStateWithLifecycle()`.
   - В [`feature-r/.../ScreenSaved.kt`](file:///g:/xvideos2/feature-r/src/main/java/com/client/xvideos/r/ui/explorer/tab/saved/ScreenSaved.kt): `overlay0` и `overlay4` переведены на свойство-делегат `by` с чистой нормализацией колонок:
     ```kotlin
     val overlay0Raw by Settings.r_likesTab_column_current_count.field.collectAsStateWithLifecycle()
     val overlay0 = normalizeRColumnCount(overlay0Raw)
     ```
   - В [`R_Screen_Saved_LikesTab.kt`](file:///g:/xvideos2/feature-r/src/main/java/com/client/xvideos/r/ui/explorer/tab/saved/tab/R_Screen_Saved_LikesTab.kt): аналогично `columnSelect` переведён на `by`.
   - В `R_Screen_CollectionTab.kt`: сохранено локальное чтение `.value` для `selectedCollection`, поскольку Kotlin запрещает smart-cast свойств-делегатов к `String` ненулевого типа внутри лямбд навигатора (`Navigator(ScreenCollectionName(selectedCollection))`).

2. **Ликвидация мёртвой лямбды и калибровка сетки в [`SavedCollectionName.kt`](file:///g:/xvideos2/feature-r/src/main/java/com/client/xvideos/r/ui/explorer/tab/saved/tab/collection/SavedCollectionName.kt)**:
   - **Проблема**: В коде присутствовала дублирующая лямбда `val handleBack = { closeCollection() }`, которая ничем не отличалась от существующей `closeCollection`.
   - **Решение**: Удалена лишняя лямбда, `IconButton` напрямую вызывает `closeCollection`.
   - Для `LazyRow123` добавлен явный модификатор `modifier = Modifier.fillMaxSize()` для корректного заполнения экрана коллекции.
