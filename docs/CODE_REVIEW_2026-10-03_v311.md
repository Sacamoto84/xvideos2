### C1 — Удаление качающегося ролика R показывает ошибку загрузки. Низкая.

[feature-r/src/main/java/com/client/xvideos/r/common/downloader/DownloadRed.kt:372](../feature-r/src/main/java/com/client/xvideos/r/common/downloader/DownloadRed.kt:372)

`delete` отменяет задачу через `kDownloader.cancel(item.id)`. Задача, заметив
отмену, зовёт `listener.onError("Cancelled")`, а колбэк `Downloader`
([Downloader.kt:181](../feature-r/src/main/java/com/client/xvideos/r/common/downloader/Downloader.kt:181))
не отличает отмену от сбоя: показывает «Ошибка закачки: Cancelled» и ставит
индикатор в состояние ошибки (`-3f`). Пользователь сам удалил ролик и видит
два сообщения — «Gif удален» и ошибку — плюс красную полосу. В загрузках X это
уже решено: `onVideoFinished(id, failed = false)` до отмены и учёт `inFlight`.

Нет: проверки на устройстве.

### T1 — «Удалить всё» в R очищает общую таблицу загрузчика, которой пользуется и X. Низкая.

[core/src/main/java/com/client/xvideos/common/kdownloader/internal/DownloadDispatchers.kt:141](../core/src/main/java/com/client/xvideos/common/kdownloader/internal/DownloadDispatchers.kt:141)

`DownloadRed.deleteAll` зовёт `kDownloader.cancelAll()`, а тот — `dbHelper.empty()`.
У R и X разные экземпляры `KDownloader` (R получает через DI, X создаёт свой
через `KDownloader.create`), но база одна — `kdownloader.db`. Очистка стирает
и записи X: идущая загрузка X теряет сведения для докачки, при сбое начнётся
с нуля. Отмена задач при этом затрагивает только экземпляр R — поведение
половинчатое: чужие задачи живы, чужие записи стёрты.

Нет: воспроизведения.

### T2 — Одновременные сохранения в галерею делят один временный файл. Низкая.

[core/src/main/java/com/client/xvideos/common/gallery/GallerySaver.kt:119](../core/src/main/java/com/client/xvideos/common/gallery/GallerySaver.kt:119)

`saveFromUrl` качает во временный файл `gallery_tmp/<имя>`. Проверка `exists`
смотрит только в галерею, а не на идущие сохранения. Два нажатия «В галерею»
для одного ролика X дают два запроса: прямая ссылка X каждый раз новая, поэтому
дедупликация `KDownloader` по адресу их не склеивает. Обе задачи пишут один
`.temp`, результат — повреждённый файл или две записи в галерее. Для R ссылка
постоянная, там второй запрос отбрасывается (см. C2 прохода 175).

Нет: воспроизведения.

### C2 — Блокировка по настенным часам не ограничена сверху. Низкая.

[core/src/main/java/com/client/xvideos/common/applock/AppLockThrottle.kt:101](../core/src/main/java/com/client/xvideos/common/applock/AppLockThrottle.kt:101)

В `remainingMillis` остаток по `elapsedRealtime` отсекается, если он больше
`MAX_LOCKOUT_MS` (после перезагрузки счётчик начинается заново), а остаток по
настенным часам — нет. Если часы устройства ушли назад (разряженная батарея и
запуск до синхронизации времени, ручная правка), `lockoutUntilWall - wallNow`
может составить дни и годы: ввод кода заблокирован, пока часы не вернутся.
Достаточно ограничить `byWall` тем же `MAX_LOCKOUT_MS`.

Нет: воспроизведения; теста на перевод часов назад.

### A1 — Загрузчик R предоставляется DI-модулем раздела L. Низкая.

`provideDownloader` в DI-модуле `feature-l` (каталог `l/di`, строка 35)

Единственный потребитель `KDownloader` из графа Hilt — `Downloader` в
`feature-r`; сам раздел L им не пользуется (в `feature-l` класс встречается
только в этом провайдере). Раздел R работает, пока в сборке есть модуль L, а
настройки загрузчика R лежат в чужом модуле. Провайдеру место в `:core` или в
`feature-r`.

### Исправления (`ce4fb3ff`)

- **C1.** У `KDownloader.enqueue` появился отдельный колбэк `onCancelled`;
  загрузки R и X и сохранение в галерею отмену ошибкой не считают. Тест:
  `DownloaderCancelTest` — до правки индикатор уходил в ошибку.
- **T1.** Поправка к находке: описанный сценарий сегодня недостижим. Загрузчик
  R создаётся без базы (`DownloaderConfig(false)`), его `cancelAll` ничего не
  стирает, а X `cancelAll` не зовёт вовсе. Дефект был скрытым: проявился бы,
  включи R базу или вызови X `cancelAll`. `cancelAll` больше не очищает базу
  целиком — записи своих запросов удаляет отмена каждого. Тест:
  `KDownloaderSharedStateTest`.
- **T2.** `GallerySaver` отклоняет второе сохранение того же файла, пока идёт
  первое; X к тому же не начинает сохранение ролика, который уже качается.
  Теста нет: `GallerySaver` завязан на MediaStore.
- **C2.** Остаток по настенным часам больше потолка отбрасывается, как и
  монотонный. Тест в `AppLockThrottleTest`. Следствие, о котором нужно знать:
  после перезагрузки с часами, ушедшими назад дальше потолка, блокировки нет —
  так же, как и раньше не было её при переводе часов вперёд.
- **A1.** Провайдер перенесён в `:core` (`KDownloaderModule`). Проверено сборкой
  `:app:assembleDebug`.
