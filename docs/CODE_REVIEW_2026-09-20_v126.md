## Находки

### C1 — Риск коллизии ключей в горизонтальных списках ScreenNiche. Средняя.

[feature-r/src/main/java/com/client/xvideos/r/ui/niche/ScreenNiche.kt:265-298](file:///g:/xvideos2/feature-r/src/main/java/com/client/xvideos/r/ui/niche/ScreenNiche.kt#L265-L298)

В экране ниши `ScreenNiche` в списках `LazyRow` использовались ключи `key = { it.id }` для похожих ниш и `key = { it.username }` для авторов. При возврате сервером дублирующихся записей или пустых имён пользователей Compose падал с `IllegalArgumentException: Key was already used`.

**Решение:**
Оба списка переведены на `itemsIndexed` с составными ключами:
```kotlin
itemsIndexed(
    items = related,
    key = { index, item -> "${item.id}#$index" },
    contentType = { _, _ -> "niche_preview" }
)
```
и аналогично для авторов: `key = { index, item -> "${item.username}#$index" }`.

### C2 — Риск коллизии ключей в списке ниш R_ScreenNichesTab. Средняя.

[feature-r/src/main/java/com/client/xvideos/r/ui/explorer/tab/niches/R_ScreenNichesTab.kt:274](file:///g:/xvideos2/feature-r/src/main/java/com/client/xvideos/r/ui/explorer/tab/niches/R_ScreenNichesTab.kt#L274)

В основном списке ниш `R_ScreenNichesTab` ключ задавался как `key = { it.id }`. При динамическом поиске или пагинации ответов сервера дублирующийся ID приводил к сбою рендеринга.

**Решение:**
Переведено на `itemsIndexed` с ключом `"${item.id}#$index"`.
В `RSavedNichesTest.kt` добавлен модульный тест проверки уникальности составных ключей при дублировании ниш.

### C3 — Коллизии ключей в диалоге фильтрации тегов AlbumFilterTagsDialog. Средняя.

[feature-l/src/main/java/com/client/xvideos/l/ui/screens/screenAlbumList/molecule/filter/atom/AlbumFilterTagsDialog.kt:143, 169, 193](file:///g:/xvideos2/feature-l/src/main/java/com/client/xvideos/l/ui/screens/screenAlbumList/molecule/filter/atom/AlbumFilterTagsDialog.kt#L143)

В диалоге выбора тегов ключи формировались из простых строк `key = { it }`, `key = { "plus_$it" }`, `key = { "minus_$it" }`. При загрузке пресетов или пользовательском вводе с дубликатами тегов (или различиями в пробелах) происходил краш Compose.

**Решение:**
Ключи усилены суффиксом индекса позиции: `"${item}#$index"`, `"plus_${tag}#$index"`, `"minus_${tag}#$index"`.

В списке аудиторий `key = { it.id }` мог вызывать коллизии при кастомных или дублирующихся сущностях.

**Решение:**
Переведено на `itemsIndexed` с ключом `"${item.id}#$index"`.
