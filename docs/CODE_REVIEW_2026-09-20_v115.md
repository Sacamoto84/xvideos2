### T1 — Холостые затратные расчеты дубликатов на пуле Default при каждом входе в коллекцию. Средняя.

[feature-l/src/main/java/com/client/xvideos/l/featured/saved/SavedL_Collection.kt:40, 269-278, 289-312](file:///g:/xvideos2/feature-l/src/main/java/com/client/xvideos/l/featured/saved/SavedL_Collection.kt#L40)

При каждом вызове `setCollection(name)` или `refresh()` в `SavedL_Collection` безусловно вызывается:
```kotlin
refreshDuplicates(collectionName)
```
Который на `Dispatchers.Default` повторно считывает с диска все файлы коллекции через `lReadCollectionItems`, производит хэширование, группирует дубликаты и наполняет `val duplicateGroups = mutableStateListOf<LCollectionDuplicateGroup>()`.

Однако в коммите `9f21480` весь UI детектора дубликатов (`LCollectionDuplicatesDialog`, кнопка количества дублей, вызов диалога) был полностью удалён из экрана `ScreenCollectionName.kt`.
Поиск по кодовой базе подтверждает, что поле `duplicateGroups` больше не читается ни одним Composable-элементом во всем приложении.

**Последствия:**
- При каждом открытии любой коллекции выполняются холостые дисковые операции и нагрузка на процессор при группировке дубликатов, результаты которых нигде не отображаются.

### C2 — Гонка приоритетов системного BackHandler между ландшафтным режимом и зумом в ScreenX_VideoPlayer. Средняя.

[feature-x/src/main/java/com/client/xvideos/x/screens/videoplayer/ScreenX_VideoPlayer.kt:78-84, 236-242](file:///g:/xvideos2/feature-x/src/main/java/com/client/xvideos/x/screens/videoplayer/ScreenX_VideoPlayer.kt#L78-L84)

В родительской функции `ScreenX_VideoPlayer.Content()` зарегистрирован обработчик:
```kotlin
BackHandler(enabled = vm.isFullScreen) {
    vm.exitFullScreen()
}
```
Который безусловно активен при `vm.isFullScreen == true`, не учитывая, увеличено ли сейчас видео (`isZoomed`).
В то же время внутри дочернего `VideoPlayerContentView` зарегистрирован зум-обработчик:
```kotlin
BackHandler(enabled = isZoomed) {
    resetZoomTrigger++
}
```
При одновременном `vm.isFullScreen == true` и `isZoomed == true` активны оба обработчика. В механизме `OnBackPressedDispatcher` платформы Android порядок вызова зависит от того, какой колбэк был зарегистрирован или обновлен позже. При рекомпозиции `Content()` (например, при смене состояния во ViewModel) родительский обработчик может перехватить жест «Назад» раньше зум-обработчика, что приведет к немедленному выходу из ландшафтного режима вместо ожидаемого сброса приближения кадра до 1.0x (нарушение контракта NAV07).

### C3 — Отсутствие промежуточного закрытия поисковой строки по жесту «Назад» в коллекции L. Средняя.

[feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/saved/collection/ScreenCollectionName.kt:114-119, 160-166](file:///g:/xvideos2/feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/saved/collection/ScreenCollectionName.kt#L114-L119)

В `L_CollectionNameContent` обработчики возврата настроены так:
```kotlin
BackHandler(enabled = searchQuery.isNotEmpty()) {
    host.collectionSearchQuery = ""
}
BackHandler(enabled = searchQuery.isEmpty()) {
    handleExit()
}
```
Если пользователь открыл строку поиска, но ещё не ввёл символы (или очистил поле ввода), нажатие системной кнопки «Назад» или наэкранной кнопки со стрелкой приводит к немедленному выходу из всей коллекции к сетке коллекций (`handleExit()`), вместо естественного скрытия панели поиска.

### T2 — Повторная компиляция Regex("\\s+") на каждом элементе коллекции при поиске. Низкая.

[feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/saved/collection/ScreenCollectionName.kt:207-211](file:///g:/xvideos2/feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/saved/collection/ScreenCollectionName.kt#L207-L211)

В функции:
```kotlin
private fun PicsDetails.matchesCollectionSearch(query: String): Boolean {
    ...
    return normalized
        .lowercase()
        .split(Regex("\\s+"))
        .all { it in haystack }
}
```
Регулярное выражение `Regex("\\s+")` создается и компилируется заново для каждого элемента коллекции при каждом нажатии клавиши в поле ввода. Для коллекций с сотнями и тысячами файлов это создает паразитные аллокации в памяти и нагрузку на GC.
