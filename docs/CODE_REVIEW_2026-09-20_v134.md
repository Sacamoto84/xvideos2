## Находки

### C1 — Двойное закрытие наложенных диалогов коллекций по нажатию «Назад» в `R_Screen_Root` и `LCollectionDialogs`. Средняя.

[feature-r/src/main/java/com/client/xvideos/r/ui/root/R_Screen_Root.kt:60-72](file:///g:/xvideos2/feature-r/src/main/java/com/client/xvideos/r/ui/root/R_Screen_Root.kt#L60-L72)
[feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/L_DialogCollection.kt:39-48](file:///g:/xvideos2/feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/L_DialogCollection.kt#L39-L48)

В экранах `R_Screen_Root` и `L_DialogCollection` при нажатии «+ Новая коллекция» поверх диалога со списком коллекций открывается диалог ввода имени `DaialogNewCollection`. В этом состоянии оба флага (`visibleDialog = true` и `visibleDialogCreateNew = true`) активны одновременно. В системном `BackHandler` сброс флагов проверялся через последовательные `if` без условий исключения (`if (visibleDialogCreateNew) ... if (visibleDialog) ...`). В результате при нажатии кнопки «Назад» пользователь ожидал отмены создания и возврата к диалогу со списком коллекций, однако происходило одновременное закрытие обоих диалогов и непредвиденный возврат на родительский экран.

**Решение:**
1. В `R_Screen_Root.kt` внедрены перечисление `RedRootDialogBackAction` и чистая функция `resolveRedRootDialogBackAction(visibleDialogCreateNew, visibleDialog, blockVisibleDialog)`.
2. В `L_DialogCollection.kt` внедрены `LCollectionDialogBackAction` и чистая функция `resolveLCollectionDialogBackAction(visibleDialogCreateNew, visibleDialog)`.
3. В обоих экранах `BackHandler` переведён на последовательный выбор одного приоритетного действия: сначала закрывается верхний диалог создания новой коллекции, затем диалог выбора коллекции, затем блокировка.
4. Добавлены модульные тесты `RedRootDialogBackActionTest.kt` в `:feature-r` и `LCollectionDialogBackActionTest.kt` в `:feature-l`.

### C2 — XlrBackupManager: Утечка скрытых и служебных папок при записи директорий, пустых заготовок и распаковке. Средняя.

[core/src/main/java/com/client/xvideos/common/backup/XlrBackupManager.kt:170-178, 298-325, 405-415, 530-545](file:///g:/xvideos2/core/src/main/java/com/client/xvideos/common/backup/XlrBackupManager.kt#L170-L178)

В менеджере резервного копирования `XlrBackupManager`:
1. `writePath` выполнял проверку `shouldIncludeBackupEntry(entryRoot, options)` только для одиночных файлов (`source.isFile`), делегируя директории в `writeDirectory` без проверки корневого пути каталога.
2. `writeDirectory` безусловно создавал запись `ZipEntry("$entryRoot/")` в архиве до проверки включения входящих элементов.
3. `createBackup` при отсутствии папки на диске (`!source.exists()`) безусловно добавлял запись директории `ZipEntry("$path/")` в архив, минуя проверку `shouldIncludeBackupEntry`.
4. `normalizeSelectedPaths` не фильтровал пути со скрытыми сегментами (например, `.xlr_old_*`), из-за чего служебные директории отката могли передаваться в бэкап или восстанавливаться.
5. `extractBackup` не проверял сегменты с точкой у распаковываемых записей, допуская извлечение скрытых служебных файлов из недоверенных архивов.

**Решение:**
1. В `writePath` и `writeDirectory` добавлен немедленный возврат пустого отчёта, если `!shouldIncludeBackupEntry(entryRoot, options)`.
2. В `createBackup` запись отсутствующей директории защищена проверкой `shouldIncludeBackupEntry(path, options)`.
3. Функция `normalizeSelectedPaths` сделана доступной для тестов (`internal`) и дополнена фильтрацией путей, содержащих сегменты с точкой: `!path.split('/').any { it.startsWith(".") }`.
4. В `extractBackup` добавлен пропуск записей, содержащих скрытые сегменты пути.
5. В `XlrRestoreApplyTest.kt` добавлены модульные тесты на фильтрацию служебных каталогов в `normalizeSelectedPaths`.

### C3 — Клампинг отрицательных значений в `toTwoDecimalPlacesWithColon` и валидация `timeA >= 0f` в `isValidABRange`. Низкая.

[core/src/main/java/com/client/xvideos/common/util/toTwoDecimalPlacesWithColon.kt:17-23](file:///g:/xvideos2/core/src/main/java/com/client/xvideos/common/util/toTwoDecimalPlacesWithColon.kt#L17-L23)
[feature-r/src/main/java/com/client/xvideos/r/ui/video/RedPooledVideoPlayer.kt:67-69](file:///g:/xvideos2/feature-r/src/main/java/com/client/xvideos/r/ui/video/RedPooledVideoPlayer.kt#L67-L69)

1. В утилите `Float.toTwoDecimalPlacesWithColon()` обрабатывались `isNaN()` и `isInfinite()`, но отсутствовала проверка отрицательных значений (`this <= 0f`). При передаче отрицательного смещения времени (например, до старта воспроизведения видео) формировалась строка вида `"-1:50"`, отображавшаяся на кнопках таймкодов A-B (`TimeMarkerButton`).
2. В функции `isValidABRange` видеоплеера `RedPooledVideoPlayer` проверялись `enableAB && timeA.isFinite() && timeB.isFinite() && timeB > timeA`, однако отсутствовало требование неотрицательности точки старта (`timeA >= 0f`). Отрицательное значение точки A признавалось валидным и приводило к перемотке на сжатый 0L, искажая цикл повтора.

**Решение:**
1. В `toTwoDecimalPlacesWithColon()` добавлено условие `this <= 0f`, гарантирующее возврат `"0:00"` при любых неположительных или невалидных значениях (по аналогии с `Double.toMinSec()`).
2. В `isValidABRange` добавлено строгое условие `timeA >= 0f`.
3. Обновлены модульные тесты в `FormattingUtilsTest.kt` и `RedPooledVideoPlayerTest.kt`.

### C4 — ScreenTags: Паритет системного `BackHandler` с чистой иерархией `TagsBackAction`. Низкая.

[feature-x/src/main/java/com/client/xvideos/x/screens/tags/ScreenTags.kt:58-68](file:///g:/xvideos2/feature-x/src/main/java/com/client/xvideos/x/screens/tags/ScreenTags.kt#L58-L68)

В экране `ScreenTags` кнопка «Назад» тулбара использует чистую функцию `resolveTagsBackAction(currentListState?.isScrolled == true, pagerState.currentPage)` для определения приоритета возврата (скролл к началу списка -> возврат на 0 страницу -> закрытие экрана). Однако системные `BackHandler` на уровне экрана проверяли только `pagerState.currentPage > 0` и `pagerState.currentPage == 0`, полагаясь на дочерний `BackHandler` в `TagsPaginatedListScreen`. Из-за предварительного кэширования соседних страниц пейджером (`beyondViewportPageCount = 1`) это приводило к рассинхронизации поведения системного жеста и наэкранной кнопки.

**Решение:**
1. В `ScreenTags` обработчики `BackHandler` переведены на явную проверку `isListScrolled = currentListState?.isScrolled == true`.
2. Системная навигация «Назад» полностью синхронизирована с приоритетами `resolveTagsBackAction`.
