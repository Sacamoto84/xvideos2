## Находки

### C1 — Небезопасный вызов item.id.toLong() в сетке ScreenAlbumList.kt. Высокая.

[feature-l/src/main/java/com/client/xvideos/l/ui/screens/screenAlbumList/ScreenAlbumList.kt:330](file:///g:/xvideos2/feature-l/src/main/java/com/client/xvideos/l/ui/screens/screenAlbumList/ScreenAlbumList.kt#L330)

При клике на карточку альбома в общем пагинированном списке альбомов Luscious передача ID выполнялась через прямой вызов:
```kotlin
onAlbumClick(item.id.toLong())
```
Поле `id` сущности `Album` является строкой из удалённого GraphQL API. Если сервер вернёт некорректное строковое значение, пустую строку или нечисловой UUID, `toLong()` выбрасывает `NumberFormatException`, приводя к крашу UI-потока.

**Решение:** Заменить на безопасное извлечение `item.id.toLongOrNull()?.let { onAlbumClick(it) }`.

### C2 — Небезопасный парсинг меток времени Instant.ofEpochSecond и аллокация DateTimeFormatter в ScreenAlbum.kt. Средняя.

[feature-l/src/main/java/com/client/xvideos/l/ui/screens/screenAlbum/ScreenAlbum.kt:260-285](file:///g:/xvideos2/feature-l/src/main/java/com/client/xvideos/l/ui/screens/screenAlbum/ScreenAlbum.kt#L260-L285)

В карточке деталей альбома строки даты создания (`created`) и модификации (`modified`) рассчитывались безусловно на каждой рекомпозиции:
```kotlin
val formatter = DateTimeFormatter.ofPattern("dd.MM.yyyy HH:mm")

val textCreated =
    Instant.ofEpochSecond(parsed.created.toLong())
        .atZone(ZoneId.systemDefault()).format(formatter)

val textModified =
    Instant.ofEpochSecond(parsed.modified.toLong())
        .atZone(ZoneId.systemDefault()).format(formatter)
```
1. `DateTimeFormatter.ofPattern` аллоцировался и компилировал шаблон на каждом кадре рекомпозиции.
2. `Instant.ofEpochSecond` вызывался даже при `created == 0.0` (до проверки `if (parsed.created != 0.0)`), что приводило к холостому расчёту даты Unix epoch (1970).
3. При получении отрицательных, `NaN` или не-finite (`Double.POSITIVE_INFINITY`, `Double.NEGATIVE_INFINITY`) значений метод `Instant.ofEpochSecond(...)` может выбросить `DateTimeException`.

**Решение:**
- Вынести `ALBUM_DATE_FORMATTER` в приватную константу уровня файла.
- Реализовать функцию `formatEpochSeconds(seconds: Double, zoneId: ZoneId = ZoneId.systemDefault()): String?` с проверкой `seconds.isFinite() && seconds > 0.0` и блоком `try/catch (DateTimeException)`.
- Кэшировать результат через `remember(parsed.created)` и `remember(parsed.modified)`.

### C3 — Трехэтапная навигация BackHandler и onBack в профиле автора ScreenRedProfile.kt. Средняя.

[feature-r/src/main/java/com/client/xvideos/r/ui/profile/ScreenRedProfile.kt:68-75, 102-108](file:///g:/xvideos2/feature-r/src/main/java/com/client/xvideos/r/ui/profile/ScreenRedProfile.kt#L68-L75)

В экране профиля автора (`ScreenRedProfile`) обработчик `BackHandler` учитывал только выбор тегов фильтра:
```kotlin
BackHandler(enabled = tagsSelect.isNotEmpty()) {
    vm.tagsSelect.value = emptySet()
}
BackHandler(enabled = tagsSelect.isEmpty()) {
    navigator.pop()
}
```
Если теги не выбраны, но пользователь пролистал сотни элементов ленты автора вниз (`vm.likedHost.state.firstVisibleItemIndex > 0`), нажатие «Назад» или клик по стрелке тулбара мгновенно закрывали экран.

**Решение:** Внедрить трехэтапный возврат:
1. `tagsSelect.isNotEmpty()` -> сбросить фильтр тегов (`vm.tagsSelect.value = emptySet()`).
2. `tagsSelect.isEmpty() && vm.likedHost.state.firstVisibleItemIndex > 0` -> прокрутить к началу (`vm.likedHost.gotoUp()`).
3. `tagsSelect.isEmpty() && vm.likedHost.state.firstVisibleItemIndex == 0` -> выйти (`navigator.pop()`).
Обеспечить идентичное поведение для кнопки «Назад» в тулбаре `RedProfileScreenContent`.

### C4 — Иерархический скролл к началу в поиске авторов SearchTab.kt. Низкая.

[feature-r/src/main/java/com/client/xvideos/r/ui/explorer/tab/search/SearchTab.kt:105-107, 151](file:///g:/xvideos2/feature-r/src/main/java/com/client/xvideos/r/ui/explorer/tab/search/SearchTab.kt#L105-L107)

В `SearchTabContent` списка авторов при прокрутке длинного списка результатов нажатие системного жеста «Назад» очищало текстовое поле, но не позволяло вернуться к первому элементу списка, так как `LazyColumn` не управлялся внешним `LazyListState`.

**Решение:**
- Создать и передать в `LazyColumn` состояние `listState = rememberLazyListState()`.
- Добавить `BackHandler(enabled = searchText.isEmpty() && listState.firstVisibleItemIndex > 0)` со скроллом к началу `listState.animateScrollToItem(0)`.
