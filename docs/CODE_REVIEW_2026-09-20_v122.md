## Находки

### C1 — Потеря позиции прокрутки и преждевременный выход в AppSettingsScreen. Средняя.

[app/src/main/java/com/client/xvideos/screenSettings/AppSettingsScreen.kt:208-270, 290-300](file:///g:/xvideos2/app/src/main/java/com/client/xvideos/screenSettings/AppSettingsScreen.kt#L208-L270)

В `AppSettingsScreen` состояние `rememberScrollState()` создавалось внутри `AppSettingsScreenBody`. При переходе между страницами (например, из «Основное» в «Хранилище» или «Сеть») позиция прокрутки сохранялась, из-за чего вложенные страницы могли открываться уже прокрученными вниз. Кроме того, при прокрутке вниз на любой странице настроек нажатие кнопки «Назад» или стрелки тулбара мгновенно закрывало под-страницу или выходило из настроек без предварительной прокрутки к началу.

**Решение:**
1. Управление состоянием прокрутки `scrollState = rememberScrollState()` поднято в `AppSettingsScreenContent` и передаётся через `Modifier.verticalScroll(scrollState)` (без увеличения числа параметров тела, сохраняя лимит Detekt `LongParameterList`).
2. Добавлен сброс скролла на 0 при смене страницы:
   ```kotlin
   LaunchedEffect(currentPage) {
       scrollState.scrollTo(0)
   }
   ```
3. Реализована трёхступенчатая цепочка `BackHandler` и синхронизированная кнопка тулбара `handleBack`:
   - При `scrollState.value > 0`: плавно скроллить к началу страницы.
   - При `scrollState.value == 0 && currentPage != SettingsPage.Main`: возврат в главное меню настроек.
   - При `scrollState.value == 0 && currentPage == SettingsPage.Main`: закрытие экрана настроек (`onBack()`).
4. Добавлен модульный тест `Settings back navigation hierarchy priority` в `AppSettingsScreenSerializationTest.kt`.

### C2 — Отсутствие скролла к началу списка при возврате в HapticDemoScreen. Средняя.

[app/src/main/java/com/client/xvideos/HapticDemoScreen.kt:65-110, 125-135](file:///g:/xvideos2/app/src/main/java/com/client/xvideos/HapticDemoScreen.kt#L65-L110)

В демонстрационном экране виброоткликов `HapticDemoScreen` при прокрутке длинного перечня из 13 типов тактильных сигналов и кастомного waveform-блока вниз нажатие системной кнопки «Назад» или стрелки в шапке сразу вызывало `navigator.pop()`.

**Решение:**
1. Поднято `scrollState = rememberScrollState()` и `scope = rememberCoroutineScope()`.
2. Внедрена двухступенчатая цепочка `BackHandler`:
   ```kotlin
   val isScrolled = scrollState.value > 0
   BackHandler(enabled = isScrolled) {
       scope.launch { scrollState.animateScrollTo(0) }
   }
   BackHandler(enabled = !isScrolled) {
       navigator.pop()
   }
   ```
3. Стрелка возврата в тулбаре `IconButton` синхронизирована с системным `BackHandler`.

### C3 — Императивный BackHandler в ScreenX_LocalVideoPlayer. Средняя.

[feature-x/src/main/java/com/client/xvideos/x/screens/videoplayer/ScreenX_LocalVideoPlayer.kt:125-136](file:///g:/xvideos2/feature-x/src/main/java/com/client/xvideos/x/screens/videoplayer/ScreenX_LocalVideoPlayer.kt#L125-L136)

В `ScreenX_LocalVideoPlayer` использовался непараметризованный обработчик `BackHandler { if (isZoomed) resetZoomTrigger++ else navigator.pop() }`, в отличие от декларативного разделения в `ScreenX_VideoPlayer`.

**Решение:**
Приведено к общему стандарту видеоплееров:
```kotlin
BackHandler(enabled = isZoomed) {
    resetZoomTrigger++
}
BackHandler(enabled = !isZoomed) {
    navigator.pop()
}
```
