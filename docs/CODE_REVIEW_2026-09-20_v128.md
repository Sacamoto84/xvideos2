## Находки

### C1 — Повторная компиляция Regex и сбой парсинга относительных путей в extractIdFromUrl. Средняя.

[feature-l/src/main/java/com/client/xvideos/l/net/Luscious.kt:74-78](file:///g:/xvideos2/feature-l/src/main/java/com/client/xvideos/l/net/Luscious.kt#L74-L78)

В функции `extractIdFromUrl` регулярное выражение компилировалось заново при каждом вызове:
```kotlin
internal fun extractIdFromUrl(url: String): String? {
    val regex = Regex("/albums/(?:[^/]*_)?(\\d+)")
    val matchResult = regex.find(url)
    return matchResult?.groupValues?.get(1)
}
```
Это приводило к лишним аллокациям AST регулярного выражения. Кроме того, шаблон требовал обязательного ведущего слэша `/albums/...`, из-за чего относительные пути вида `albums/374481` или `albums/animated-gifs_374481/` не распознавались, а пробелы по краям строки не санитизировались.

**Решение:**
1. Регулярное выражение скомпилировано один раз на уровне файла:
   ```kotlin
   private val ALBUM_ID_REGEX = Regex("(?:^|/)albums/(?:[^/]*_)?(\\d+)")
   ```
2. Поддержаны относительные пути без ведущего слэша, ссылки с query-параметрами и добавлена санитизация `url.trim()`:
   ```kotlin
   internal fun extractIdFromUrl(url: String): String? {
       return ALBUM_ID_REGEX.find(url.trim())?.groupValues?.get(1)
   }
   ```
3. В `LPureFunctionsTest.kt` добавлены модульные тесты для относительных путей и ссылок с query-параметрами.
