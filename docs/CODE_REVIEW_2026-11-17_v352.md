## Находки

### C1 — Утечка ресурсов и фоновое исполнение скриптов в `NCloudflareChallengeDialog` из-за отсутствия `onRelease` у `AndroidView`. Средняя.

[feature-n/src/main/java/com/client/xvideos/n/ui/molecule/NCloudflareChallengeDialog.kt:95-105](file:///H:/xvideos2/feature-n/src/main/java/com/client/xvideos/n/ui/molecule/NCloudflareChallengeDialog.kt#L95-L105)

В `NCloudflareChallengeDialog` для отображения интерактивной проверки Cloudflare Turnstile используется `AndroidView`:
```kotlin
AndroidView(
    factory = { context ->
        WebView(context).apply {
            setupCloudflareWebView(this, url) { cookies ->
                onSuccess(cookies)
            }
            loadUrl(url)
        }
    },
    modifier = Modifier.fillMaxWidth().weight(1f)
)
```
В отличие от `NLoginDialog`, где корректно передан колбэк `onRelease`, в `NCloudflareChallengeDialog` очистка отсутствует. Когда пользователь закрывает диалог (нажатием на крестик, кликом вне области диалога или системной кнопкой «Назад»), экземпляр `WebView` остаётся в памяти и продолжает выполнять сетевые запросы и скрипты Cloudflare Turnstile в фоне, удерживая ссылку на контекст Activity.

Необходимо добавить блок `onRelease`:
```kotlin
onRelease = { webView ->
    runCatching {
        webView.stopLoading()
        webView.destroy()
    }
}
```

Отдельно: подтверждено анализом жизненного цикла `AndroidView` и сравнением с `NLoginDialog`.

### C2 — Отсутствие стабильного ключа (`key = "loading_more"`) у футера пагинации в `NGalleryGrid`. Низкая.

[feature-n/src/main/java/com/client/xvideos/n/ui/molecule/NGalleryGrid.kt:72-86](file:///H:/xvideos2/feature-n/src/main/java/com/client/xvideos/n/ui/molecule/NGalleryGrid.kt#L72-L86)

В компоненте `NGalleryGrid` элемент индикатора подгрузки страниц (`isLoadingMore`) добавляется в `LazyVerticalGrid` без указания ключа:
```kotlin
if (isLoadingMore) {
    item(span = { GridItemSpan(maxLineSpan) }) {
        Box(...) { CircularProgressIndicator(...) }
    }
}
```
По соглашениям кодовой базы (проходы 197 и 218), `item` без явного ключа получает автоматический числовой ключ `0`. При динамическом появлении и исчезновении лоадера внизу сетки это может приводить к конфликту ключей с первым элементом списка (`it.id == 0`) и вызывать нежелательные анимации перестроения позиций.

Необходимо явно задать `item(key = "loading_more", span = { GridItemSpan(maxLineSpan) })`.

Отдельно: подтверждено правилами вёрстки списков Compose.

### T1 — Отсутствие отмены предыдущего сетевого запроса поиска и пагинации в `N_ScreenGallerySearchSM`. Средняя.

[feature-n/src/main/java/com/client/xvideos/n/ui/screens/explorer/tab/search/N_ScreenGallerySearchSM.kt:99-124](file:///H:/xvideos2/feature-n/src/main/java/com/client/xvideos/n/ui/screens/explorer/tab/search/N_ScreenGallerySearchSM.kt#L99-L124)  
[feature-n/src/main/java/com/client/xvideos/n/ui/screens/explorer/tab/search/N_ScreenGallerySearchSM.kt:129-153](file:///H:/xvideos2/feature-n/src/main/java/com/client/xvideos/n/ui/screens/explorer/tab/search/N_ScreenGallerySearchSM.kt#L129-L153)

В методе `search()` сетевой запрос запускается напрямую в `screenModelScope.launch { ... }` без сохранения ссылки на `Job` и без отмены предыдущего поиска:
- Если пользователь повторно нажимает «Поиск» или выбирает подсказку тега во время выполнения предыдущего запроса, старый и новый сетевые вызовы выполняются параллельно.
- Медленный старый ответ может прийти позже нового и перезаписать актуальные результаты поиска.
- Кроме того, активный запрос подгрузки страницы `loadNextPage()` не отменяется при старте нового поиска `search()`.

Необходимо сохранять `searchJob: Job?` и `pageJob: Job?`, отменяя их перед запуском нового поиска.

Отдельно: выявлено анализом конкурентности корутин во вкладке поиска.

### A1 — Отсутствие адаптивных отступов `adaptiveListPadding(...)` в `NGalleryGrid`, `NPictureGrid` и `NGalleryRelatedStrip`. Низкая.

[feature-n/src/main/java/com/client/xvideos/n/ui/molecule/NGalleryGrid.kt:36](file:///H:/xvideos2/feature-n/src/main/java/com/client/xvideos/n/ui/molecule/NGalleryGrid.kt#L36)  
[feature-n/src/main/java/com/client/xvideos/n/ui/molecule/NPictureGrid.kt:27](file:///H:/xvideos2/feature-n/src/main/java/com/client/xvideos/n/ui/molecule/NPictureGrid.kt#L27)  
[feature-n/src/main/java/com/client/xvideos/n/ui/molecule/NGalleryRelatedStrip.kt:61](file:///H:/xvideos2/feature-n/src/main/java/com/client/xvideos/n/ui/molecule/NGalleryRelatedStrip.kt#L61)

По правилам поддержки складных устройств (`CLAUDE.md`, раздел «Складные телефоны»):
> Ленивый список на всю ширину — `contentPadding = adaptiveListPadding(...)`, чтобы свайп работал по всей ширине.

В `NGalleryGrid` и `NPictureGrid` значение по умолчанию задано как фиксированное `PaddingValues(8.dp)`, а в `NGalleryRelatedStrip` в `LazyRow` передан `PaddingValues(horizontal = 16.dp)`. В результате на широком/внутреннем экране складного устройства сетки и горизонтальная лента рекомендаций не центрируются и не получают необходимых боковых полей безопасности.

Необходимо обернуть значения `contentPadding` в `adaptiveListPadding(...)`.

Отдельно: подтверждено требованиями адаптивной вёрстки.

Необходимо передать значение `Color(0xFFED2553)` inline в параметре `accent = Color(0xFFED2553)`.
