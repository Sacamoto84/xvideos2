### C1 — Небезопасный вызов album.id.toLong() с риском NumberFormatException в разделах L. Высокая.

[feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/albumSearch/L_ScreenAlbumSearch.kt:254](file:///g:/xvideos2/feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/albumSearch/L_ScreenAlbumSearch.kt#L254)  
[feature-l/src/main/java/com/client/xvideos/l/ui/screens/albumLandingTag/ScreenLAlbumLandingTag.kt:219](file:///g:/xvideos2/feature-l/src/main/java/com/client/xvideos/l/ui/screens/albumLandingTag/ScreenLAlbumLandingTag.kt#L219)  
[feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/albumTopHits/L_ScreenAlbumTopHits.kt:120](file:///g:/xvideos2/feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/albumTopHits/L_ScreenAlbumTopHits.kt#L120)

В разметке сетки альбомов `FlowRow` клик по карточке альбома передавал идентификатор навигации напрямую через вызов `album.id.toLong()`:
```kotlin
onClick = { onAlbumClick(album.id.toLong()) }
```
Поле `id` в DTO-модели `Album` является строкой из недоверенного серверного GraphQL-ответа. Если сервер вернёт пустую строку, нечисловой UUID или строковое значение `null`, метод `toLong()` выбросит исключение `NumberFormatException`, приводя к аварийному завершению процесса приложения прямо в UI-потоке.

**Решение:** Заменить прямой вызов на безопасный парсер `album.id.toLongOrNull()?.let { onAlbumClick(it) }`.

### C2 — Отсутствие промежуточного возврата к началу прокрученных списков в L_ScreenAlbumTopHits и ScreenLAlbumLandingTag. Средняя.

[feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/albumTopHits/L_ScreenAlbumTopHits.kt:70-85](file:///g:/xvideos2/feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/albumTopHits/L_ScreenAlbumTopHits.kt#L70-L85)  
[feature-l/src/main/java/com/client/xvideos/l/ui/screens/albumLandingTag/ScreenLAlbumLandingTag.kt:95-115](file:///g:/xvideos2/feature-l/src/main/java/com/client/xvideos/l/ui/screens/albumLandingTag/ScreenLAlbumLandingTag.kt#L95-L115)

В экранах `L_ScreenAlbumTopHits` и `ScreenLAlbumLandingTag` при прокрутке длинных списков категорий и тегов вниз (`state.firstVisibleItemIndex > 0`) нажатие системного жеста «Назад» или наэкранной кнопки возврата приводило к моментальному выходу из экрана или переключению родительского таба. В отличие от `L_ScreenAlbumSearch`, `ScreenAlbumList` и `ScreenTags`, в данных экранах отсутствовал промежуточный возврат к нулевому элементу списка.

**Решение:**
- Внедрить двухэтапную иерархию `BackHandler`: если `state.firstVisibleItemIndex > 0` — плавный скролл к началу (`animateScrollToItem(0)`), иначе — выход (`navigator.pop()`).
- В `LandingTagTopBar` пробросить аналогичную проверку в клик наэкранной стрелки «Назад».

### C3 — Двухэтапная навигация «Назад» в ленте ниш R_ScreenNiche. Средняя.

[feature-r/src/main/java/com/client/xvideos/r/ui/niche/ScreenNiche.kt:68-70](file:///g:/xvideos2/feature-r/src/main/java/com/client/xvideos/r/ui/niche/ScreenNiche.kt#L68-L70)

В экране ниш раздела Red (`R_ScreenNiche`) был объявлен единственный безусловный обработчик `BackHandler { navigator.pop() }`. Если пользователь пролистал сотни GIF-анимаций вниз по ленте ниши (`vm.lazyHost.state.firstVisibleItemIndex > 0`), случайное нажатие «Назад» сразу закрывало экран вместо удобного возврата к шапке ниши и блоку `Related Niches`.

**Решение:**
- Добавить двухэтапный возврат:
  1. `BackHandler(enabled = vm.lazyHost.state.firstVisibleItemIndex > 0) { vm.lazyHost.gotoUp() }`
  2. `BackHandler(enabled = vm.lazyHost.state.firstVisibleItemIndex == 0) { navigator.pop() }`

### T1 — Повторная компиляция регулярных выражений в sanitizeTagForUrl. Низкая.

[feature-x/src/main/java/com/client/xvideos/x/screens/tags/ScreenTagsViewModel.kt:107-112](file:///g:/xvideos2/feature-x/src/main/java/com/client/xvideos/x/screens/tags/ScreenTagsViewModel.kt#L107-L112)

Функция санитизации тегов `sanitizeTagForUrl` вызывается при формировании каждого сетевого URL для экранов тегов X:
```kotlin
tag.trim()
    .replace(Regex("[#?&/\\\\\\s\\u00A0]+"), "-")
    .replace(Regex("-+"), "-")
    .trim('-')
```
Создание и парсинг регулярных выражений внутри тела функции вызывали постоянные аллокации объектов `Regex` на каждый запрос.

**Решение:** Вынести регулярные выражения в предкомпилированные `private val` уровня файла.
