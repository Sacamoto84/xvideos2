## Находки

### C1 — Риск коллизии ключей в пагинированных лентах DashboardsPaginatedListContent. Средняя.

[feature-x/src/main/java/com/client/xvideos/x/screens/dashboards/DashboardsPaginatedListScreen.kt:214-220](file:///g:/xvideos2/feature-x/src/main/java/com/client/xvideos/x/screens/dashboards/DashboardsPaginatedListScreen.kt#L214-L220)

В сетке пагинации `LazyVerticalGrid` элементы ключились исключительно по `id` видео:
```kotlin
items(items, key = { it.id }) { cell ->
```
При динамической подгрузке страниц с сервера (в ситуациях появления новых видео в ленте или перекрытия страниц при постраничной загрузке) один и тот же `id` мог оказаться на стыке двух порций данных, что приводило к мгновенному падению приложения с фатальной ошибкой `Key <id> was already used`.

**Решение:**
Сетка переведена на `itemsIndexed` с составным ключом по индексу:
```kotlin
itemsIndexed(items, key = { index, cell -> "${cell.id}#$index" }) { _, cell ->
```

### C2 — Риск коллизии ключей в списке сохранённых видео ScreenSavedX. Средняя.

[feature-x/src/main/java/com/client/xvideos/x/screens/saved/ScreenSavedX.kt:119-123](file:///g:/xvideos2/feature-x/src/main/java/com/client/xvideos/x/screens/saved/ScreenSavedX.kt#L119-L123)

В `LazyColumn` экрана скачанных видео `ScreenSavedX` использовался ключ `key = { it.id }`. При повторном скачивании или параллельной записи файлов базы данных наличие дубликата ключа вызывало сбой рендера Compose.

**Решение:**
Ключ защищён суффиксом индекса позиции:
```kotlin
itemsIndexed(list, key = { index, item -> "${item.id}#$index" }) { _, item ->
```

**Решение:**

```kotlin
itemsIndexed(favorites, key = { index, item -> "${item.id}#$index" }) { _, item ->
```

### C4 — Риск коллизии ключей в истории просмотров ScreenXHistory. Средняя.

[feature-x/src/main/java/com/client/xvideos/x/screens/history/ScreenXHistory.kt:233-237](file:///g:/xvideos2/feature-x/src/main/java/com/client/xvideos/x/screens/history/ScreenXHistory.kt#L233-L237)

В истории просмотров `ScreenXHistory` элементы сетки ключились как `key = { it.item.id }`. При повторных просмотрах одного и того же видео и сохранении хронологических записей сетка падала из-за дублирования идентификаторов.

**Решение:**
Переведено на составной ключ `"${historyItem.item.id}#$index"`:
```kotlin
itemsIndexed(history, key = { index, historyItem -> "${historyItem.item.id}#$index" }) { _, historyItem ->
```
В `SavedX_FavoritesTest.kt` добавлен модульный тест проверки уникальности составных ключей при наличии дублирующихся ID.
