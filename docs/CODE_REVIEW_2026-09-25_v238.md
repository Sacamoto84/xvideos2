## Summary of Passes (761–768)

### Pass 761 — `:feature-l` (`Repository.kt`)
- **Finding:** On every ROM or RAM cache miss (`getFromCacheRom` / `getFromCacheRam`), `data.toMD5()` was computed once to look up the cache entry and then computed a second time inside `postJsonValidated(data)` (`val requestHash = data.toMD5()`). Additionally, `createHandler()` allocated a new `setOf(413, 429, 500, 502, 503, 504)` on every creation, and `ensureAuthenticated()` allocated `Result.success(Unit)`.
- **Fix:** Added `requestHash: String = data.toMD5()` parameter to `postJsonValidated` and passed `cacheKey` from `getFromCacheRom` and `getFromCacheRam`. Hoisted `RETRY_STATUS_CODES` and `SUCCESS_UNIT` to `companion object`.

### Pass 762 — `:feature-l` (`AlbumList.kt`)
- **Finding:** `getAlbumListAggregationsImpl` scanned `aggregations` three separate times with `aggregations?.indexOfFirst { ... }` (`genre_ids`, `tagged`, `picture_count_rank`) and copied each decoded list into a `mutableListOf` via `addAll`. Meanwhile, `getAlbumListImpl` allocated a `mutableListOf<Album>()`, copied `parsedResult.items` into it, and wrapped it in a new `AlbumListImplInfoAndList` even though `parseAlbumListResponse` already returned the exact `Result<AlbumListImplInfoAndList>`.
- **Fix:** Replaced the 3 `indexOfFirst` passes with a single `for (el in aggregations)` loop dispatching on `short_name` via `decodeAggregationValues(obj)`, pre-sized `ArrayList<Album>(itemsJson.size)` in `parseAlbumListResponse`, and returned `parsed` directly from `getAlbumListImpl`.

### Pass 763 — `:feature-l` (`getAlbumListTopHits.kt`)
- **Finding:** `getAlbumListTopHitsQuery()` executed multi-line string interpolation and `.trimIndent()` on every call, including the default-argument invocation in `AlbumTopHitsImpl`.
- **Fix:** Precomputed `DEFAULT_ALBUM_LIST_TOP_HITS_QUERY` for the default arguments (`display = "date_newest"`, `albumType = AlbumType.Pictures`, `contentId = ContentId.Hentai`, `hitsFrom = "genre_ids"`), returning in $O(1)$ without string allocations.

### Pass 764 — `:feature-l` (`LusciousServerFavoritesRepositoryImpl.kt`)
- **Finding:** In `resolvePictureId()`, for every picture in an album page, `thumbUrls` (`mapNotNull`) and `listOf(picUrl, picOrig, picVideo) + thumbUrls` allocated 3 intermediate lists per picture before checking whether `targetSlug` matched. In addition, `addFavorite` and `removeFavorite` duplicated identical GraphQL mutation error-parsing logic.
- **Fix:** Short-circuited `resolvePictureId()` before pagination if `targetSlug.isBlank()`, replaced the per-picture list allocations with zero-allocation helper `pictureMatchesSlug(picObj, targetSlug)`, and extracted `parseFavoriteMutationResult(rawResult, mutationField, operationLabel)`.

### Pass 765 — `:feature-r` (`DownloadRed.kt`)
- **Finding:** `refreshDownloadList()` materialized `rootDir.walkTopDown().filter { it.isFile }.toList()` and then filtered `allFiles` twice (once for `.info` + `.sortedByDescending`, and once for `.mp4`), while `downloadedVideoKeys()` allocated an un-sized `LinkedHashSet`.
- **Fix:** Partitioned `infoFiles` and `mp4Files` in a single `walkTopDown()` loop, sorted `infoFiles` in-place (`infoFiles.sortByDescending`), and pre-sized `HashSet(videoFiles.size)` in `downloadedVideoKeys()`.

### Pass 766 — `:feature-r` (`R_Saved_Subscriptions.kt` & `ItemSubscriptionsPagingSource.kt`)
- **Finding:** `R_Saved_Subscriptions.refreshSubscription()` called `syncSelectedList()` inside `withContext(Dispatchers.Main)` and then read `selectedListCreator.filter { it.select }` off the Main thread (a thread-safety hazard on `SnapshotStateList`). Furthermore, `ItemSubscriptionsPagingSource.load()` called `.sanitizeGifsInfoList().distinctBy { it.id }` on the result of `refreshSubscription()`, which had already sanitized each creator's items and deduplicated by `id`.
- **Fix:** Extracted `selectedNames` inside the `withContext(Dispatchers.Main)` block in `refreshSubscription()` and removed the duplicate `.sanitizeGifsInfoList().distinctBy { it.id }` passes in `ItemSubscriptionsPagingSource.load()`.

### Pass 767 — `:feature-r` (`BlockRed.kt`, `blockGetAllBlockedGifsInfo.kt`, `blockGetGifsInfoByUserName.kt`)
- **Finding:** `BlockRed.refreshListAndBlock()` unconditionally called `list.value.filterNot { it.id in blocked }`, allocating a new list and emitting to `StateFlow` even when `blockedIds` was empty or no items in the feed were blocked. Meanwhile, `blockGetAllBlockedGifsInfo()` called `blockGetGifsInfoByUserName(userDir.name)` via `flatMap`, repeating `File(AppPath.r_block)` construction, two `canonicalFile` syscalls (`requireInside`), and an intermediate list allocation per user directory.
- **Fix:** Guarded `BlockRed.refreshListAndBlock()` with `if (blocked.isEmpty()) return` and `current.any { it.id in blocked }`. Extracted `readBlockedGifsFromDir(blockDir, out)` so `blockGetAllBlockedGifsInfo()` populates a single `ArrayList<GifsInfo>()` across all user directories.

### Pass 768 — `:feature-r` (`GifsInfo.kt` & `URL1.kt`)
- **Finding:** `URL1.sanitize()` and `GifsInfo.sanitizeOrNull()` unconditionally called `.copy(...)` and `.mapNotNull(...)` on every item, allocating new `URL1`, `ArrayList<String>`, and `GifsInfo` objects even when 100% of fields were already non-null and valid. Furthermore, `List<GifsInfo>?.sanitizeGifsInfoList()` chained `.mapNotNull { ... }.distinctBy { it.id }`, allocating an intermediate list before deduplicating.
- **Fix:** Added fast identity returns (`return this`) in `URL1.sanitize()`, `sanitizeTagsList()`, and `GifsInfo.sanitizeOrNull()` when all fields are already valid, and fused `sanitizeOrNull()` + `seenIds.add(sanitized.id)` into a single pre-sized loop in `sanitizeGifsInfoList()`.
