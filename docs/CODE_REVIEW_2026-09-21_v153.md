## 1. Контекст и цели прохода

В рамках прохода 175 проведён глубокий аудит производительности Compose UI, направленный на устранение паразитных аллокаций во время композиции списков, обеспечение устойчивого пропуска рекомпозиций (smart skipping) для элементов списков и сеток, стабилизацию коллбеков в экранах поиска, сохранённого, тегов и локального плеера в модулях Luscious (`:feature-l`), Red (`:feature-r`) и X (`:feature-x`):

1. **Оптимизация каталога альбомов, поиска и топов (`ScreenAlbumList.kt`, `L_ScreenAlbumSearch.kt`, `L_ScreenAlbumTopHits.kt`, `L_Screen_CollectionTab.kt`, `:feature-l`)**:
   - **Проблема**:
     - В `ScreenAlbumList.kt`: коллбеки навигации, фильтра и пагинации (`onClickVisibleFilter`, `onPageChange`, `onAlbumClick`, `onFilterClose`, `onFilterApply`) передавались inline-лямбдами, лишая `ScreenAlbumListContent` и `AlbumFilterSheet` скипуемости при скролле и анимациях.
     - В `L_ScreenAlbumSearch.kt`: коллбеки ввода поиска и кликов по альбомам создавались inline при каждой рекомпозиции.
     - В `L_ScreenAlbumTopHits.kt`: `itemWidth = screenWidth.dp * 0.4f` пересчитывался в цикле элементов `itemsIndexed`; коллбеки `onAlbumClick` и `onSeeAllClick` создавались inline.
     - В `L_Screen_CollectionTab.kt`: коллбеки сортировки, выбора, контекстного меню и выхода из коллекции передавались inline.
   - **Решение**:
     - Все коллбеки стабилизированы через `remember` с явными ключами зависимостей (`navigator`, `vm`, `job`, `pagerState`).
     - В `L_ScreenAlbumTopHits.kt` расчёт `itemWidth` вынесен из цикла и мемоизирован через `remember(screenWidth)`.

2. **Smart skipping элементов скачиваний и сохранённых ниш (`R_Screen_Saved_DownloadTab.kt`, `SavedNichesTab.kt`, `:feature-r`)**:
   - **Проблема**:
     - В `R_Screen_Saved_DownloadTab.kt`: компонент `DownloadListItem` принимал 4 нуль-аргументных коллбека `() -> Unit`. В `items(downloadRed)` для каждой строки создавались новые замыкания (`{ sm.onItemClick(item) }`, `{ sm.onShareClick(item) }` и др.), что разрушало Compose skipping для всех строк списка скачиваний при скролле. Кроме того, пути `imagePath` и `mp4Path` формировались без мемоизации.
     - В `SavedNichesTab.kt`: элемент списка сохранённых ниш рендерился инлайн-блоком `Row` с лямбдами, пересоздаваемыми на каждый элемент.
   - **Решение**:
     - Сигнатуры `DownloadListItem` переведены на коллбеки уровня элемента `(GifsInfo) -> Unit`, передаваемые стабильными ссылками. Внутри строки вызовы мемоизированы через `remember(item, callback)`. Пути `imagePath` и `mp4Path` мемоизированы через `remember(item)`. Стабилизирован `scrollPercentProvider`.
     - Из `SavedNichesTab.kt` выделена скипуемая `@Composable fun SavedNicheRow` с коллбеками `(NichesInfo) -> Unit`. Коллбеки клика, удаления и скролл-провайдер стабилизированы.

3. **Стабилизация табов гифок, поиска и коллекций (`R_ScreenGifsTab.kt`, `SearchTab.kt`, `R_Screen_Saved_LikesTab.kt`, `R_Screen_CollectionTab.kt`, `:feature-r`)**:
   - **Проблема**: Коллбеки выбора сортировки, перехода в профиль автора, строки поиска и действий над коллекциями передавались нестабильными inline-лямбдами.
   - **Решение**: Все коллбеки обёрнуты в `remember`, предотвращая паразитные перерисовки родительских и дочерних контейнеров.

4. **Оптимизация экрана тегов и локального плеера (`ScreenTags.kt`, `ScreenX_LocalVideoPlayer.kt`, `:feature-x`)**:
   - **Проблема**:
     - В `ScreenTags.kt`: `loadPage = { vm.loadPage(it).items }`, `onOpenVideo = { ... }` и `onPageChange` передавались inline в `TagsPaginatedListScreen` и пагинатор, разрушая скипуемость страниц в `HorizontalPager`.
     - В `ScreenX_LocalVideoPlayer.kt`: `val resolvedItem = item ?: sm.saved.downloads.list.value.find { it.id == videoId } ?: ItemsX(id = videoId)` выполнял линейный поиск `.find` по всему списку загрузок и аллокацию дефолтного объекта при каждой рекомпозиции плеера. Коллбеки жестов и масштаба `onZoomChanged`, `onTap`, `onBackClick` создавались заново при каждом тике воспроизведения.
   - **Решение**:
     - В `ScreenTags.kt`: коллбеки `loadPage`, `onOpenVideo` и `onPageChange` стабилизированы через `remember`.
     - В `ScreenX_LocalVideoPlayer.kt`: `resolvedItem` мемоизирован через `remember(item, videoId, sm.saved.downloads.list.value)`, устранив линейные сканы. Коллбеки `onZoomChanged`, `onTap` и `onBackClick` стабилизированы через `remember`.

5. **Инварианты**:
   - P2P модуль (`core/.../p2p/`) строго заморожен и не модифицировался.
