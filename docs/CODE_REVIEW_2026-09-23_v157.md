## 1. Контекст и цели прохода (2-е код-ревью)

В рамках второго раунда ревью проведён глубокий аудит экранов, использующих компонент сетки `LazyRow123` и плавающие кнопки быстрой прокрутки (`FloatingScrollButtons`), а также экранов со смешанной иерархией контента. В фокусе внимания находился экран профиля RedGifs — [`ScreenRedProfile.kt`](file:///g:/xvideos2/feature-r/src/main/java/com/client/xvideos/r/ui/profile/ScreenRedProfile.kt) (`:feature-r`).

### Выявленные проблемы и решения:

1. **Дублирующий скроллбар (`VerticalScrollbar`) поверх `LazyRow123`**:
   - **Проблема**: Компонент `LazyRow123` уже инкапсулирует собственный `VerticalScrollbar`, автоматически учитывающий динамическое число колонок (`host.columns`) и смещение верхнего блока (`itemsToIgnore = if (contentBeforeList != null) 1 else 0`). При этом `ScreenRedProfile` в контейнере `Box` рендерил второй экземпляр `VerticalScrollbar(scrollPercent)` в правом краю экрана. Это приводило к наложению двух независимых полос прокрутки друг на друга и двойной нагрузке на отрисовку.
   - **Решение**: Удалён внешний контейнер `Box` со вторым `VerticalScrollbar`. Отрисовка скроллбара полностью и единообразно делегирована внутреннему механизму `LazyRow123` (по аналогии с `ScreenNiche`, `R_Screen_Saved_LikesTab` и другими экранами лент).

2. **Устранение избыточных вычислений скролла (`rememberVisibleRangePercentIgnoringFirstNForGrid`)**:
   - **Проблема**: В `ScreenRedProfile.Content()` на каждый кадр скролла выполнялся расчет `scrollPercent` с жестко зашитыми параметрами `itemsToIgnore = 3, numberOfColumns = 2` (хотя в реальной сетке колонок может быть другое число, а `contentBeforeList` занимает 1 слот элемента).
   - **Решение**: Полностью удалён вызов `rememberVisibleRangePercentIgnoringFirstNForGrid` и провайдер `scrollPercentProvider`, снижая нагрузку на CPU во время прокрутки.

3. **Ликвидация мёртвого кода навигации (`onBack`)**:
   - **Проблема**: После удаления статического `topBar` в коммите `852d8fc` параметр `onBack` остался висеть в сигнатуре `RedProfileScreenContent` со значением по умолчанию `{}` и в `ScreenRedProfile.Content()`, не вызываясь ни одним UI-элементом.
   - **Решение**: Удалена неиспользуемая лямбда `onBack` из `RedProfileScreenContent` и её формирование в `Content()`.

4. **Удаление неиспользуемой зависимости `LocalNavigator`**:
   - **Проблема**: Вызов `val navigator = LocalNavigator.currentOrThrow` в `ScreenRedProfile.Content()` существовал исключительно для передачи в удалённый `onBack`. Системный же возврат назад обрабатывается декларативным `BackHandler`:
     ```kotlin
     BackHandler(enabled = tagsSelect.isNotEmpty()) {
         vm.tagsSelect.value = emptySet()
     }
     ```
     Когда фильтр тегов пуст (`tagsSelect.isEmpty()`), `BackHandler` отключён (`enabled = false`), и системное нажатие «Назад» естественным образом закрывает экран через стековый навигатор Voyager.
   - **Решение**: Удалена неиспользуемая переменная `navigator` и импорт `cafe.adriel.voyager.navigator.LocalNavigator`.

5. **Очистка импортов и соблюдение стандартов форматирования**:
   - Удалены неиспользуемые импорты компоновки (`fillMaxHeight`, `width`) и утилит скролла.
   - Устранена лишняя пустая строка в конце файла для идеального прохождения `git diff --check`.
