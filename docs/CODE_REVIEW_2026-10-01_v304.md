## Находки

### C1 — Сетевая ошибка кэшируется как пустая страница канала. Высокая.

[ScreenX_ChannelSM.kt:356](../feature-x/src/main/java/com/client/xvideos/x/screens/channel/ScreenX_ChannelSM.kt:356)

`readHtmlFromURLDirect` при сбое возвращает `""`, парсер превращает это в пустой
список, и он ложится в `pagesCache`. `errorPages` не заполняется, повтор
невозможен: `loadPage` выходит по `pagesCache.containsKey`. Для страницы 0
`loadInitial` ставит `isEndReached = true` без ошибки — профиль выглядит пустым.

Чего нет: не воспроизведено на устройстве, вывод из чтения кода.

### C2 — Отменённая загрузка страницы удаляет записи новой. Средняя.

[ScreenX_ChannelSM.kt:378](../feature-x/src/main/java/com/client/xvideos/x/screens/channel/ScreenX_ChannelSM.kt:378)

`loadInitial` отменяет задачи и тут же запускает новые. `catch`/`finally`
отменённой задачи позже выполняют `loadingPages.remove(page)` и
`pageJobs.remove(page)` и удаляют записи новой задачи той же страницы. Её уже не
отменит следующая смена сортировки, и результат старой сортировки попадает в
`pagesCache` новой; снятый флаг загрузки допускает дублирующий запрос.

### C3 — Ошибка подгрузки индекса моделей завершает список. Средняя.

[ScreenX_ActressesIndexSM.kt:175](../feature-x/src/main/java/com/client/xvideos/x/screens/actresses/ScreenX_ActressesIndexSM.kt:175)

Неудачный запрос следующей страницы (`""`) разбирается в пустой список, и
`isEndReached = true`: бесконечная прокрутка останавливается до переоткрытия
экрана, ошибка не показывается.

### C4 — Неудачный поиск показывается как «ничего не найдено». Средняя.

[ScreenXSearchSM.kt:213](../feature-x/src/main/java/com/client/xvideos/x/screens/search/ScreenXSearchSM.kt:213)

Если не сработали ни прямой запрос, ни WebView, `fetchVideosPage` возвращает

### A1 — `""` как признак ошибки сети. Средняя.

[readHtmlFromURLDirect.kt:53](../feature-x/src/main/java/com/client/xvideos/x/feature/net/readHtmlFromURLDirect.kt:53)

Общая причина C1, C3, C4: «запрос упал» и «пустой ответ» неразличимы по типу.
`ScreenTagsViewModel` контракт соблюдает, три экрана — нет. Исправлять на

### C5 — Повторное нажатие «Скачать» качает тот же файл дважды. Средняя.

[SavedX_Downloads.kt:108](../feature-x/src/main/java/com/client/xvideos/x/feature/saved/SavedX_Downloads.kt:108)

`contains()` становится истинным только после завершения. Второе нажатие заново
резолвит прямую ссылку (с токеном, каждый раз другая), `KDownloader` не
распознаёт дубль, и две задачи пишут в один `<id>.mp4`. Все загрузки делят один
`_percent`: первая завершённая выставляет «готово», пока идёт вторая — тот же
дефект, что T1 прохода 170, исправленный тогда только для R.

### C6 — HTML из WebView декодируется из JSON вручную и не полностью. Средняя.

[readHtmlFromURLWebView.kt:149](../feature-x/src/main/java/com/client/xvideos/x/feature/net/readHtmlFromURLWebView.kt:149)

Результат `evaluateJavascript` — JSON-строка, а разбирается заменами только
`<`, `\n`, `\"`. Обратные слэши, `\t`, `\r`, `\/` и прочие `\uXXXX`
остаются в HTML, ссылки и данные из скриптов страницы портятся.

### T1 — Записи истории просмотров идут вперемешку. Низкая.

[SavedX_History.kt:110](../feature-x/src/main/java/com/client/xvideos/x/feature/saved/SavedX_History.kt:110)

Каждый `updateProgress` (раз в 3 секунды, при паузе и при закрытии плеера)
запускает отдельную запись того же файла. Записи завершаются в любом порядке:
позиция возобновления может откатиться на старую, а удалённая запись —
вернуться, если её последнее сохранение ещё шло.

### E1 — Лента подписок шлёт все запросы разом. Низкая.

[SavedX_Subscriptions.kt:264](../feature-x/src/main/java/com/client/xvideos/x/feature/saved/SavedX_Subscriptions.kt:264)

По запросу (до двух с фолбэком) на каждого автора без ограничения
параллелизма. При десятках подписок сайт ограничивает частоту, неудачные авторы
молча выпадают из ленты.

### R1 — `flagEmoji` дублирует `getFlagEmoji`. Низкая.

[ActressesIndexModel.kt:34](../feature-x/src/main/java/com/client/xvideos/x/model/ActressesIndexModel.kt:34)

Своя реализация флага страны со слабой проверкой рядом с `model/CountryFlag.kt`:

## Что осталось открытым

Все находки закрыты в `53bc3255`.
Сознательно не менялось: заголовок канала и рейтинги по-прежнему грузятся через
`readHtmlFromURLDirect` — без них экран деградирует мягко, а ошибку покажет
загрузка видео.

Отрицательные результаты:

- Порядок инициализации `ScreenX_VideoPlayerSM`: `loadJob` объявлен после
  `init { loadVideo() }`, но по байткоду конструктора повторного присваивания
  `null` нет — ссылка на первую загрузку сохраняется. Дефекта нет.
- Парсеры (`parcer/`, `search/`, `model/`) проверены на выход за границы:
  индексы и `substring` защищены проверками длины.
- `ScreenTagsViewModel` обрабатывает пустой ответ как ошибку — корректно.
- Подписки: проверка подписки реактивна (`mutableStateSetOf`), повторное
  добавление идемпотентно.
