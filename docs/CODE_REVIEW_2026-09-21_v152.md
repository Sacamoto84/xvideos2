## 1. Контекст и цели прохода

В рамках прохода 174 проведён комплексный аудит устойчивости Compose UI, устранения паразитных линейных сканов и аллокаций во время композиции, стабилизации обработчиков в панелях навигации и восстановления smart skipping в элементах списков и сеток для модулей Luscious (`:feature-l`), Red (`:feature-r`) и X (`:feature-x`):

1. **Оптимизация экрана альбома (`ScreenAlbum.kt`, `:feature-l`)**:
   - **Проблема**:
     - `val saved = parsed != null && ... && vm.saved.albums.list.any { it.id == parsed.id }`: `vm.saved.albums.list` является `SnapshotStateList`. Без `derivedStateOf` любое добавление или удаление любого другого альбома вызывало чтение списка и рекомпозицию экрана альбома.
     - `hasAnimatedItems = albumPicsDetails?.pics?.any { it.isAnimatedMedia() } == true`: при каждой рекомпозиции выполнялся полный линейный проход по списку картинок альбома (сотни и тысячи элементов).
     - `val strId`, `val strCreated`, `val strModified`: `buildAnnotatedString` аллоцировались заново при каждой рекомпозиции.
     - `AlbumInfoTags`: лямбда `tags` вызывалась при каждой композиции `FlowRow`, выполняя `.reversed().filter { it.count > 0 }`.
   - **Решение**:
     - `saved` и `hasAnimatedItems` обёрнуты в `remember(...) { derivedStateOf { ... } }`, рекомпозиция вызывается только при реальном изменении boolean-результата.
     - `strId`, `strCreated`, `strModified` мемоизированы через `remember`.
     - `activeTags` мемоизированы через `remember(parsed.tags)` и передаются стабильным замыканием.

2. **Стабилизация обработчиков в корневых TabRow навигации (`L_ScreenExplorer.kt`, `ScreenExplorer.kt`, `ScreenSaved.kt` в L и R)**:
   - **Проблема**: В корневых экранах разделов (`L_ScreenExplorer`, `ScreenRedExplorer`, а также `ScreenSaved` обоих разделов) обработчик `onChangeState` передавался анонимной лямбдой `{ ... }`. При любом обновлении процента скачивания (`percentDownload`) или количества колонок родительский экран рекомпоновался и заставлял `TabRow` перекомпоновываться из-за нестабильного экземпляра лямбды.
   - **Решение**: Обработчики `onTabChange` стабилизированы через `remember(vm)`, сохраняя smart skipping для `TabRow`.

3. **Стабилизация профиля автора и экрана ниши (`ScreenRedProfile.kt`, `ScreenNiche.kt`, `:feature-r`)**:
   - **Проблема**:
     - В `ScreenRedProfile.kt` коллбеки `onTagClick`, `onAppendLoaded`, `savedRedProvider`, `onBack` и `scrollPercent` передавались inline, из-за чего `RedProfileScreenContent` терял возможность пропуска рекомпозиции.
     - В `ScreenNiche.kt` провайдеры `relatedNiches`, `topCreators`, а также `onSortChange` и `onUpClick` создавались как inline-лямбды.
   - **Решение**: Все коллбеки и провайдеры мемоизированы через `remember` с соответствующими ключами зависимостей (`vm`, `navigator`, `scrollPercent`).

4. **Оптимизация дашбордов, плеера и сеток избранного (`ScreenXDashBoards.kt`, `ScreenFavorites.kt`, `ScreenX_VideoPlayer.kt`, `:feature-x`)**:
   - **Проблема**:
     - В `ScreenXDashBoards.kt` коллбеки табов `onSavedTabChange`, `onMainTabChange` и `onDashboardPageChange` создавались inline и пересоздавались при каждом тике прогресса загрузки (`downloadPercent`).
     - В `ScreenFavorites.kt` элемент сетки `FavoriteRow` принимал нуль-аргументные коллбеки `() -> Unit`, что вынуждало в `itemsIndexed` создавать для каждого элемента новые замыкания (`{ onDownload(item) }`, `{ onOpenVideo(item) }` и т.д.), полностью лишая `FavoriteRow` возможности скипать рекомпозицию при скролле.
     - В `ScreenX_VideoPlayer.kt` коллбеки `onZoomChanged` и `onTap` для `ComposeVideoPlayer` создавались inline.
   - **Решение**:
     - В `ScreenXDashBoards.kt` коллбеки табов и перелистывания страниц мемоизированы через `remember(vm)`.
     - В `ScreenFavorites.kt` коллбеки `FavoriteRow` переведены на сигнатуры уровня элемента `(ItemsX) -> Unit`, передаются стабильными ссылками, а вызовы с контекстом элемента инкапсулированы внутри строки через `remember(item, callback)`. `onDeleteItem` вынесен в `@Composable` скоуп. В результате строки сетки `FavoriteRow` получили полную скипуемость.
     - В `ScreenX_VideoPlayer.kt` коллбеки плеера стабилизированы через `remember`.

5. **Инварианты**:
   - P2P модуль (`core/.../p2p/`) строго заморожен и не модифицировался.
