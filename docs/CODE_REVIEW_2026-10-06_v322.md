### C1 — L: вкладка «Подписки на альбомы» падает после подгрузки страницы. Критично.

[SubscribedAlbumsGrid.kt:45](../feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/saved/subscribedAlbums/molecule/SubscribedAlbumsGrid.kt:45) ·
[LServerPagedList.kt:91](../feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/saved/LServerPagedList.kt:91) ·
[ScreenLAlbumSM.kt:133](../feature-l/src/main/java/com/client/xvideos/l/ui/screens/screenAlbum/ScreenLAlbumSM.kt:133)

Сетка задаёт ключ элемента `key = { it.id }`. Список приходит из
`LServerPagedList`: страницы запрашиваются по номеру и дописываются как
`publish(_items.value + list)` — повторы не убираются. Модель вкладки живёт
дольше экрана и о подписке, оформленной в другом месте, не знает: кнопка
серверного избранного на экране альбома (`toggleServerFavorite` →
`likeAlbum`) список не обновляет.

Если выдача «по дате» идёт от новых к старым, новая подписка сдвигает её на
одну позицию: первый альбом страницы N+1 — это последний альбом уже
загруженной страницы N. Два элемента с одним `id` в `LazyVerticalGrid` —
`IllegalArgumentException: Key "…" was already used`, приложение закрывается.

Как воспроизвести: учётная запись с подписками больше одной страницы; открыть
«Сохранённое → Подписки на альбомы»; перейти в каталог, открыть альбом без
подписки, нажать серверное избранное; вернуться во вкладку и прокрутить до
конца списка.

Чего нет: порядок выдачи сервера не проверен — при порядке «старые сверху»
сдвига не будет. Размер страницы сервера не проверен. Второй путь к тому же
падению — два альбома с пустым `id` (`AlbumDetails.id` по умолчанию `""`).

### C2 — Сетки коллекций R и L не обновляются при изменении списка. Средняя.

[L_SavedCollectionTabContent.kt:28](../feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/saved/collection/molecule/L_SavedCollectionTabContent.kt:28) ·
[L_Screen_CollectionTab.kt:177](../feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/saved/collection/L_Screen_CollectionTab.kt:177) ·
[R_Screen_CollectionTab.kt:168](../feature-r/src/main/java/com/client/xvideos/r/ui/explorer/tab/saved/tab/R_Screen_CollectionTab.kt:168) ·
[R_Screen_CollectionTab.kt:147](../feature-r/src/main/java/com/client/xvideos/r/ui/explorer/tab/saved/tab/R_Screen_CollectionTab.kt:147)

Обе молекулы строят элементы сетки так:
`val gridItems = remember(collectionList) { collectionList.map { … } }`.
В параметр передаётся сам `mutableStateListOf`
([SavedL_Collection.kt:48](../feature-l/src/main/java/com/client/xvideos/l/featured/saved/SavedL_Collection.kt:48),
[LinkCollectionStore.kt:29](../core/src/main/java/com/client/xvideos/common/collectionDB/model/LinkCollectionStore.kt:29)),
который меняется на месте через `replaceWith`. Ссылка та же — ключ `remember`
не меняется, и `gridItems` остаётся прежним, пока молекула не уйдёт из
композиции. Это случай из `CLAUDE.md` («Реактивность при выносе кода в
atom/molecule»).

У пользователя: на сетке коллекций создать коллекцию кнопкой «+»,
переименовать или удалить долгим нажатием — сетка показывает прежний набор;
удалённую коллекцию можно открыть. В L сетка обновится после входа в
коллекцию и выхода (ветка `AnimatedContent` компонуется заново); в R
`gridItems` считается над ветвлением и переживает и это.

Чего нет: `SnapshotStateList` без своего `equals` проверен по исходникам
`runtime-android 1.13.0-alpha01` из кэша Gradle, а не по версии, которую
разрешает BOM сборки. Код датирован 21.09 (R) и 30.09 (L).

### C5 — R: подтверждение поиска пересоздаёт все ленты раздела. Средняя.

[LazyRow123Host.kt:150](../feature-r/src/main/java/com/client/xvideos/r/ui/ui/lazyrow123/LazyRow123Host.kt:150)
