## Находки

### A1 — Область приложения без обработчика исключений. Средняя.

[core/.../di/CoroutinesModule.kt:21](../core/src/main/java/com/client/xvideos/common/di/CoroutinesModule.kt:21)

Область приложения — `SupervisorJob() + Dispatchers.IO` без
`CoroutineExceptionHandler`. `ExpandMenuViewModel` запускает на ней работу без
`try/catch`
([ExpandMenuVM.kt:91](../feature-l/src/main/java/com/client/xvideos/l/ui/element/expandMenu/ExpandMenuVM.kt:91),
158, 171). Любое исключение в таком запуске доходит до обработчика потока и
закрывает приложение. Конкретный источник уже найден — C1
[прохода 182](CODE_REVIEW_2026-10-05_v315.md).

Чинить по месту вызова — значит повторять `try/catch` в каждом запуске;
обработчик в самой области закрывает все места сразу.

### C1 — Авто-имя пресета молча перезаписывает другой пресет. Средняя.

[feature-l/.../filter/AlbumFilterPresetManager.kt:102](../feature-l/src/main/java/com/client/xvideos/l/featured/filter/AlbumFilterPresetManager.kt:102)

Пресет с тем же именем заменяется без вопроса, а имя по умолчанию строится из
части полей фильтра (строки 167–188). Два фильтра с двумя разными парами
включённых жанров оба называются «+2 genres» — второй заменяет первый.
Исключённые жанры, сортировка и размер альбома в имя не попадают: такие фильтры
получают «Preset N» по текущему числу пресетов, и после удаления одного номер
совпадает с уже занятым.

[feature-l/.../albumSearch/ScreenLAlbumSearchSM.kt:79](../feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/albumSearch/ScreenLAlbumSearchSM.kt:79)

### T1 — Порядок записи пресетов на диск не гарантирован. Низкая.

[feature-l/.../filter/AlbumFilterPresetManager.kt:104](../feature-l/src/main/java/com/client/xvideos/l/featured/filter/AlbumFilterPresetManager.kt:104)

Каждое сохранение и удаление запускает свою корутину на пуле IO со снимком
списка. Мьютекс исключает одновременную запись, но не порядок: поздний снимок
может лечь на диск раньше раннего. В памяти список верный, на диске
устаревший — после перезапуска удалённый пресет возвращается.

Чего у находки нет: не воспроизводилась, окно узкое. Запись текущего значения
под мьютексом вместо снимка его закрывает.

### C5 — Неразобранные элементы списков отбрасываются без лога. Низкая.

[feature-l/.../net/AlbumList.kt:258](../feature-l/src/main/java/com/client/xvideos/l/net/AlbumList.kt:258)

### A3 — Область пресетов без `SupervisorJob`, чтение на главном потоке. Низкая.

[feature-l/.../filter/AlbumFilterPresetManager.kt:62](../feature-l/src/main/java/com/client/xvideos/l/featured/filter/AlbumFilterPresetManager.kt:62)

Область менеджера — `CoroutineScope(Dispatchers.IO)`: первое исключение в
корутине записи отменило бы её целиком, и следующие сохранения молча не
писались бы. Сейчас тело записи обёрнуто в `runCatching`, сценарий не
достижим — защита держится на одной обёртке. `init()` читает
`SharedPreferences` из `LaunchedEffect`, то есть на главном потоке.

### Проверено, находок нет

- **Поиск.** `ScreenLAlbumSearchSM` отменяет прошлый запрос и сбрасывает флаг
  загрузки, только если корутина ещё текущая.
- **Список альбомов.** Сбой разбора удаляет ответ из RAM- и ROM-кэша; отмена
  пробрасывается.
- **Справочник категорий.** Разбор под `runCatching`, публикация на главном
  потоке. Устаревание `user_id` вынесено в C3 прохода 182.
