## 1. Контекст и цели прохода

В рамках прохода 169 проведён детальный аудит производительности рендеринга и стабильности Compose-состояний в экранах настроек бэкапа (`:app`) и подписок Red (`:feature-r`):

1. **Оптимизация консоли восстановления бэкапов (`BackupComponents.kt` в `:app`)**:
   - **Проблема 1 (выделение памяти на каждый кадр)**: В компоненте `BackupConsole` список строк `visibleLines` вычислялся без `remember`: `lines.ifEmpty { ... }.flatMap { entry -> entry.lineSequence().toList() }`. При частых перерисовках (или поступлении логов во время восстановления сотен файлов) происходило постоянное разбиение строк и аллокация промежуточных коллекций.
   - **Решение 1**: `visibleLines` обёрнут в `remember(lines) { ... }`.
   - **Проблема 2 (отсутствие ключей в элементах списка)**: В `LazyColumn` вызов `items(visibleLines.size)` не имел явного лямбда-ключа, что вызывало пересоздание `BackupConsoleLine` при мутациях родительских контейнеров.
   - **Решение 2**: Добавлен явный `key = { index -> index }`: `items(count = visibleLines.size, key = { index -> index }) { index -> BackupConsoleLine(...) }`.

2. **Оптимизация фильтрации и группировки дерева папок бэкапа (`BackupComponents.kt` в `:app`)**:
   - **Проблема**: В `BackupFolderList` на каждой рекомпозиции (включая клик по чекбоксу или раскрытие секции) заново выполнялся $O(N)$ проход `items.filter { it.parentPath == null }`, а затем для каждой корневой папки — отдельный поиск `items.filter { it.parentPath == section.path }`.
   - **Решение**: Выделены мемоизированные коллекции:
     ```kotlin
     val rootItems = remember(items) { items.filter { it.parentPath == null } }
     val childrenByParent = remember(items) {
         items.filter { it.parentPath != null }.groupBy { it.parentPath }
     }
     ```
     Дочерние элементы теперь извлекаются за $O(1)$ по ключу `childrenByParent[section.path].orEmpty()`.

3. **Стабилизация реактивного ключа флага выбора авторов (`R_Screen_Saved_SubscriptionsTab.kt` в `:feature-r`)**:
   - **Проблема**: Флаг `hasSelectedCreators` вычислялся через `remember { derivedStateOf { selectedListCreator.any { it.select } } }` без передачи ключа зависимости. При повторном монтировании вкладки или смене модели `derivedStateOf` мог застрять на предыдущем экземпляре списка.
   - **Решение**: Добавлен явный ключ: `remember(selectedListCreator) { derivedStateOf { ... } }`.

4. **Инварианты**:
   - P2P модуль (`core/.../p2p/`) строго заморожен и не изменялся.
