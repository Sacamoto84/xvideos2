# Код-ревью: Итерация 121 (2026-09-19)

**Фокус ревью:** `:app`, `:core`, `:feature-l`, `:feature-r`, `:feature-x` (безопасность PIN-кода AppLock, возобновление воспроизведения X и авто-скрытие уведомления, защита жизненного цикла ProcessLifecycleOwner при неинициализированных настройках, кэширование регулярных выражений в Luscious, полное устранение устаревших компонентов Material 2).

---

## 1. Контекст и цели
1. Устранить уязвимость утечки PIN-кода [S13] в `CamouflageVerificationDialog` (`AppLockSection.kt`): хранение пользовательского PIN в `rememberSaveable` приводило к сохранению секретного кода в открытом виде в Bundle сохранённого состояния Android при поворотах экрана.
2. Исправить логику возобновления воспроизведения [C37] в `ScreenX_VideoPlayerSM` и `ScreenX_VideoPlayer.kt`:
   - Состояние возобновления вычислялось единожды в конструкторе SM как неизменяемое поле (`val`), из-за чего для роликов, чей ID разрешался из HTML-страницы (`resolvedId`), возобновление не активировалось;
   - Обеспечить корректный сброс позиции и скрытие плашки при перезапуске (`restartFromBeginning()`);
   - Гарантировать автоматическое скрытие плашки через 4 секунды при непрерывном воспроизведении.
3. Предотвратить падение приложения [T46] в `AppLockLifecycleObserver.kt` и `AppLockRepository.kt` при возникновении событий жизненного цикла процесса до завершения инициализации `Settings` (`UninitializedPropertyAccessException`). Обеспечить тестируемость через инжекцию `elapsedRealtimeProvider` и покрыть сценарии модульными тестами.
4. Оптимизировать производительность [P48] в `LusciousServerFavoritesRepositoryImpl.kt`: устранить повторную компиляцию и аллокацию объектов `Regex` при каждом разрешении ID картинки через вынос скомпилированных шаблонов на уровень файла.
5. Завершить глобальную миграцию на Material 3 [UI40]: полностью ликвидировать остаточные импорты `androidx.compose.material.*` (компоненты `Icon`, `Text`, `Scaffold`, `TabRowDefaults`) во всех модулях проекта (`:core`, `:feature-l`, `:feature-r`, `:feature-x`).

## 2. Выявленные замечания и исправления

### [S13] Утечка PIN-кода маскировки AppLock в SavedState Bundle
- **Проблема:** В [AppLockSection.kt](file:///g:/xvideos2/app/src/main/java/com/client/xvideos/screenSettings/components/AppLockSection.kt) поля `pinInput` и `pinError` в `CamouflageVerificationDialog` хранились в `rememberSaveable { mutableStateOf("") }`. При изменении конфигурации устройства (поворот экрана) или вытеснении процесса Android сериализует Bundle в открытом виде, что создаёт уязвимость компрометации кода доступа.
- **Решение:**
  - `pinInput` и `pinError` переведены на `remember`.
  - Реализован `handleDismiss`, принудительно обнуляющий `pinInput = ""` и `pinError = null` при закрытии диалога.
  - При успешной проверке PIN также очищается из памяти (`pinInput = ""`).
- **Статус:** Исправлено.

### [C37] Возобновление воспроизведения X и авто-скрытие плашки
- **Проблема:**
  - В [ScreenX_VideoPlayerSM.kt](file:///g:/xvideos2/feature-x/src/main/java/com/client/xvideos/x/screens/videoplayer/ScreenX_VideoPlayerSM.kt) свойства `historyItem`, `resumePositionSeconds` и `resumeNoticeText` были объявлены как неизменяемые свойства (`val`), вычисляемые в момент создания SM. Если URL видео не содержал ID в явном виде и ID извлекался позже из HTML-страницы (`parsedData.pageVideoId`), состояние возобновления оставалось `null`.
  - При нажатии кнопки «С начала» в [ScreenX_VideoPlayer.kt](file:///g:/xvideos2/feature-x/src/main/java/com/client/xvideos/x/screens/videoplayer/ScreenX_VideoPlayer.kt) вызывался только `dismissResumeNotice()`, не сбрасывавший `resumePositionSeconds`.
- **Решение:**
  - `historyItem`, `resumePositionSeconds` и `resumeNoticeText` переведены в реактивные Compose-состояния (`var ... by mutableStateOf(...)`).
  - Добавлен метод `checkAndInitResume(videoId: Long)`, вызываемый как при инициализации SM, так и при разрешении `resolvedId > 0L` после парсинга HTML.
  - Добавлен метод `restartFromBeginning()`, обнуляющий позицию и скрывающий уведомление.
  - В `ScreenX_VideoPlayer.kt` кнопка «С начала» переведена на `vm.restartFromBeginning()`.
- **Статус:** Исправлено.

### [T46] Защита от сбоев при неинициализированных Settings в ProcessLifecycleOwner
- **Проблема:**
  - В [AppLockLifecycleObserver.kt](file:///g:/xvideos2/core/src/main/java/com/client/xvideos/common/applock/AppLockLifecycleObserver.kt) методы `onStop` и `onStart` обращались к `Settings.app_lock_timeout_seconds.field.value` напрямую.
  - В [AppLockRepository.kt](file:///g:/xvideos2/core/src/main/java/com/client/xvideos/common/applock/AppLockRepository.kt) метод `isEnabled` обращался к `Settings.app_lock_enabled.field.value`.
  - Если событие жизненного цикла процесса происходило до завершения `Settings.init(...)` (или в изолированных тестовых окружениях), выбрасывалось `UninitializedPropertyAccessException: lateinit property pref has not been initialized`.
  - Прямой вызов `SystemClock.elapsedRealtime()` в методах жизненного цикла без возможности внедрения монотонных часов препятствовал чистому юнит-тестированию на JVM.
- **Решение:**
  - В `AppLockRepository.isEnabled` добавлена проверка `Settings.isInitialized`.
  - В `AppLockLifecycleObserver.onStop` и `onStart` чтение настроек обёрнуто проверкой `Settings.isInitialized` с безопасным дефолтом `AppLockTimeout.DEFAULT.seconds`.
  - Добавлен параметр `elapsedRealtimeProvider: () -> Long = { SystemClock.elapsedRealtime() }`.
  - Написан изолированный модульный тест [AppLockLifecycleObserverTest.kt](file:///g:/xvideos2/core/src/test/java/com/client/xvideos/common/applock/AppLockLifecycleObserverTest.kt).
- **Статус:** Исправлено.

### [P48] Кэширование скомпилированных регулярных выражений в Luscious
- **Проблема:** В [LusciousServerFavoritesRepositoryImpl.kt](file:///g:/xvideos2/feature-l/src/main/java/com/client/xvideos/l/repository/LusciousServerFavoritesRepositoryImpl.kt) функция `extractSlugCandidate` при каждом вызове компилировала три регулярных выражения: `Regex("""[0-9A-HJKMNP-TV-Z]{26}""")`, `Regex("""\.\d+x\d+\.[a-zA-Z0-9]+$""")` и `Regex("""\.[a-zA-Z0-9]+$""")`, создавая лишнюю нагрузку на GC при разрешении картинок в альбомах.
- **Решение:** Выражения вынесены в `private val` уровня файла: `ULID_REGEX`, `DIMENSIONS_EXT_REGEX`, `EXT_REGEX`.
- **Статус:** Исправлено.

### [UI40] Полное устранение остаточных импортов Material 2
- **Проблема:** В нескольких модулях оставались устаревшие зависимости `androidx.compose.material.*`:
  - `:core`: `PlayerSpeedButton.kt` (`Text`), `ButtonMoreVert.kt` (`Icon`), `IconSave18.kt`, `IconPerson18.kt`, `IconFavorite18.kt` (`Icon`), `TabRow.kt` (`Icon`, `TabRowDefaults`).
  - `:feature-x`: `X_DashboardExpandMenu.kt` (`Icon`, `Text`), `ScreenFavorites.kt` (`Icon`, `IconButton`, `Scaffold`, `Text`).
  - `:feature-r`: `CustomBasicTextFieldContent.kt` (`Icon`, `Text`).
  - `:feature-l`: `L_FullScreenImage.kt` (`ExperimentalMaterialApi`).
- **Решение:**
  - Все перечисленные файлы мигрированы на чистый Material 3 (`androidx.compose.material3.*`).
  - `Scaffold` в `ScreenFavorites.kt` переведён на `containerColor`.
  - Индикатор `TabRow.kt` переведён на `TabRowDefaults.SecondaryIndicator`.
  - Неиспользуемый аннотационный импорт в `L_FullScreenImage.kt` удалён.
  - Поиск `import androidx.compose.material.[A-Z]` по всему проекту подтверждает **0** остаточных импортов M2.
- **Статус:** Исправлено.
