# Code Review & Optimization Report — Batch 38 (v254)

**Date:** 2026-09-25  
**Passes:** 889 – 896  
**Scope:** Album list filtering and preset state representations, repository sealed action modernization, Red niche domain models and deserialization sanitization, video duration parsing memory allocation optimizations, haptic feedback waveform allocation elimination, and GraphQL album metadata query validation.

---

### Pass 889 (`:feature-l` — `AlbumListFilter.kt`)
- **Finding:** `AlbumListFilter` lacked domain query state inspection properties (`hasSearchQuery`, `hasTags`, `hasGenres`, `isFiltered`), requiring callers to manually inspect raw string and list fields, and lacked a standardized `DEFAULT` companion instance.
- **Fix:** Added `hasSearchQuery`, `hasTags`, `hasGenres`, and `isFiltered` computed properties, along with `AlbumListFilter.DEFAULT` companion object.

---

### Pass 890 (`:feature-l` — `SavedAlbumFilter.kt`)
- **Finding:** `SavedAlbumFilter` lacked default parameter values for `name` and `filter`, lacked validation helper `isValid`, and lacked a standardized `EMPTY` instance.
- **Fix:** Provided default parameter values (`name = ""`, `filter = AlbumListFilter.DEFAULT`), added `isValid: Boolean get() = name.isNotBlank()`, and introduced `SavedAlbumFilter.EMPTY` companion instance.

---

### Pass 891 (`:feature-l` — `RepositoryAction.kt`)
- **Finding:** `RepositoryAction.Login` was declared as a plain `object`, missing modern Kotlin `data object` semantics for consistent `toString`, `equals`, and `hashCode` implementations in reactive repository pipelines.
- **Fix:** Converted `object Login : RepositoryAction()` to `data object Login : RepositoryAction()`.

---

### Pass 892 (`:feature-r` — `NichesInfo.kt`)
- **Finding:** `NichesInfo` used non-empty dummy string defaults (`"cover"`, `"description"`, `"owner"`, `"thumbnail"`, `"rules"`) for missing JSON fields, populating fallback strings into domain objects instead of proper null/empty values. Also lacked validation helpers and companion instances.
- **Fix:** Cleaned dummy defaults to `null` and `""`, added `isValid`, `isEmpty`, and `isNotEmpty` properties, and added `EMPTY` companion objects to both `NichesInfo` and `NicheResponse`.

---

### Pass 893 (`:feature-r` — `NichesResponse.kt`)
- **Finding:** `NichesResponse`, `Niche`, and `Preview` lacked domain inspection properties (`isEmpty`, `isNotEmpty`, `hasMorePages`, `isValid`) and standardized `EMPTY` companion instances.
- **Fix:** Added `isEmpty`, `isNotEmpty`, `hasMorePages` to `NichesResponse`; `isValid`, `isEmpty`, `isNotEmpty` to `Niche`; `isValid` to `Preview`; and added `EMPTY` companion objects to all three models.

---

### Pass 894 (`:feature-x` — `XSite.kt`)
- **Finding:** `parseDurationToMs(raw: String)` executed `raw.trim().lowercase()` prior to checking if the string was blank, causing two unnecessary string heap allocations for empty or blank duration inputs.
- **Fix:** Added an early `if (raw.isBlank()) return 0L` fast path before executing trimming and case conversion.

---

### Pass 895 (`:core` — `vibrateWithPatternAndAmplitude.kt`)
- **Finding:** `vibrateWithPatternAndAmplitude` allocated new `longArrayOf(0, 25, 50, 50)` and `intArrayOf(0, 255, 0, 127)` arrays on every haptic vibration invocation.
- **Fix:** Preallocated `VIBRATION_PATTERN` and `VIBRATION_AMPLITUDES` at file scope, eliminating heap allocations during user haptic feedback interactions.

---

### Pass 896 (`:feature-l` — `getAlbumInfo.kt`)
- **Finding:** `getAlbumInfo(albumId: Int)` constructed GraphQL queries with negative or zero album IDs, generating invalid GraphQL payloads that would fail on server requests.
- **Fix:** Added early return guard `if (albumId <= 0) return ""` to prevent invalid query construction and avoid wasteful server roundtrips.
