## Summary of Passes (785–792)

### Pass 785 — `:feature-x` (`parseHTML5Player.kt`)
- **Finding:** `parseHTML5Player()` evaluated 17 regex patterns across the script before checking if any video source (`videoUrlLow`, `videoUrlHigh`, `videoHLS`) existed. Unplayable scripts executed 14 useless regex matcher operations. `unescapeUrl()` ran `.contains` and `.replace` before checking for empty strings.
- **Fix:** Extracted `videoUrlLow`, `videoUrlHigh`, `videoHLS` first and performed an early return if all are blank, skipping 14 regex passes. Optimized `unescapeUrl()` to trim first and immediately return `""` when empty.

### Pass 786 — `:feature-x` (`parserVideoPreviewFromImageUrl.kt`)
- **Finding:** `parserVideoPreviewFromImageUrl` executed `url.split("/")` (creating an array of 8–10 string objects) on all image URLs, even if the URL did not contain `"videos"` or `"xvideos-cdn.com"`.
- **Fix:** Added a fast-path check `if (!url.contains("videos") && !url.contains("xvideos-cdn.com", ignoreCase = true)) return null` before executing `split("/")`.

### Pass 787 — `:feature-x` (`parserItemVideoTags.kt`)
- **Finding:** When a video had no uploaders, models, or tags, `parserItemVideoTags` still allocated a new `TagsModel` instance and a new empty `ArrayList`.
- **Fix:** Returned cached singleton `EMPTY_TAGS_MODEL` when all 3 collections are empty, and avoided array allocation when `tagsSet` is empty.

### Pass 788 — `:feature-x` (`parserScreenTags.kt`)
- **Finding:** In `parserScreenTags()`, `videos.isEmpty()` allocated an empty `ArrayList<ItemsX>` instead of using `emptyList()`. In `parseLastPage()`, CSS selector `pagination.select("a")` was parsed instead of using the faster DOM tag lookup.
- **Fix:** Short-circuited with `emptyList()` when `videos.isEmpty()` and replaced `pagination.select("a")` with `pagination.getElementsByTag("a")`.

### Pass 789 — `:feature-l` (`getAlbumListGraphQL.kt`)
- **Finding:** `jsonEscape(value: String)` unconditionally copied each character into a new `StringBuilder` and allocated a new `String`, even when the string contained no characters needing escaping (typical for tags, display modes, and IDs).
- **Fix:** Added a fast-path scan returning the original `value` unchanged if no escape characters (`\\`, `"`, control characters) are present.

### Pass 790 — `:feature-l` (`AlbumInfo.kt`)
- **Finding:** In `parseAlbumDetails()`, GraphQL errors returned by Luscious were ignored, causing the parser to fail with a confusing `missing data.album.get` error.
- **Fix:** Extracted `json["errors"]` first to surface the exact GraphQL error message from the server.

### Pass 791 — `:feature-l` (`AlbumList.kt`)
- **Finding:** In `parseAlbumListResponse()`, `itemsJson.isEmpty()` allocated an empty `ArrayList<Album>(0)`, and GraphQL errors were not extracted.
- **Fix:** Added GraphQL `errors` extraction and returned `emptyList()` when `itemsJson.isEmpty()`.

### Pass 792 — `:core` (`replaceWith.kt`)
- **Finding:** `SnapshotStateList.replaceWith(items)` unconditionally executed `clear()` and `addAll(items)`, causing Compose UI observers to recompose even when the incoming collection was identical.
- **Fix:** Added `if (isEmpty() && items.isEmpty()) return; if (this == items) return` to eliminate redundant mutations and UI recomposition on identical updates.
