## Находки

### C1 — Отсутствие промежуточного скролла к началу страницы альбомов в ScreenAlbumList. Средняя.

[feature-l/src/main/java/com/client/xvideos/l/ui/screens/screenAlbumList/ScreenAlbumList.kt:145-160](file:///g:/xvideos2/feature-l/src/main/java/com/client/xvideos/l/ui/screens/screenAlbumList/ScreenAlbumList.kt#L145-L160)

В `ScreenAlbumListContent` обработчик «Назад» при закрытом диалоге фильтров сразу проверял номер страницы пейджера (`vm.statePager.currentPage > 0`) или закрывал экран (`navigator.pop()`). При пролистывании сетки альбомов вниз (`currentGridState.firstVisibleItemIndex > 0`) нажатие кнопки «Назад» на нулевой странице сразу закрывало весь раздел или выходило из приложения, игнорируя прокрутку сетки.

**Решение:**
В цепочку приоритетов `BackHandler` перед сменой страницы пейджера и выходом внедрена проверка `isGridScrolled`:
```kotlin
val currentGridState = vm.stateGrid[vm.statePager.currentPage]
val isGridScrolled = currentGridState != null && currentGridState.firstVisibleItemIndex > 0
BackHandler(enabled = !showFilterDialog && isGridScrolled) {
    scope.launch { currentGridState?.animateScrollToItem(0) }
}
```

### C2 — Отсутствие скролла к началу в ScreenAlbum при возврате назад и неполный паритет тулбара. Средняя.

[feature-l/src/main/java/com/client/xvideos/l/ui/screens/screenAlbum/ScreenAlbum.kt:114-126, 240-255](file:///g:/xvideos2/feature-l/src/main/java/com/client/xvideos/l/ui/screens/screenAlbum/ScreenAlbum.kt#L114-L126)

В `ScreenAlbum.kt` при просмотре альбома с большим количеством медиа-файлов и прокрутке вниз (`vm.host.state.firstVisibleItemIndex > 0`):
1. Системный жест «Назад» при отсутствии диалогов и выключенном фильтре `showOnlyAnimated` сразу вызывал `navigator.pop()`.
2. Кнопка «Назад» в шапке экрана также сразу закрывала альбом через `navigator.pop()`.

**Решение:**
В `BackHandler` и кнопку тулбара `IconButton` добавлен промежуточный шаг возврата: при `vm.host.state.firstVisibleItemIndex > 0` плавно анимировать скролл к началу альбома (`scope.launch { vm.host.state.animateScrollToItem(0) }`), и лишь при нахождении в начале — производить выход.

### C3 — Преждевременный выход из открытой коллекции в ScreenCollectionName. Средняя.

[feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/saved/collection/ScreenCollectionName.kt:120-135, 150-165](file:///g:/xvideos2/feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/saved/collection/ScreenCollectionName.kt#L120-L135)

В открытой коллекции Luscious (`ScreenCollectionName`) при пустом поисковом запросе и закрытой строке поиска нажатие «Назад» сразу закрывало коллекцию (`handleExit()`). При пролистывании изображений вниз пользователь терял контекст просмотра. В кнопке возврата в `LCollectionDetailTopBar` аналогично отсутствовал скролл к началу.

**Решение:**
1. В `BackHandler` добавлен приоритет: если `host.state.firstVisibleItemIndex > 0`, запускается `scope.launch { host.state.animateScrollToItem(0) }`, и только на нулевой позиции — `handleExit()`.
2. В `LCollectionDetailTopBar` `onExitCollection` также поддержан предварительный скролл к началу.

### C4 — Отсутствие скролла к началу сетки коллекций в L_Screen_CollectionTab. Средняя.

[feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/saved/collection/L_Screen_CollectionTab.kt:85-102](file:///g:/xvideos2/feature-l/src/main/java/com/client/xvideos/l/ui/screens/explorer/tab/saved/collection/L_Screen_CollectionTab.kt#L85-L102)

В общем списке сохранённых коллекций Luscious при `selectedCollection == null` и закрытых диалогах действий/переименования/удаления нажатие «Назад» перехватывалось родительским экраном `ScreenSaved` и сразу переключало вкладку на «Понравившиеся».

**Решение:**
Добавлен `BackHandler(enabled = selectedCollection == null && itemPendingAction == null && itemPendingRename == null && itemPendingDelete == null && vm.gridState.firstVisibleItemIndex > 0)` с вызовом `vm.gridState.animateScrollToItem(0)`.
