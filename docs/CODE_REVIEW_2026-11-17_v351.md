[feature-n/src/main/java/com/client/xvideos/n/ui/molecule/NCloudflareChallengeDialog.kt:134](file:///H:/xvideos2/feature-n/src/main/java/com/client/xvideos/n/ui/molecule/NCloudflareChallengeDialog.kt#L134)  
[feature-n/src/main/java/com/client/xvideos/n/ui/molecule/NLoginDialog.kt:134](file:///H:/xvideos2/feature-n/src/main/java/com/client/xvideos/n/ui/molecule/NLoginDialog.kt#L134)

В функциях `setupCloudflareWebView` и `setupNLoginWebView` в настройках WebView принудительно включен флаг:
```kotlin
allowFileAccess = true
```
Оба этих компонента открывают внешние сетевые страницы сайта (`https://nhentai.net/` и `https://nhentai.net/login/`). Включение `allowFileAccess = true` для WebView, работающих с сетевым контентом, является известной уязвимостью в Android (начиная с API 29 он отключен по умолчанию), так как при наличии XSS или вредоносных внешних редиректов JavaScript на странице может попытаться прочитать файлы из локальной приватной песочницы приложения (`file://`).

Локальные файлы этим компонентам не требуются. Необходимо установить `allowFileAccess = false`.

Отдельно: уязвимость подтверждена статическим анализом конфигурации WebSettings; прямая эксплуатация требует XSS-инъекции на стороне внешнего домена.

### C1 — Утечка сетевых соединений и сокетов OkHttp в `NClient.executeRequest` при исключениях чтения ответа. Высокая.

[feature-n/src/main/java/com/client/xvideos/n/net/NClient.kt:80-97](file:///H:/xvideos2/feature-n/src/main/java/com/client/xvideos/n/net/NClient.kt#L80-L97)

В методе `executeRequest` ответ OkHttp обрабатывается напрямую:
```kotlin
val response = okHttpClient.newCall(request).execute()
val code = response.code
val body = response.body.string()
```
Если на этапе `response.body.string()` возникает исключение (таймаут соединения при чтении потока, обрыв сокета, `OutOfMemoryError`), или если в коде возникнет непредвиденный сбой, объект `response` и его поток `ResponseBody` не закрываются. В OkHttp это приводит к утечке сокетов пула соединений (`ConnectionPool`) и файловых дескрипторов процесса.

Корректный паттерн:
```kotlin
okHttpClient.newCall(request).execute().use { response ->
    val code = response.code
    val body = response.body.string()
    ...
}
```

Отдельно: подтверждено анализом жизненного цикла ресурсов OkHttp.

### C5 — Блокирующий дисковый I/O на главном потоке в `NFavoritesRepository.isFavorite`. Низкая.

[feature-n/src/main/java/com/client/xvideos/n/saved/NFavoritesRepository.kt:31-34](file:///H:/xvideos2/feature-n/src/main/java/com/client/xvideos/n/saved/NFavoritesRepository.kt#L31-L34)

Метод `isFavorite(id: Long)` обращается напрямую к `db.contains(id.toString())`:
```kotlin
fun isFavorite(id: Long): Boolean {
    if (!AppPath.isInitialized) return false
    return db.contains(id.toString())
}
```
В `FileDB.contains` выполняется синхронная блокирующая проверка файла на диске: `File(dir, "$nameFile$dotExtension").exists()`. При вызове в процессе отрисовки UI это приводит к дисковому I/O на главном потоке. В отличие от `NLikesRepository`, где проверяется `likes.any { it.id == id } || db.contains(id)`, в `NFavoritesRepository` оперативный кэш `favorites` (`SnapshotStateList`) игнорируется.

Необходимо заменить проверку на `favorites.any { it.id == id }` (или чтение кэшированного `Set`), исключив синхронный доступ к диску.

Отдельно: подтверждено реализацией `FileDB.contains`.

По правилам поддержки складных устройств (`CLAUDE.md`, «Складные телефоны»):

Необходимо использовать `adaptiveListPadding(PaddingValues(8.dp))`.
