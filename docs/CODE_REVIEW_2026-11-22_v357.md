## Находки

### C1 · P1 · Прерванный ZIP принимается и заменяет содержимое папки

При восстановлении старого формата чтение заканчивается по `nextEntry == null`. Если копирование оборвалось между записями, `ZipInputStream` может вернуть `null` после целого файла, хотя в архиве отсутствуют оставшиеся записи и центральный каталог. В режиме «Заменить» первая подходящая запись уже даёт основание заменить всю папку. Перед заменой проверять полноту ZIP и его оглавление. Отклонённый архив должен оставлять библиотеку в прежнем состоянии. [Проверка архива](../core/src/main/java/com/client/xvideos/common/backup/XlrBackupManager.kt#L626), [подмена папок](../core/src/main/java/com/client/xvideos/common/backup/XlrBackupManager.kt#L316)

Подтверждено вызовом штатного `restoreArchive` на JVM. `ZipFile` отклонил оборванный ZIP. Восстановление из того же файла вернуло успех, записало первый элемент и удалило локальную запись из «Избранного» X.

### C2 · P1 · Восстановление R может удалить сохранённые комнаты XLive

После применения выбранных папок движок в любом случае запускает перенос `X/Live` в `XLive` с режимом текущего восстановления. Если старая папка ещё осталась на диске, режим «Заменить» удаляет нынешнюю папку XLive, даже когда пользователь выбрал только R. Преобразовывать старые пути из выбранного архива во временной папке до применения журнала восстановления. Перенос оставшихся локальных файлов выполнять по правилам обычной миграции. [Вызов переноса](../core/src/main/java/com/client/xvideos/common/backup/XlrBackupManager.kt#L324), [удаление текущей папки](../core/src/main/java/com/client/xvideos/common/backup/XLiveLegacyFolder.kt#L39)

Подтверждено на JVM. При одновременном наличии старой и новой папок «Мои» восстановлен только раздел R. Современная запись XLive исчезла, на её месте осталась запись из старой локальной папки.

### T1 · P2 · Запуск R может прочитать данные до завершения отката восстановления

`App` запускает откат журнала в фоне. Обычный `SplashActivity` вызывает инициализатор до ожидания `StorageCleanupGate`. Если чтение сохранённого и списка блокировок R приходится на момент до возврата прежних папок, в памяти оказываются преждевременные результаты. `MainActivity` ждёт гейт, но следующий вызов `init()` уже пропускается, поскольку флаг выставлен при первом входе. Ожидать завершения отката перед созданием хранилищ. Считать инициализацию готовой после завершения чтений и разрешать повтор после отмены или сбоя. Условие гонки подтверждено по цепочке вызовов. [Фоновый откат](../app/src/main/java/com/client/xvideos/App.kt#L105), [обычный запуск](../app/src/main/java/com/client/xvideos/SplashActivity.kt#L130), [флаг инициализации](../app/src/main/java/com/client/xvideos/AppStartupInitializer.kt#L31), [ожидание из главного экрана](../app/src/main/java/com/client/xvideos/MainActivity.kt#L423)

### T2 · P2 · Запись эфира XLive может продолжаться без записанного видео

Если адрес эфира обновляется успешно, но медиаплейлист на каждом новом адресе отвечает `401`, `403`, `404` или `410`, рекордер снова запрашивает адрес. Предел в 25 секунд и пауза работают в ветке, в которой адрес обновить не удалось. Индикатор продолжает показывать запись, а приложение повторяет сетевые запросы без новых видеосегментов. Проверять время с записи последнего видеосегмента при любом исходе обновления адреса и ограничить частоту повторов. Условие подтверждено по циклу рекордера. [Обработка ответа медиаплейлиста](../feature-xlive/src/main/java/com/client/xvideos/xlive/record/XLiveRecorder.kt#L227), [повтор после обновления адреса](../feature-xlive/src/main/java/com/client/xvideos/xlive/record/XLiveRecorder.kt#L245)

### C3 · P2 · В L кэш альбома переносит состояние избранного между профилями

Полный бандл альбома хранится до семи дней по одному `albumId` и содержит `like_status` текущего профиля. При открытии из кэша сетевое чтение пропускается. Если открыть сохранённый в избранном альбом под профилем A, сменить профиль на B и открыть его снова, кнопка может показать статус A и отправить запрос на удаление вместо добавления. Получать персональный статус для активного профиля отдельно от кэша альбома. Проверено по ключу, сериализованным полям и выбору мутации. [Ключ кэша](../feature-l/src/main/java/com/client/xvideos/l/repository/Repository.kt#L562), [загрузка из кэша](../feature-l/src/main/java/com/client/xvideos/l/net/AlbumInfo.kt#L121), [выбор серверного действия](../feature-l/src/main/java/com/client/xvideos/l/ui/screens/screenAlbum/ScreenLAlbumSM.kt#L111)

### C4 · P2 · Полноэкранная лента R не даёт повторить загрузку следующей страницы

Полноэкранный пейджер добавляет страницу с индикатором только при `LoadState.Loading`. После ошибки дозагрузки индикатор исчезает, а кнопка повтора доступна только в сетке. Если связь пропадёт у конца списка, она может вернуться, но пользователь останется на последнем загруженном ролике. Показывать ошибку дозагрузки с действием `retry()` на последней служебной странице. Проверено по обработке состояний в пейджере и сетке. [Полноэкранный пейджер](../feature-r/src/main/java/com/client/xvideos/r/ui/fullscreen/molecule/RedFullScreenFeed.kt#L52), [повтор в сетке](../feature-r/src/main/java/com/client/xvideos/r/ui/ui/lazyrow123/LazyRow123.kt#L274)

### C5 · P2 · Поиск X после возврата из результатов показывает старые или пустые подсказки

Переход из истории сразу задаёт запрос и открывает результаты. Коллектор подсказок получает запрос после задержки и пропускает его, пока открыт режим результатов. При нажатии «Назад» меняется режим экрана, а запрос остаётся тем же. Коллектор ничего не получает, поэтому подсказки пусты или относятся к прежнему запросу до следующего ввода. Загружать подсказки при входе в этот режим с текущим текстом. Подтверждено по обработчикам истории, запроса и возврата. [Выбор записи истории](../feature-x/src/main/java/com/client/xvideos/x/screens/search/ScreenXSearchTab.kt#L145), [коллектор подсказок](../feature-x/src/main/java/com/client/xvideos/x/screens/search/ScreenXSearchSM.kt#L111), [обработка «Назад»](../feature-x/src/main/java/com/client/xvideos/x/screens/search/ScreenXSearchSM.kt#L295)

### C6 · P3 · XLive теряет ручное обновление статусов, если проверка уже идёт

При активной проверке в очередь сохраняются только имена комнат. При возобновлении вызов теряет `force = true`, поэтому уже известные комнаты фильтруются. Нажатие на активную вкладку «Мои» или «История» в этот момент может оставить старые статусы. Хранить признак ручного обновления вместе с запросом. Подтверждено по формированию очереди и повторному вызову. [Ручное обновление](../feature-xlive/src/main/java/com/client/xvideos/xlive/ui/root/XLiveSM.kt#L216), [очередь проверок](../feature-xlive/src/main/java/com/client/xvideos/xlive/ui/saved/XLiveOnlineCheck.kt#L59)

### C7 · P3 · Настройки N подтверждают сохранение ключа, который действует только до перезапуска

При недоступности защищённого хранилища ключ начинает работать из памяти. Настройки закрывают диалог «Сохранить» и показывают новый ключ как действующий, при следующем запуске он исчезает. Возвращать результат сохранения из хранилища и явно сообщать, если ключ принят только на текущий сеанс. Ожидаемая потеря временного ключа уже покрыта модульным тестом. Отсутствие обратной связи видно в обработчике диалога. [Запись ключа](../core/src/main/java/com/client/xvideos/common/settings/element/NAccessSettings.kt#L22), [тест временного ключа](../core/src/test/java/com/client/xvideos/common/settings/element/NAccessSettingsTest.kt#L34), [кнопка «Сохранить»](../app/src/main/java/com/client/xvideos/screenSettings/section/NSettingsSection.kt#L182)
