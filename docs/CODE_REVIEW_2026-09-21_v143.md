## 1. Контекст и цели прохода

Проведён детальный аудит и устранение проблем с отступами под системный вырез экрана (displayCutout / Edge-to-Edge) и разметкой списков в модулях `:feature-x` и `:feature-r`:

1. **Корректный учёт выреза фронтальной камеры в экране «Сохранённое» раздела X (`ScreenSavedX.kt`)**:
   - Ранее шапка экрана «Сохранённое» (`Row` с заголовком и `HorizontalDivider`) полностью игнорировала верхний вырез (`getTopInsetDp()` / `displayCutout`), из-за чего на устройствах с фронтальной камерой (вырез/«глазок») заголовок накладывался на системные элементы.
   - **Решение**: Вычислен `val topCutout = getTopInsetDp()`. По аналогии с экраном «Избранное» (`ScreenFavorites.kt`):
     - При пустом списке заголовок и заглушка «Пусто» смещены на `topCutout`.
     - При наличии сохранённых роликов заголовок и разделитель оформлены как скроллящийся элемент `item(key = "header")` внутри `LazyColumn` с верхним отступом `topCutout`. В начальном состоянии заголовок гарантированно находится под камерой, а при прокрутке элементы плавно уходят под статус-бар/вырез без визуальных артефактов.

2. **Ликвидация глобального двойного отступа в модуле RedGifs (`R_Screen_Root.kt`)**:
   - В корне раздела R (`R_Screen_Root.kt`) компонент `Scaffold` не сбрасывал системные инсеты (`contentWindowInsets`), по умолчанию применяя инсеты выреза экрана. Вложенный контейнер вызывал `Box(modifier = Modifier.padding(padding))`, передавая `padding.calculateTopPadding()` (равный вырезу экрана) на весь навигатор `ScreenRedExplorer`.
   - В то же время все дочерние экраны раздела R (`R_ScreenGifsTab`, `SearchTab`, `ScreenRedManageBlock`, `SavedCollectionName`, `R_ScreenNichesTab`) самостоятельно рассчитывали и применяли свой отступ выреза (`getTopInsetDp()` или `WindowInsets.displayCutout`), что приводило к **двойному верхнему отступу** во всём разделе R («там везде стоит паддинг к которому мы добавляем свой паддинг, короче их два»).
   - **Решение**:
     - В корневом `Scaffold` раздела R явно задан `contentWindowInsets = WindowInsets(0, 0, 0, 0)`.
     - Вложенный контейнер ограничен отступом только нижней границы индикатора загрузки: `Box(modifier = Modifier.padding(bottom = padding.calculateBottomPadding()))`.
     - Устранены избыточные вложенные отступы `displayCutoutPadding()` и устаревший `systemBarsPadding()` в `RedProfileUserImage.kt` и `ScreenNiche.kt`.

3. **Устранение тёмной полосы и оптимизация `LazyRow123` (`LazyRow123.kt`, `R_Screen_Saved_LikesTab.kt`)**:
   - В табе «Лайки» (`R_Screen_Saved_LikesTab.kt`) была предпринята неудачная попытка добавить отступ через:
     ```kotlin
     contentBeforeList = {
         Box(modifier = Modifier.displayCutoutPadding()){}
     }
     ```
   - В `LazyRow123.kt` строка `item(key = "before", span = { GridItemSpan(maxLineSpan) }) { contentBeforeList() }` безусловно вставляла в грид элемент на всю ширину строки.
   - В результате пустой `Box` занимал отдельную полноширинную строку грида над картинками и отображался как **тёмная пустая полоса**, на которой не выводилось изображение («на первом изображение не выводится, просто темная полоса»).
   - Кроме того, даже когда `contentBeforeList` был пустым (`{}`), `LazyRow123` регистрировал пустой элемент с `key = "before"`, из-за чего требовалось искусственное смещение `scrollToItem(targetIndex + 1)` и искажался расчёт прогресса в `scrollPercent`.
   - **Решение**:
     - В `LazyRow123.kt`: параметр `contentBeforeList` сделан nullable (`null` по умолчанию). Элемент `item(key = "before")` добавляется в грид **только** если `contentBeforeList != null`. Смещение скролла при возврате (`targetIndex + offset`) и `itemsToIgnore` для скроллбара теперь динамически определяются наличием хедера (`if (contentBeforeList != null) 1 else 0`).
     - В `R_Screen_Saved_LikesTab.kt`: удалён пустой `Box`, отступ задан штатно через `contentPadding = PaddingValues(top = getTopInsetDp())`. Первое видео выводится сразу на первой позиции грида без тёмных полос.
     - Во вкладках «Подписки» (`R_Screen_Saved_SubscriptionsTab.kt`), «Авторы» (`R_Screen_CreatorsTab.kt`), «Группы» (`SavedNichesTab.kt`) и «Загрузки» (`R_Screen_Saved_DownloadTab.kt`) добавлены `contentWindowInsets = WindowInsets(0, 0, 0, 0)` и корректные отступы выреза.

4. **Соблюдение архитектурных инвариантов и верификация**:
   - Полная заморозка P2P-модуля (`core/.../p2p/` не затрагивался).
   - 0 предупреждений и ошибок в Detekt (очищены неиспользуемые импорты).
   - 100% прохождение модульных тестов (140 задач Gradle).
   - Успешная сборка полного debug APK (`assembleDebug`).

## 2. Детальный аудит изменений по файлам

### 2.1. Модуль X (`:feature-x`)
- **`feature-x/src/main/java/com/client/xvideos/x/screens/saved/ScreenSavedX.kt`**:
  - Добавлен вызов `getTopInsetDp()` для получения безопасного верхнего отступа.
  - При `list.isEmpty()` контейнер `Column` смещается на `topCutout`.
  - При непустом списке заголовок «Сохранённое» и `HorizontalDivider` помещены в `item(key = "header")` в `LazyColumn` с `padding(top = topCutout)`. Обеспечена плавная прокрутка под статус-бар.

### 2.2. Модуль RedGifs (`:feature-r`)
- **`feature-r/src/main/java/com/client/xvideos/r/ui/root/R_Screen_Root.kt`**:
  - `Scaffold` получил `contentWindowInsets = WindowInsets(0, 0, 0, 0)`.
  - `Box` использует `Modifier.padding(bottom = padding.calculateBottomPadding())`, устраняя паразитный верхний отступ для всех вложенных табов.
- **`feature-r/src/main/java/com/client/xvideos/r/ui/ui/lazyrow123/LazyRow123.kt`**:
  - `contentBeforeList: (@Composable () -> Unit)? = null`.
  - В `LazyRow123ContentStateless` элемент `item(key = "before")` эмитится только при `contentBeforeList != null`.
  - Смещение `state.scrollToItem(targetIndex + offset)` и `itemsToIgnore` динамически используют `1` при наличии хедера и `0` при его отсутствии.
- **`feature-r/src/main/java/com/client/xvideos/r/ui/explorer/tab/saved/tab/R_Screen_Saved_LikesTab.kt`**:
  - Удалён пустой `Box(modifier = Modifier.displayCutoutPadding()){}` из `contentBeforeList`.
  - `LazyRow123` переведён на `contentPadding = PaddingValues(top = getTopInsetDp())`.
  - Удалён неиспользуемый импорт `dp`.
- **`feature-r/src/main/java/com/client/xvideos/r/ui/explorer/tab/saved/tab/R_Screen_Saved_SubscriptionsTab.kt`**:
  - Задан `contentPadding = PaddingValues(top = getTopInsetDp())` в `LazyRow123`, предотвращая обрезку чипов авторов вырезом камеры.
- **`feature-r/src/main/java/com/client/xvideos/r/ui/explorer/tab/saved/tab/R_Screen_CreatorsTab.kt`**:
  - `Scaffold` настроен с `contentWindowInsets = WindowInsets(0, 0, 0, 0)`.
  - Заменена конструкция `windowInsetsTopHeight(...)` в `topBar` на лаконичный `Row` с `padding(top = getTopInsetDp())`.
  - Удалены неиспользуемые импорты (`displayCutout`, `union`, `windowInsetsTopHeight`).
- **`feature-r/src/main/java/com/client/xvideos/r/ui/explorer/tab/saved/tab/savedNiche/SavedNichesTab.kt`**:
  - `Scaffold` настроен с `contentWindowInsets = WindowInsets(0, 0, 0, 0)`.
  - Заголовок `>Группы` обёрнут в `Row` с `padding(top = getTopInsetDp())`.
- **`feature-r/src/main/java/com/client/xvideos/r/ui/explorer/tab/saved/tab/R_Screen_Saved_DownloadTab.kt`**:
  - `Scaffold` настроен с `contentWindowInsets = WindowInsets(0, 0, 0, 0)`.
  - Заголовок `>Загрузки` обёрнут в `Row` с `padding(top = getTopInsetDp())`.
- **`feature-r/src/main/java/com/client/xvideos/r/ui/profile/atom/RedProfileUserImage.kt`**:
  - Удалён лишний `displayCutoutPadding()` из `RedProfileCreaterInfo`, исключая повторный отступ внутри профиля автора.
- **`feature-r/src/main/java/com/client/xvideos/r/ui/niche/ScreenNiche.kt`**:

  - В `NicheHeaderContent` наложение инсетов очищено до единого `.windowInsetsPadding(WindowInsets.displayCutout.only(WindowInsetsSides.Top))`.
