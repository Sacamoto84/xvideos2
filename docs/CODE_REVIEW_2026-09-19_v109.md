# Код-ревью: Итерация 130 (2026-09-19)

**Фокус ревью:** Системный аудит контракта идентичности экранов Voyager (`ScreenKey`), иерархии возвратов «Назад» (`BackHandler`), предотвращения потери состояния экранов при смене конфигурации во всех прикладных модулях (`:feature-r`, `:feature-x`, `:feature-l`).
Подсистемы: экраны видеоплееров X и локального воспроизведения, блокировка авторов RedGifs, таб-навигация и подстраницы RedGifs и Luscious, полноэкранный просмотр изображений L, модульное тестирование Java-сериализации экранов в saved state.

---

## 1. Контекст и цели

1. **[UI59] Унификация навигации «Назад», детерминированный ключ и обработка пустого списка в `ScreenRedManageBlock` (`:feature-r`)**:
   - `ScreenRedManageBlock` использовал `uniqueScreenKey`, генерируя новый UUID при каждом создании, что разрушало сохранность стека Voyager.
   - На экране отсутствовал `BackHandler` и наэкранная кнопка «Назад», а при пустом списке заблокированных отображался пустой чёрный экран.
   - *Решение:*
     - Задать детерминированный ключ `override val key: ScreenKey = "ScreenRedManageBlock"`.
     - Добавить `BackHandler { navigator.pop() }`.
     - Реализовать верхнюю панель `topBar` со стрелкой возврата (`Icons.AutoMirrored.Filled.ArrowBack`) и заголовком «Заблокированные».
     - Добавить центрированную заглушку «Список заблокированных пуст» при `blockList.isEmpty()`.
2. **[UI60] Иерархическая навигация «Назад» и детерминированные ключи табов в `:feature-r`**:
   - В `ScreenExplorer.kt` и `ScreenSaved.kt` при нахождении во вторичных вкладках системный жест «Назад» приводил к выходу из приложения вместо возврата к первой вкладке.
   - В `R_Screen_Root.kt` присутствовал безусловный `BackHandler { Timber.i(...) }`, который перехватывал и глушил жест «Назад».
   - Singleton-экраны и параметризованные экраны (`R_ScreenNiche`, `ScreenRedProfile`, `FavoritesTab`, `ScreenRedFullScreen`, `R_ScreenGifsTab`, `R_ScreenNichesTab`, `R_Screen_Saved_LikesTab`, `R_Screen_CreatorsTab`, `R_Screen_Saved_DownloadTab`, `SavedNichesTab`, `R_Screen_CollectionTab`, `R_Screen_Saved_SubscriptionsTab`) генерировали случайные `uniqueScreenKey`.
   - *Решение:*
     - В `ScreenExplorer` и `ScreenSaved` добавить `BackHandler(enabled = vm.screenType != 0) { vm.screenType = 0 }`.
     - В `R_Screen_Root` перевести `BackHandler` в режим закрытия открытых диалогов (`enabled = isAnyDialogOpen`).
     - В `R_ScreenNiche` добавить `BackHandler { navigator.pop() }`.
     - Заменить все вызовы `uniqueScreenKey` на стабильные детерминированные строковые ключи.
3. **[UI61] Детерминированные ключи и бесшовный BackHandler в видеоплеерах X (`:feature-x`)**:
   - `ScreenX_VideoPlayer`, `ScreenX_LocalVideoPlayer` и `ScreenX_VideoPlayerFullScreen` использовали `uniqueScreenKey`.
   - В `ScreenX_LocalVideoPlayer` обработчик `BackHandler(enabled = isZoomed)` обрабатывал только сброс зума, а при `!isZoomed` жест «Назад» не был связан с `navigator.pop()`.
   - *Решение:*
     - Задать ключи `"ScreenX_VideoPlayer:$url"`, `"ScreenX_LocalVideoPlayer:$fileUrl"` и `"ScreenX_VideoPlayerFullScreen:$url"`.
     - В `ScreenX_LocalVideoPlayer` унифицировать `BackHandler { if (isZoomed) resetZoomTrigger++ else navigator.pop() }`.
4. **[UI62] Детерминированные ключи и возврат в табах Luscious (`:feature-l`)**:
   - `L_ScreenAlbumList`, `ScreenLAlbumList`, `ScreenLAlbumLandingTag`, `L_FullScreenImage`, `L_ScreenExplorer`, `L_SavedTab`, `L_ScreenAlbumSearch`, `L_ScreenAlbumTopHits`, `L_ScreenSavedAlbumsTab`, `L_ScreenSavedLikesTab`, `L_Screen_CollectionTab`, `L_ScreenServerLikesTab`, `L_ScreenSubscribedAlbumsTab` использовали `uniqueScreenKey`.
   - При поиске в `L_ScreenAlbumSearch` жест «Назад» не сбрасывал введенный текст.
   - Во вторичных вкладках `L_ScreenExplorer` и `L_SavedTab` отсутствовал возврат к первой вкладке.
   - *Решение:*
     - Задать стабильные ключи всем экранам.
     - В `L_ScreenAlbumSearch` подключить `BackHandler(enabled = searchText.isNotEmpty()) { vm.searchText.value = "" }`.
     - В `L_ScreenExplorer` и `L_SavedTab` добавить `BackHandler(enabled = vm.screenType != 0) { vm.screenType = 0 }`.
5. **[T60] Модульное тестирование контракта сериализации и ScreenKey**:
   - Разработаны `ScreenRedProfileSerializationTest` (`:feature-r`), `ScreenX_VideoPlayerKeysTest` (`:feature-x`), `ScreenAlbumListSerializationTest` (`:feature-l`), покрывающие Java-сериализацию и проверку стабильных ключей всех обновленных экранов.

## 2. Выявленные замечания и исправления

### [UI59] Экран управления заблокированными авторами ScreenRedManageBlock
- **Проблема:** В [ScreenRedManageBlock.kt](file:///g:/xvideos2/feature-r/src/main/java/com/client/xvideos/r/ui/manager_block/ScreenRedManageBlock.kt) случайный ключ, отсутствие навигации «Назад» и отсутствие индикации при пустом списке.
- **Решение:** Назначен ключ `"ScreenRedManageBlock"`, добавлен `BackHandler`, сверстана верхняя панель с кнопкой возврата и вывод заглушки при пустом списке.
- **Статус:** Исправлено.

### [UI60] Иерархия возвратов и стабильные ключи в RedGifs
- **Проблема:** Недетерминированные ключи экранов Voyager и преждевременный выход из раздела при нажатии «Назад» в табах. Глушение Back в корневом экране.
- **Решение:** Подключены `BackHandler` переключения табов на индекс 0, в `R_Screen_Root` `BackHandler` закрывает открытые диалоги, все 15 экранов и вкладок переведены на детерминированные ключи.
- **Статус:** Исправлено.

### [UI61] Стабильные ключи и навигация в видеоплеерах X
- **Проблема:** Случайные ключи плееров `ScreenX_VideoPlayer`, `ScreenX_LocalVideoPlayer`, `ScreenX_VideoPlayerFullScreen`. В локальном плеере `BackHandler` не закрывал плеер при отсутствии зума.
- **Решение:** Установлены ключи на основе URL роликов. В `ScreenX_LocalVideoPlayer` `BackHandler` сбрасывает зум при масштабировании, либо выходит по стеку навигатора.
- **Статус:** Исправлено.

### [UI62] Стабильные ключи и возврат в табах Luscious
- **Проблема:** Случайные ключи во всех экранах и табах `feature-l`, отсутствие сброса строки поиска по Back в `L_ScreenAlbumSearch`, отсутствие возврата к начальной вкладке в Explorer и Saved.
- **Решение:** Все экраны переведены на детерминированные `ScreenKey`, добавлены `BackHandler` очистки поиска и возврата к первой вкладке.
- **Статус:** Исправлено.

### [T60] Модульное тестирование сохранности экранов Voyager
- **Проблема:** Отсутствие тестов стабильности ключей и Java-сериализации в saved state для обновленных экранов.
- **Решение:** Написаны комплексные unit-тесты `ScreenRedProfileSerializationTest`, `ScreenX_VideoPlayerKeysTest`, `ScreenAlbumListSerializationTest`.
- **Статус:** Исправлено.
