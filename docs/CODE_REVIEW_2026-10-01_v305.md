## Находки

### C1 — Поиск в истории читает диск на главном потоке. Средняя.

[SavedX_History.kt:66](../feature-x/src/main/java/com/client/xvideos/x/feature/saved/SavedX_History.kt:66)

`get` при промахе по кэшу вызывает `historyDb.read()` — синхронное чтение файла
под замком `FileDB`. Вызывается из композиции (`ScreenX_LocalVideoPlayer`,
`remember(videoId) { history.get(...) }`) и из `init` `ScreenX_VideoPlayerSM`.
Если в этот момент `refresh()` читает до 200 файлов истории под тем же замком,
главный поток ждёт его — подвисание, риск ANR.

### C2 — Парсер длительности не знает суффикс «h». Средняя.

[XSite.kt:46](../feature-x/src/main/java/com/client/xvideos/x/XSite.kt:46)

Часы распознаются только как `hr`, `ч`, `hour`. «1 h 5 min» разбирается как
5 минут, «1 h» уходит в запасной разбор цифр и становится 1 минутой. Пока
плеер не сообщил длительность, `saveProgress` берёт её отсюда, и позиция
обрезается по неверной длине.

Чего нет: формат длительности на сайте не проверен на устройстве; тест
покрывает только `hr`.

[ChannelModel.kt:258](../feature-x/src/main/java/com/client/xvideos/x/model/ChannelModel.kt:258)

`ChannelUiState.currentPage`, а `goToPage` меняет только отдельное поле
`ScreenX_ChannelSM.currentPage`. Пейджер упирается в 10 страниц.

## Что осталось открытым

Все находки закрыты в `f07eb47e`.

Решения по ходу исправления:

- R2: слой данных `search` не может импортировать `feature` — это проверяет
  `LayerBoundariesTest`. Сетевой запрос подсказок перенесён в
  `feature/net/getSearchResults.kt`, построители URL остались в
  `search/SuggestUrl.kt`. Общий клиент ставит свои User-Agent и
  Accept-Language через `appendIfNameAbsent`: при совпадении имени Ktor 3.6
  отправил бы оба значения через запятую.
- C1: плеер скачанного файла показывает индикатор загрузки, пока не прочитана
  позиция возобновления; когда запись уже в памяти, это один кадр.
- A1: корневая функция только собирает молекулы, `@Suppress("LongMethod",
  "CyclomaticComplexMethod")` сняты; 27 параметров остались — экран передаёт
  их в молекулы как есть.

Отрицательные результаты:

- Регрессии `53bc3255` не найдены: прежние вызывающие
  `readHtmlFromURLDirect` получают тот же контракт; адреса индекса моделей всегда
  абсолютные, так что `fetchHtml` не отбрасывает их как некорректные; удаление
  загрузки снимает её учёт; записи истории идут последовательно.
- Правило `CLAUDE.md` про `remember` с ключом-`SnapshotStateList` в Compose-коде
  X не нарушено: найденные `remember` держат лямбды, читающие список в момент
  вызова, или ключуются по неизменяемым значениям `StateFlow`.
- Кодирование поискового запроса корректно: `+` → `%20` для пути подсказок,
  параметр `k` кодируется `URLEncoder`.
- Избранное: гонка добавления и удаления через интерфейс не возникает —
  состояние кнопки обновляется только после записи.
- Поиск id видео из ссылки используется только для карточек и плеера, URL-путь
  без карточки не вызывается.
