# Code Review & Optimization Report — Batch 47 (v263)

**Date:** 2026-09-26  
**Passes:** 961 – 968  
**Scope:** Core coroutine exception handling and receiver-based cancellable execution, event bus message classification and subscriber inspection, JSON null-safe parsing extensions, section L picture details media URL & anchor ID helpers, filter genre & content models, and album list filter state calculations.

---

### Pass 961 (`:core` — `runCatchingCancellable.kt`)
- **Finding:** `runCatchingCancellable` was only available as a top-level block function `(() -> T)`, unlike standard Kotlin's `runCatching`, which also provides a receiver-based form (`T.runCatching`).
- **Fix:** Added `inline fun <T, R> T.runCatchingCancellable(block: T.() -> R): Result<R>` to enable scoped receiver execution while preserving coroutine cancellation propagation.

---

### Pass 962 (`:core` — `LaunchCatching.kt`)
- **Finding:** `launchCatching` only logged exceptions without offering callers an easy mechanism to handle or react to caught non-cancellation exceptions (e.g. state reset or user feedback).
- **Fix:** Added optional `onError: (suspend (Exception) -> Unit)? = null` callback parameter.

---

### Pass 963 (`:core` — `Event.kt` & `EventBus.kt`)
- **Finding:** `Event` instances required verbose `is Event.ShowSnackBar` type checks, and callers could not inspect `EventBus` subscriber counts to bypass expensive event assembly when nobody was observing.
- **Fix:** Added `isSnackBar`, `isLog`, `isExitPosition` to `Event`; added `isError`, `isSuccess`, `isInfo`, `isWarning` to `Event.ShowSnackBar`; added `subscriberCount` and `hasSubscribers` to `EventBus`.

---

### Pass 964 (`:core` — `AppJson.kt`)
- **Finding:** Many data layers and repositories wrapped `AppJson.decodeFromString` or `encodeToString` in boilerplate `runCatching { ... }.getOrNull()` blocks with manual null/blank checks.
- **Fix:** Added `inline fun <reified T> Json.decodeFromStringOrNull(string: String?): T?` and `inline fun <reified T> Json.encodeToStringOrNull(value: T): String?`.

---

### Pass 965 (`:feature-l` — `PicsDetailsMedia.kt`)
- **Finding:** Callers handling `PicsDetails` anchor IDs had to repeatedly check `extractAnchorId() != null` or fallback to empty strings. Image URL validation lacked a dedicated extension.
- **Fix:** Added `String.isLImageFileUrl(): Boolean`, `PicsDetails.hasAnchorId: Boolean`, and `PicsDetails.extractAnchorIdOrEmpty(): String`.

---

### Pass 966 (`:feature-l` — `FilterGenre.kt`)
- **Finding:** `FilterGenre` and `OnlyContent` models lacked standard presence inspection properties for optional metadata (posters, descriptions, parent categories, URLs).
- **Fix:** Added `hasPoster`, `hasDescription`, `hasParent` to `FilterGenre`, and `hasUrl` to `OnlyContent`.

---

### Pass 967 (`:feature-l` — `SavedAlbumFilter.kt`)
- **Finding:** `SavedAlbumFilter` lacked direct emptiness checks and a way to verify if non-default filter settings were contained.
- **Fix:** Added `isEmpty`, `isNotEmpty`, and `hasFilter` (`filter != AlbumListFilter.DEFAULT`).

---

### Pass 968 (`:feature-l` — `AlbumListFilter.kt`)
- **Finding:** `AlbumListFilter` had no properties to check whether animation selection was active (`selection == "animated"`) or calculate the aggregate count of applied filters for badges.
- **Fix:** Added `hasSelection`, `isAnimatedOnly`, and `totalFilterCount` computed properties.
