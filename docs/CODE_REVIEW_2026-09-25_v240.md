## Summary of Passes (777–784)

### Pass 777 — `:feature-l` (`PicsDetailsMedia.kt`)
- **Finding:** `lMediaRequestHeaders()` and `lMediaDownloadHeaders()` constructed new `Map` and `HashMap` instances, iterating and creating entry wrappers on every media playback and image fetch request. Furthermore, `extractAnchorId()` concatenated 4 lists (`listOfNotNull(...) + thumbnails.orEmpty().mapNotNull(...)`) to run regex search.
- **Fix:** Precomputed `L_MEDIA_REQUEST_HEADERS: Map<String, String>` and `L_MEDIA_DOWNLOAD_HEADERS: HashMap<String, List<String>>` as top-level constants and returned cached/reusable structures. Rewrote `extractAnchorId()` to inspect candidate URLs sequentially without allocating intermediate collections.

### Pass 778 — `:feature-l` (`PicsDetailsMedia.kt`)
- **Finding:** In `PicsDetails.lFullScreenImageUrls()`, `(listOfNotNull(localOriginal) + thumbnails + listOfNotNull(fallbackOriginal)).distinct()` created 4 intermediate lists and a `LinkedHashSet` (5 collection allocations per full-screen image transition).
- **Fix:** Replaced with a single pre-sized `ArrayList<String>(thumbnails.size + 2)` populating unique elements without temporary collections or set allocations.

### Pass 779 — `:feature-l` (`Luscious.kt`)
- **Finding:** In `extractIdFromUrl(url: String)`, regular expression matching was executed on all input strings unconditionally, including raw numeric IDs and non-album URLs.
- **Fix:** Added `if (!trimmed.contains("albums/")) return null`, fast-pathing plain numeric strings and non-album URLs without invoking the regex matcher engine.

### Pass 780 — `:feature-r` (`R_Saved_Creator.kt`)
- **Finding:** In `add(item: UserInfo)`, the item was removed and re-added even if it was already the latest entry in `list`, triggering redundant list mutation notifications to observers. In `updateIfSaved(item: UserInfo)`, `list.indexOfFirst` was evaluated again from scratch on success.
- **Fix:** Added an early return check in `add` when the item is already the last element and identical, and reused the precomputed index in `updateIfSaved` when position has not changed.

### Pass 781 — `:feature-r` (`R_Saved_Niches.kt`)
- **Finding:** In `add(item: NichesInfo)`, adding an already active niche removed and re-added the item at `list.lastIndex`, causing unnecessary Compose list recompositions.
- **Fix:** Added a guard `if (existingIndex == list.lastIndex && list[existingIndex] == item) return@withContext`.

### Pass 782 — `:feature-r` (`R_Saved_Likes.kt`)
- **Finding:** In `add(item: GifsInfo)`, likes already at the top/end position were removed and appended again, dispatching redundant change events.
- **Fix:** Added a guard `if (existingIndex == list.lastIndex && list[existingIndex] == safeItem) return@withContext`.

### Pass 783 — `:core` (`SettingElementString.kt`, `SettingElementBoolean.kt`, `SettingElementInt.kt`)
- **Finding:** Calling `setValue(value)` unconditionally initiated `sharedPrefs.edit { ... }` disk writes, lock acquisitions, and `OnSharedPreferenceChangeListener` dispatches, even when the value had not changed.
- **Fix:** Added `if (_field.value == value && sharedPrefs.contains(name)) return` in all three primitive setting elements, completely eliminating disk writes and redundant StateFlow notifications when the setting is unchanged.

### Pass 784 — `:feature-r` (`R_SearchExplorer.kt` & `ISearchTemplate.kt`)
- **Finding:** In `R_SearchExplorer.suggestionsFor()`, `redApi.getTagSuggestions(request).map { list -> list.map { ... } }` allocated an empty `ArrayList` when results were empty and dynamically resized when non-empty. In `ISearchTemplate`, `trimmed.isNotBlank()` performed a redundant character scan after `trim()`.
- **Fix:** Returned `emptyList()` immediately when `list.isEmpty()` and pre-sized `ArrayList<SuggestionItem>(list.size)` in `R_SearchExplorer`. Replaced `trimmed.isNotBlank()` with `trimmed.isNotEmpty()` in `ISearchTemplate`.
