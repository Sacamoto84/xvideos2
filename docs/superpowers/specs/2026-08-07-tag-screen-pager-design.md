# Постраничность на экране тега X

Составлено 07.08.2026. Согласовано с владельцем.

## Задача

Экран тега показывает одну страницу выдачи и не даёт перейти к остальным.
Нужен тот же способ хождения по страницам, что в ленте раздела: свайп
`HorizontalPager` плюс ряд номеров внизу.

## Что уже есть

**Лента раздела** (`ScreenXDashBoards`) — образец. `HorizontalPager` со
`PagerState(0) { 20000 }`; каждая страница пейджера — свой
`DashboardsPaginatedListScreen(pageIndex)`, который грузит себя сам в
`LaunchedEffect(pageIndex)`. Внизу `DashboardControlsRow` = кнопка страны плюс
`BottomListDashBoardNavigationButtons2(value, onChange, max)`.

**Экран тега** (`ScreenTags`) — `ScreenTagsViewModel` забирает `/tags/<тег>`,
`parserScreenTags` разбирает заголовок, счётчик и элементы. Список элементов
проведён в `TagsPaginatedListScreen` (правка `1a7dc88`), постраничности нет.

**Ряд номеров** — `List(max) { it + 1 }` в `LazyRow`, значение 0-based, метки
1-based, прокрутка к текущему номеру. Большое `max` переваривает: список
ленивый.

## Что отдаёт сайт

Страницы адресуются `/tags/<тег>/N`, где N считается с нуля; `/tags/<тег>` и
`/tags/<тег>/0` — одна и та же страница.

Число страниц лежит в блоке `div.pagination`. Последняя помечена классом:

```html
<li><a href="/tags/public/148" class="last-page">149</a></li>
```

То есть максимум известен точно, подбирать вслепую не нужно. Для `public` —
149 страниц.

## Решение

Зеркалим ленту раздела. Совпадение с соседним экраном важнее одного лишнего
запроса.

### Разбор

`parserScreenTags` дополнительно достаёт число страниц:

1. `div.pagination a.last-page` — текст ссылки и есть число страниц;
2. если класса нет (страниц мало) — наибольшая числовая метка среди ссылок
   блока;
3. блока нет вовсе — одна страница.

`ModelScreenTag` получает поле `lastPage: Int` со значением по умолчанию `1`.

### ViewModel

`ScreenTagsViewModel` продолжает грузить нулевую страницу в `init` — с неё
берутся заголовок, счётчик и `lastPage`. Добавляется
`suspend fun loadPage(index: Int): List<ItemsX>`, которая забирает
`/tags/<тег>/<index>` и возвращает разобранные элементы.

Нулевая страница при открытии запрашивается дважды: разово ради заголовка и
числа страниц, затем ребёнком пейджера. Принято сознательно: убирать это
кэшем в сетевом слое, если понадобится, отдельной задачей.

### Экран

`Scaffold`:

- сверху — тег и счётчик результатов, как сейчас;
- в теле — `HorizontalPager(pageCount = lastPage)`, каждая страница
  `TagsPaginatedListScreen(pageIndex, loadPage, onOpenVideo)`;
- снизу — `BottomListDashBoardNavigationButtons2` без кнопки страны: адрес
  `/tags/<тег>/N` от страны не зависит.

Ряд и пейджер связаны в обе стороны: свайп двигает подсветку номера, тап по
номеру вызывает `animateScrollToPage`.

Пока `lastPage` не известен (первая загрузка) пейджер держит одну страницу.

### Правка компонента

В `BottomListDashBoardNavigationButtons2` список номеров собран как
`remember { List(max) { it + 1 } }` — без ключа. Число страниц становится
известно только после первой загрузки, то есть `max` меняется с `1` на `149`,
а ряд остаётся с одной кнопкой навсегда. Нужен `remember(max)`.

Затрагивает и ленту раздела, но там `max` задан константой и не меняется —
поведение прежнее.

### Тесты

На `parserScreenTags`, фикстуры — сокращённая настоящая разметка со страницы
`/tags/public`, а не выдуманная:

- блок `pagination` с `a.last-page` даёт 149;
- блок без `a.last-page` даёт наибольшую метку;
- страницы без блока — 1;
- разбор элементов и заголовка не сломан.

## Границы

Не делаем: бесконечную прокрутку, кэш страниц во ViewModel, фильтры качества
(`/tags/q:hd/<тег>`), сохранение выбранной страницы между открытиями экрана.
