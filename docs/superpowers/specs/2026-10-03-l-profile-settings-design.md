# Профиль L в настройках: вход и выход

Дата: 2026-10-03  
Статус: дизайн утверждён  

---

## 1. Контекст и постановка проблемы

Страница L в настройках начинается строкой «Профиль L»
(`app/.../screenSettings/section/LSettingsSection.kt`). У неё три дефекта.

1. **Кнопка не соответствует действию.** Текст кнопки — «Нет», если логин пуст, и
   «Выйти», если задан. Диалог по нажатию один и тот же: «Выйти из профиля L».
   Без аккаунта он сообщает «Вы не авторизованы в L.», а подтверждение стирает
   пустые поля и показывает «Профиль L закрыт».
2. **Войти из настроек нельзя.** Форма входа показывается только при открытии
   раздела L (`feature-l/.../ui/screens/explorer/L_ScreenExplorer.kt`), пока
   логин или пароль пусты. После «Пропустить» она недоступна до перезапуска
   приложения: признак `LSession.loginSkipped` живёт в памяти процесса.
3. **«Выйти» не завершает сессию.** Настройки стирают только сохранённые логин и
   пароль. `Repository.ensureAuthenticated()` пустой профиль пропускает, клиент
   остаётся вошедшим (`handler.loggedIn == true`), и запросы до перезапуска
   процесса уходят от имени прежнего пользователя; RAM-кэш с его ответами не
   очищается. Метод `Repository.logout()`, который всё это делает, в боевом коде
   не вызывается — только в тесте. Установлено чтением кода, на устройстве не
   воспроизводилось.

### Целевое поведение

1. Строка «Профиль L» показывает состояние и предлагает действие, которое ему
   соответствует: без аккаунта — «Войти», с аккаунтом — «Выйти».
2. «Войти» открывает ту же форму логина и пароля, что и раздел L, прямо из
   настроек — в том числе после «Пропустить».
3. «Выйти» спрашивает подтверждение и завершает сессию без перезапуска
   приложения: следующий запрос L уходит анонимно.

## 2. Решения

| Решение | Альтернативы | Обоснование |
|---|---|---|
| **Кнопка по состоянию: «Войти» / «Выйти»** | Только статус без кнопки; строка-переход на экран аккаунта | Выбор владельца. Убирает нелогичность и даёт вход из настроек без нового экрана аккаунта. |
| **Форма входа — Voyager-экран `L_ScreenLogin` на существующей форме** | Диалог с полями в настройках; сброс «Пропустить» и переход в раздел L | Выбор владельца. Форма одна на оба входа, автозаполнение паролей уже работает; пользователь возвращается на страницу L настроек. |
| **Тело формы — молекула `LLoginForm`** | Оставить тело в файле экрана | Правило 2 GEMINI.md: в файле экрана лежит класс экрана и сборка молекул. Сейчас в `L_ScreenLogin.kt` класса экрана нет, поэтому правило не срабатывало. |
| **Сессию сбрасывает репозиторий, увидев пустой профиль** | Настройки вызывают `Repository.logout()` | Сохранённые логин и пароль — единственный источник истины. Вызов из настроек требует корутины: `logout()` ждёт два мьютекса, уход с экрана отменил бы выход на полпути. Сброс в репозитории срабатывает при любом способе очистки профиля. |
| **`Repository.logout()` удаляется** | Оставить рядом с новым путём | Боевых вызовов нет. Его тест проверял путь, которого в приложении нет, поэтому очистка RAM-кэша при выходе (исправление C1, проход 175) в приложении не срабатывала. |
| **Пустой профиль сбрасывает и память о неудачном входе** | Сбрасывать только сессию вошедшего | Иначе «выйти и войти теми же данными» после отказа сервера не делает новой попытки до перезапуска и ничего не сообщает. |

## 3. Дизайн

### 3.1. Строка «Профиль L»

Новая молекула `app/.../screenSettings/molecule/LProfileRow.kt`:

```kotlin
@Composable
internal fun LProfileRow(
    login: String,
    hasAccount: Boolean,
    onLogin: () -> Unit,
    onLogout: () -> Unit,
)
```

| Состояние | Подзаголовок | Кнопка | Нажатие |
|---|---|---|---|
| `hasAccount == false` | «Вход не выполнен» | «Войти» | `onLogin()`, диалога нет |
| `hasAccount == true` | `login` | «Выйти» | диалог подтверждения |

- Строка — `SettingsListItem` со значком L, заголовком «Профиль L»,
  подзаголовком и кнопкой `TextButton` в `trailing`.
- Диалог — существующий `DialogButton`: заголовок «Выйти из профиля L?», текст
  «Логин и пароль {login} будут удалены с устройства. L продолжит работать без
  авторизации.», кнопка «Выйти» (деструктивная), «Отмена». Подтверждение
  вызывает `onLogout()`.
- Видимость диалога — локальное состояние молекулы.
- Два превью: без аккаунта и с аккаунтом.

`hasAccount` — логин **и** пароль непустые. Это то же правило, по которому
раздел L показывает форму входа и по которому `UserProfile.isValid` разрешает
вход. Сейчас настройки смотрят только на логин. Если сохранён один логин,
строка показывает «Вход не выполнен» и «Войти», форма откроется с этим логином.

`LSettingsSection` получает `lLogin`, `hasLAccount`, `onLogin` и заменяет
`SettingsButtonRowWithDialog` на `LProfileRow`. Выход остаётся в секции:
стирает `Settings.l_login` и `Settings.l_pass`, показывает снэкбар «Вы вышли из
профиля L».

### 3.2. Экран входа

`feature-l/.../ui/screens/L_ScreenLogin.kt` сейчас содержит только
Composable-функцию `LLoginContent`. После изменения:

- **`feature-l/.../ui/screens/molecule/LLoginForm.kt`** — форма. Тело
  `LLoginContent` переносится без изменений, кроме одного: `onSkip` становится
  `(() -> Unit)?`, при `null` кнопка «Пропустить» не рисуется. Превью — с
  «Пропустить» и без.
- **`feature-l/.../ui/screens/L_ScreenLogin.kt`** — `class L_ScreenLogin : Screen`
  без параметров. `Content()` вызывает `LLoginForm`: начальные логин и пароль —
  сохранённые, прочитанные один раз при открытии; `onSaved` и `onBack` —
  `navigator.pop()`; `onSkip = null`.
- **`L_ScreenExplorer`** вызывает `LLoginForm` вместо `LLoginContent` с прежними
  аргументами, включая `onSkip`. Поведение входа в раздел L не меняется.

Поведение формы прежнее: «Сохранить» требует непустые логин и пароль, пишет их
в настройки, подтверждает автозаполнение, показывает «Авторизация L сохранена».
Проверки логина и пароля на сервере в этот момент нет — см. раздел 5.

Строка `LongMethod` для `LLoginContent` в `config/detekt/baseline.xml` после
переноса ничему не соответствует и удаляется; `@Suppress("LongMethod")` на
функции остаётся.

### 3.3. Сброс сессии в репозитории

`feature-l/.../repository/Repository.kt`, `ensureAuthenticated()`, под
`authMutex`:

- профиль действителен и вход разрешён → `logInIfNeeded(profile)`, как сейчас;
- профиль недействителен (`!profile.isValid`: логин или пароль пуст) →
  `dropSession()`.

Дальше «пустой профиль» означает именно это.

`dropSession()` (приватный, вызывается под `authMutex`):

1. Сбрасывает память о неудачном входе: `anonymousFallbackFor = null`,
   `loginRetryAtMs = Long.MAX_VALUE`.
2. Если клиент не вошедший — на этом всё: запросы уже анонимные, RAM-кэш
   содержит анонимные ответы.
3. Если вошедший — под `requestMutex` создаёт новый обработчик, закрывает
   старый, очищает RAM-кэш; затем сбрасывает состояние антибот-защиты.

Порядок мьютексов `authMutex` → `requestMutex` тот же, что в нынешнем
`logout()`; обратного порядка в классе нет. Закрытие клиента под `requestMutex`
не приходится на середину идущего запроса — гарантия, ради которой `logout()`
работал под обоими мьютексами, сохраняется.

`logout()` удаляется: его тело переходит в `dropSession()`, запись в
`Settings` из репозитория уходит.

Вход после сохранения профиля работает без изменений: следующий запрос видит
действительный профиль, выполняет вход и при успехе очищает RAM-кэш.

### 3.4. Проводка в настройках

- `AppSettingsScreen.Content()` создаёт `onOpenLLogin = { navigator.push(L_ScreenLogin()) }`.
- `AppSettingsScreenContent` получает параметр `onOpenLLogin: () -> Unit = {}`.
  Значение по умолчанию нужно из-за порога detekt: у функции одиннадцать
  параметров без значений по умолчанию при пороге двенадцать, а параметры со
  значением по умолчанию не считаются (`ignoreDefaultParameters: true`).
- `SettingsDetailParams` получает поле `onOpenLLogin: () -> Unit = {}`; три
  места, где параметры собираются для превью, не меняются.
- `SettingsDetailPage` дополнительно подписывается на `Settings.l_pass`,
  вычисляет `hasLAccount` и передаёт в `LSettingsSection` логин, признак и
  колбэк. Сам пароль ниже `SettingsDetailPage` не передаётся.

Страница настроек после возврата с экрана входа остаётся страницей L: текущая
страница хранится через `rememberSaveable`.

## 4. Проверка

### 4.1. Юнит-тесты (`feature-l`, JVM)

В `RepositoryNetworkFailureTest`, сначала падающий тест, потом правка:

1. **После очистки логина и пароля запросы идут анонимно.** Вход, запрос от
   вошедшего (POST), профиль очищается, следующий запрос — GET на анонимный
   адрес, новых обращений ко входу нет. Сейчас падает: второй запрос уходит POST.
2. **После выхода ответ вошедшего запрашивается заново** — существующий тест,
   из которого убирается вызов `logout()`: остаётся только очистка профиля.
3. **После выхода и ввода тех же данных вход пробуют снова.** Сервер отвергает
   логин и пароль, профиль очищается и задаётся тот же — обращений ко входу два.
   Сейчас падает: обращение одно.

Архитектурные тесты (`ScreenSerializationTest`, `GlobalStateTest`) должны
остаться зелёными: у нового экрана нет полей, глобального состояния не
добавляется.

Перед коммитом — `gradlew.bat testDebugUnitTest detekt`; в отчёт идёт
фактический результат.

### 4.2. Превью

`LProfileRow` (оба состояния), `LLoginForm` (с «Пропустить» и без),
`LSettingsSection`.

### 4.3. На устройстве

1. Без аккаунта: строка «Вход не выполнен» + «Войти»; «Войти» открывает форму
   без «Пропустить»; «Назад» возвращает на страницу L настроек.
2. Вход в раздел L без аккаунта: форма с «Пропустить», как раньше.
3. С аккаунтом: строка с логином + «Выйти»; «Выйти» открывает диалог; «Отмена»
   ничего не меняет; подтверждение переводит строку в «Вход не выполнен».
4. После выхода, без перезапуска: списки L соответствуют анонимному режиму.

Сценарии 3 и 4 требуют настоящего аккаунта — логин и пароль вводит владелец.

---

## 5. Вне объёма

- Проверка логина и пароля на сервере в момент «Сохранить». Как и сейчас, вход
  выполняет первый запрос L; при отказе — снэкбар, работа продолжается анонимно.
- Статус живой сессии в строке (вошёл / вход не удался). Строка показывает,
  что логин и пароль сохранены, а не что сервер их принял.
- Смена пароля без выхода.
- Постоянный ROM-кэш при выходе не очищается — как и сейчас.
- Признак `LSession.loginSkipped` не меняется.
