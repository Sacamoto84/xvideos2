# Код уничтожения — дизайн

Дата: 2026-10-28. Статус: черновик, ждёт одобрения владельца.

## Зачем

Владельца могут заставить открыть приложение. Вместо кода доступа он вводит
код уничтожения. Человек рядом видит обычный вход в приложение, только пустое:
данных нет. Всё, что приложение хранило, стёрто безвозвратно.

Успех — человек рядом не может понять, что код был особенный: ни по экрану, ни
по времени, ни по настройкам после входа.

## Цели

- В «Настройки → Приватность» задаётся код уничтожения, отличный от кода
  доступа.
- Ввод его на экране замка (форма кода или «=» в калькуляторе маскировки)
  стирает данные приложения и открывает пустое приложение.
- Снаружи это неотличимо от обычной разблокировки: нет надписей, прогресса,
  вибрации, лишних пауз, повторного экрана замка.
- После срабатывания приложение выглядит как свежая установка с включённым
  замком. Код уничтожения становится обычным кодом доступа: тот же код
  откроет то же пустое приложение и в следующий раз.

## Не цели

- Стирание после N неверных попыток.
- Фальшивые данные-приманки.
- Удалённое стирание.
- Файлы вне памяти приложения: сохранённое «В галерею» (`Movies/`,
  `Pictures/`) **не трогается** — решение владельца. Архивы резервных копий,
  сохранённые в выбранную папку, и пароль L в менеджере паролей Google
  приложению недоступны.
- Защита от криминалистического восстановления флеш-памяти: удаление
  файлов средствами системы, без перезаписи.

## Анти-цели (провал, даже если «работает»)

- Любой видимый признак срабатывания: экран «удаление…», заметная задержка,
  второй экран замка после ввода, всплывающее сообщение, вибрация,
  возврат на экран, где был владелец, с его данными.
- Данные, которые можно увидеть в приложении после срабатывания — хотя бы на
  один кадр, хотя бы из памяти процесса (открытые экраны, кеш картинок).
- Уведомления приложения с прежним содержимым, оставшиеся в шторке.
- Новая дыра в замке: способ снаружи (intent, adb, перезапуск) попасть в
  приложение без кода.
- Частично стёртые данные после того, как процесс убили посреди стирания.

## Ограничения

- Названия сайтов не пишутся нигде (код, логи, тексты): только X / L / R /
  XLive.
- Экраны Compose — по правилам атомарной вёрстки из `GEMINI.md`, ряд выбора —
  `ChoiceRow`, ширина — адаптивные функции `core/.../common/ui/adaptive/`.
- Гейт перед коммитом — `gradlew.bat testDebugUnitTest detekt :app:lintRelease`.
- `minSdk 29`, телефон владельца — Android 16 (HyperOS).
- `android:allowBackup="false"`: облачной копии данных нет, о ней заботиться
  не нужно.

## Поведение

### Настройка кода уничтожения

- Строка «Код уничтожения» в «Приватность», под «Код доступа». Видна, только
  когда замок включён. Состояния: «Не задан» / «Задан»; действия — задать,
  изменить, убрать.
- Задаётся так же, как код доступа: тот же диалог с повтором, та же
  минимальная длина. Совпадение с кодом доступа отвергается. Смена кода
  доступа на значение, равное коду уничтожения, тоже отвергается.
- Хранится как код доступа: соль и хеш PBKDF2 в `AppLockSecureStore`, сам код
  нигде не лежит.
- Выключение замка удаляет и код уничтожения. *(Моё решение.)*

### Где код срабатывает

- Только на экране замка (`LockActivity`): форма кода и «=» калькулятора.
- В диалогах настроек, которые просят код (смена кода, проверка перед
  маскировкой), код уничтожения — просто неверный код. *(Моё решение.)*
- При активной блокировке ввода после неверных попыток код уничтожения
  отвергается так же, как любой другой. Срабатывание сбрасывает счётчик
  попыток, как верный код.
- Проверка тратит одинаковое время на любой код: оба хеша считаются всегда,
  какой бы код ни совпал. *(Моё решение.)*

### Срабатывание

1. Экран замка выглядит как при обычной проверке кода: та же форма, без новых
   элементов.
2. Данные отрезаются от приложения сразу и надёжно: сначала на диск ложится
   отметка «идёт стирание», затем данные делаются недоступными. С этого
   момента никакой код приложения их не прочитает.
3. Код доступа заменяется кодом уничтожения, код уничтожения удаляется,
   счётчики попыток сбрасываются.
4. Настройки сбрасываются к значениям свежей установки, кроме сохраняемых
   (ниже).
5. Уведомления приложения снимаются все.
6. Процесс перезапускается: прежние экраны, загрузки, запись XLive, P2P,
   кеши в памяти исчезают вместе с ним. Новый процесс открывает главный экран
   **без экрана замка** — сеанс считается открытым, ведь «код введён верно».
7. Физическое удаление файлов может продолжаться в фоне нового процесса.
   Если процесс убит посреди стирания, следующий запуск доделывает его
   раньше, чем что-либо прочитает данные.
8. Если шаг 2 не удался (ошибка файловой системы), приложение с данными не
   открывается ни при каких условиях: стирание повторяется, а если и повтор
   не удался — экран замка отвечает «Неверный код доступа», как на любой
   неверный код. Отметка «идёт стирание» остаётся, и следующий запуск
   продолжает. *(Моё решение: лучше подозрительный отказ, чем данные на
   экране.)*

### Что стирается

Всё в частной памяти приложения, кроме сохраняемого. Это **список
сохраняемого**, а не список удаляемого *(моё решение)*: новые хранилища,
которые появятся позже, будут стираться без правки этой функции. Сейчас это:

- `filesDir` целиком (хранилище `store` с данными X / L / R / XLive и P2P,
  кеш niches R);
- `cacheDir` (кеш картинок, HTTP, видео, временные файлы шаринга и P2P);
- `databases` (очередь загрузок);
- `shared_prefs`, кроме хранилища замка и сохраняемых настроек;
- зашифрованное хранилище учётных данных (`SecureCredentialStore`: вход L и
  прочее);
- cookies сессий X и XLive, данные WebView (`app_webview` и прочие `app_*`);
- `no_backup`, внешние папки приложения (`getExternalFilesDir`,
  `externalCacheDir`), если существуют;
- отодвинутая копия данных оборванного восстановления бэкапа, если она есть.

### Что сохраняется

- Хранилище замка: замок включён, код доступа = бывший код уничтожения.
- Настройки: `app_lock_enabled`, `app_lock_timeout_seconds`,
  `camouflage_calculator_enabled` (значок на рабочем столе не меняется),
  `blur_recent_tasks`, `keyboard_incognito_enabled`.
- Сама программа, её значок и активный псевдоним лаунчера.
- Галерея.

### После срабатывания

- Главный экран как после первого запуска; разделы пустые, входы в аккаунты
  сброшены, первые подсказки (например, предложение войти в L) появляются как
  на свежей установке.
- «Приватность»: замок включён, срок автоблокировки прежний, «Код
  уничтожения — не задан». Строка не прячется: она есть в любой установке.
- Следующий вход — по бывшему коду уничтожения. Прежний код доступа больше не
  подходит.

## Решения владельца

- Сценарий — принуждение: человек рядом должен увидеть обычное пустое
  приложение.
- Код уничтожения становится обычным кодом; замок остаётся.
- Удаление выглядит мгновенным, физически доделывается в фоне и после
  перезапуска.
- Код задаётся в «Приватность», отличается от кода доступа.
- После срабатывания строка настройки не выдаёт, что функция была.
- Галерею не трогать.
- Настройки сбросить, кроме замка, срока, маскировки, «Защиты в диспетчере
  задач», инкогнито-клавиатуры.
- Открывается главный экран, а не прежний; заставка допустима, как при
  обычном запуске.
- Код уничтожения считается верным кодом для счётчика попыток.

## Оставлено исполнителю

- Как сделать данные недоступными мгновенно (переименование каталогов в
  корзину, порядок шагов, место отметки «идёт стирание») — при соблюдении
  требований к прерыванию и к первому кадру.
- Как передать новому процессу «сеанс открыт» без экрана замка. Обязательно:
  механизм одноразовый, живёт секунды, не включается ничем снаружи
  (`SplashActivity` экспортирована) и не срабатывает повторно после
  перезагрузки телефона или повторного запуска.
- Как перезапустить процесс так, чтобы это выглядело обычным открытием.
- Где в `App.onCreate` доделывать оборванное стирание, учитывая, что
  Hilt-синглтоны читают пути в конструкторе.
- Раскладка строки и диалога в настройках — по существующему образцу «Код
  доступа».

## Проверка

- Юнит-тесты: выбор «код доступа / код уничтожения / неверный»; отказ при
  совпадении кодов в обе стороны; список сохраняемого (что остаётся, что
  уходит); доделывание оборванного стирания; одноразовость и срок пропуска
  экрана замка.
- Эмулятор (Android 16), без контента на скриншотах: задать коды, наполнить
  данные; сработать через форму и через калькулятор; листинг частной памяти
  через `run-as` до и после; повторный вход бывшим кодом уничтожения, отказ
  прежнего кода; галерея на месте; уведомлений нет; убить процесс посреди
  стирания — следующий запуск доделывает; запуск `SplashActivity` извне после
  срабатывания показывает замок.
- Время от нажатия «Разблокировать» до главного экрана — не заметно дольше
  обычной разблокировки с холодным запуском; замерить на эмуляторе.
- P2P на устройстве не проверяется (правило `CLAUDE.md`).
