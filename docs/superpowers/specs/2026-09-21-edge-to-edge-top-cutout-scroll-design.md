# Edge-to-edge: автоматическая адаптация под вырез камеры (Display Cutout) и скролл контента

Дата: 2026-09-21  
Статус: дизайн утверждён  

---

## 1. Контекст и постановка проблемы

Приложение работает в режиме **Edge-to-Edge** (`enableEdgeToEdge`, `layoutInDisplayCutoutMode = SHORT_EDGES`) с полностью скрытым системным статус-баром (`hide(WindowInsetsCompat.Type.statusBars())`).

На смартфонах без выреза фронтальной камеры (например, Samsung Galaxy S7) интерфейс отображался корректно от самого верхнего края экрана. Однако на подавляющем большинстве современных устройств с вырезами (отверстие камеры punch-hole, капля, «челка») контент при открытии экранов перекрывается камерой.

При этом статичный отступ на весь экран (`Modifier.displayCutoutPadding()`) отрезает верхнюю область дисплея черной полосой и ломает бесшовный скролл.

### Целевое поведение
1. **При открытии экрана:** Верхние элементы (карточки сетки, заголовки, фильтры) начинаются строго ниже выреза камеры.
2. **При скролле («слайдинг экрана»):** Контент плавно прокручивается через верхнюю зону экрана (зону выреза/бывшего статус-бара), заполняя весь физический дисплей.
3. **Заголовки экранов:** Скроллятся наверх вместе со списками.
4. **Кнопки «Назад» в заголовках:** Удаляются (навигация в Android осуществляется системными кнопками или жестами), за исключением экранов коллекций, где они временно сохраняются.
5. **Настройки:** Ручной тумблер `Settings.useCutoutPadding` полностью удаляется — поведение работает автоматически на всех устройствах.

## 2. Understanding Summary (Фиксация требований)

- **Что создается:** Автоматическая система распределения отступов для скролла под вырез камеры (`displayCutout`).
- **Зачем существует:** Устранить наложение объектива фронтальной камеры на заголовки и верхние карточки при сохранении полноэкранного скролла Edge-to-Edge.
- **Для кого:** Для пользователей современных Android-устройств с вырезами камеры, с нулевым оверхедом для устройств без вырезов.
- **Ключевые ограничения:**
  - Системный статус-бар остаётся скрытым.
  - На устройствах без выреза инсет строго равен `0.dp` (без пустых зазоров).
  - В коллекциях кнопка «Назад» временно остаётся.
- **Явные не-цели:** Не использовать сложные нестабильные nested-scroll коллапсинг-бары Material 3; не создавать глобальных глухих черных плашек.

## 3. Assumptions (Принятые допущения)

1. **Определение высоты выреза:** Высота выреза считывается реактивно через `WindowInsets.displayCutout.asPaddingValues().calculateTopPadding()`.
2. **Нулевой инсет:** Если у устройства нет выреза камеры (API < 28 или физически прямоугольный дисплей без выреза), инсет возвращает `0.dp`.
3. **Производительность:** Расчет высоты выреза безопасен для рекомпозиции и передается как стандартный параметр отступа `contentPadding`.
4. **Альбомная ориентация (Landscape):** В альбомном режиме вертикальный верхний отступ равен 0, боковые вырезы обрабатываются стандартным образом.

## 4. Decision Log (Журнал решений)

| Решение | Рассмотренные альтернативы | Обоснование |
|---|---|---|
| **Идиоматичный `contentPadding` + `item`-заголовки** | Material 3 `enterAlwaysScrollBehavior`; кастомный Layout Modifier | M3 nestedScroll конфликтует с горизонтальными пейджерами и кастомными скроллбарами. Вариант через `contentPadding` и первый элемент списка — стабильный, надежный и чистый. |
| **Удаление кнопок «Назад» в заголовках** (кроме коллекций) | Сохранение кнопки; плавающая кнопка | В Android навигация назад осуществляется системными кнопками или свайп-жестами. Дублирующие кнопки захламляют экран. |
| **Скроллящийся заголовок вместе с контентом** | Фиксированный заголовок | Освобождает полезную площадь экрана при просмотре списков. |
| **Удаление тумблера `useCutoutPadding` из настроек** | Сохранение тумблера | Наличие или отсутствие выреза — объективный аппаратный факт. Система сама знает высоту выреза, пользовательская ручная настройка не нужна. |

## 5. Детальный дизайн реализации

### 5.1. Утилита выреза инсета (`core/.../getTopInsetDp.kt`)
Упрощается до прямого возврата верхнего инсета без проверок `Settings`:

```kotlin
@Composable
fun getTopCutoutInsetDp(): Dp {
    return WindowInsets.displayCutout.asPaddingValues().calculateTopPadding()
}
```

### 5.2. Удаление устаревшей настройки выреза
1. `Settings.kt`: удаляется поле `useCutoutPadding`.
2. `DisplaySettingsSection.kt`: удаляется переключатель выреза. Если в секции больше нет других настроек, удаляется подключение секции в `AppSettingsScreen.kt`.

### 5.3. Паттерн 1: Сетка/список без заголовка (чистый контент)
Применяется на главных экранах каталогов, табах поиска, гифок и избранного:
```kotlin
val topCutout = getTopCutoutInsetDp()

LazyVerticalGrid(
    columns = ...,
    state = stateGrid,
    contentPadding = PaddingValues(
        top = topCutout,
        bottom = bottomBarHeight
    ),
    // clipToPadding = false по умолчанию в Compose для LazyGrid
    modifier = Modifier.fillMaxSize()
) {
    items(...) { ... }
}
```
*Начальное состояние:* Первая строка карточек сдвинута ровно под вырез.  
*При скролле:* Карточки плавно поднимаются и проезжают сквозь область камеры.

### 5.4. Паттерн 2: Скроллящийся заголовок
Применяется на экранах тегов, альбомов, настроек (`ScreenAlbumList`, `ScreenTags`, `AppSettingsScreen`):
- Заголовок удаляется из `Scaffold(topBar = { ... })`.
- Заголовок помещается первым элементом:
  ```kotlin
  val topCutout = getTopCutoutInsetDp()

  LazyVerticalGrid(...) {
      item(key = "header", span = { GridItemSpan(maxLineSpan) }) {
          Box(
              modifier = Modifier
                  .fillMaxWidth()
                  .padding(top = topCutout)
                  .padding(horizontal = 16.dp, vertical = 8.dp)
          ) {
              Text(
                  text = title,
                  style = ...
              )
          }
      }
      items(...) { ... }
  }
  ```
- Кнопка «Назад» в этом хедере не рисуется.

### 5.5. Паттерн 3: Экраны коллекций (с сохранением кнопки «Назад»)
На экранах `LCollectionsTopBar`, `ScreenCollectionName`, `SavedCollectionName`:
- Кнопка «Назад» сохраняется.
- Хедер получает отступ `Modifier.padding(top = topCutout)`, чтобы кнопка «Назад» и название коллекции не попадали под глазок камеры.

### 5.6. Паттерн 4: Нескроллящиеся экраны (Главное меню `MenuScreen`)
- Иконки верхнего бара меню (`IconButton` для настроек, вибро-демо и P2P) сохраняют `Modifier.displayCutoutPadding()`.

## 6. План верификации

1. **Компиляция:** Полная сборка проекта через Gradle (`assembleDebug`) без ошибок типизации и отсутствующих ссылок на удаленный `useCutoutPadding`.
2. **Проверка на устройстве с вырезом камеры (Punch-hole/челка):**
   - Открыть экран со списком (например, альбомы, видео, теги). Убедиться, что первый элемент/заголовок расположен ниже камеры.
   - Прокрутить список вверх. Убедиться, что контент бесшовно уходит под верхний край экрана и виден в области бывшего статус-бара.
   - Проверить возврат назад системным жестом или кнопкой навигации Android.
3. **Проверка на устройстве без выреза (Samsung S7 / прямоугольный экран):**
   - Убедиться в отсутствии лишнего пустого зазора сверху — контент начинается от самого верха экрана.
4. **Проверка экрана настроек:**
   - Убедиться, что тумблер выреза отсутствует, а сам экран настроек открывается без наложений.
