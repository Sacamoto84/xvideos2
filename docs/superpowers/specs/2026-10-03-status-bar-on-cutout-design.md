# Статус-бар на устройствах с вырезом камеры

Дата: 2026-10-03  
Статус: дизайн утверждён  

---

## 1. Контекст и постановка проблемы

Приложение работает в режиме Edge-to-Edge со скрытым системным статус-баром
(см. [спецификацию выреза от 2026-09-21](2026-09-21-edge-to-edge-top-cutout-scroll-design.md)).
Экраны отступают сверху на высоту выреза камеры (`getTopInsetDp()`), поэтому на
устройствах с вырезом сверху остаётся пустая полоса цвета фона.

Попытки закрыть полосу оформлением (градиент, чёрная рамка со скруглением) не
подошли: градиент выглядит чужеродно, закреплённая рамка запрещает контенту
заходить под камеру.

### Целевое поведение

1. Полоса под вырезом — цвета фона, как было до градиента.
2. На устройстве с вырезом сверху системный статус-бар **виден**: он занимает эту
   полосу, и она перестаёт быть пустой.
3. Под статус-баром лежит полупрозрачная подложка цвета фона (70%): значки
   остаются белыми, контент при прокрутке слабо просвечивает. Полностью
   прозрачный фон не подходит — см. раздел 4, пункт 4.
4. На полноэкранных экранах статус-бар **скрыт**: просмотр картинок L,
   полноэкранная лента R, плеер X в развёрнутом (альбомном) режиме.
5. На устройствах без выреза статус-бар скрыт, как сейчас.

Это отменяет ограничение «системный статус-бар остаётся скрытым» из спецификации
от 2026-09-21 — только для устройств с вырезом. Остальные её решения (отступ
первым элементом списка, прокрутка контента под вырез) сохраняются.

## 2. Решения

| Решение | Альтернативы | Обоснование |
|---|---|---|
| **Один хозяин статус-бара в корне приложения** | Каждый экран сам показывает и прячет бар | Сейчас бар прячут в четырёх местах, и они перебивают друг друга при переходах — отсюда «страховочные» повторные скрытия. Одно место убирает гонки. |
| **Подложку рисует приложение (Compose)** | Цвет системного бара (`statusBarColor`) | На Android 15+ `statusBarColor` игнорируется: бар всегда прозрачный, подложка пропала бы на новых устройствах. |
| **Полноэкранный экран заявляет «скрыть» эффектом** | Список экранов-исключений в корне | Экран сам знает, что он полноэкранный. Корню не нужно знать про экраны модулей X / R / L. |
| **Счётчик заявок — класс через `CompositionLocal`, не `object`** | Глобальный `object` с `var` | `GlobalStateTest` запрещает заводить изменяемые глобальные точки незаметно; экземпляр от корня — обычная зависимость. |
| **Индикатор трафика не трогаем** | Сдвинуть под бар; прятать при видимом баре | Решение владельца: посмотреть на устройстве, потом решать. |

## 3. Дизайн

### 3.1. Правило видимости

Чистая функция в `core`:

```kotlin
fun shouldShowStatusBar(hasTopCutout: Boolean, hideRequests: Int): Boolean =
    hasTopCutout && hideRequests == 0
```

- `hasTopCutout` — `WindowInsets.displayCutout.getTop(density) > 0`. В альбомной
  ориентации вырез уходит вбок, верхний инсет равен 0 — бар скрыт.
- `hideRequests` — число экранов в композиции, попросивших скрыть бар.

### 3.2. Заявка «скрыть» (`core/.../common/ui/statusbar/`)

- `StatusBarRequests` — класс с наблюдаемым счётчиком `hideRequests`
  (`mutableIntStateOf`), методы `acquireHide()` / `releaseHide()`.
- `LocalStatusBarRequests` — `CompositionLocal`: экземпляр создаёт
  `MainActivity` и раздаёт экранам. Не `object`: новую изменяемую глобальную
  точку запрещает `GlobalStateTest`, а здесь это обычная зависимость композиции.
- `HideStatusBarEffect()` — берёт экземпляр из `LocalStatusBarRequests`;
  `DisposableEffect`: `acquireHide()` при входе в композицию, `releaseHide()` в
  `onDispose`.

Счётчик, а не флаг: при переходе между двумя полноэкранными экранами новый входит
в композицию раньше, чем старый её покидает; флаг сбросился бы в `false`.

Вызывают:
- `L_FullScreenImage.Content()` — всегда;
- `ScreenRedFullScreen.Content()` — всегда;
- `ScreenX_VideoPlayer` — только при `vm.isFullScreen` (внутри
  `OrientationAndSystemBarsEffect`).

Локальный плеер X окном и ориентацией не управляет, заявку не подаёт: для него
действует общее правило из 3.1.

### 3.3. Хозяин в корне (`app`)

`MainActivity.setContent` создаёт `remember { StatusBarRequests() }`, оборачивает
`ScreenRoot` в `CompositionLocalProvider(LocalStatusBarRequests provides …)` и
ставит рядом `StatusBarHost` (`app/.../screenRoot/molecule/`):

1. Получает `hideRequests` параметром и считает
   `visible = shouldShowStatusBar(hasTopCutout, hideRequests)`.
2. `LaunchedEffect(visible)` — `controller.show(statusBars())` или
   `controller.hide(statusBars())`. `systemBarsBehavior` остаётся
   `BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE`.
3. При `visible` рисует подложку: `Box` во всю ширину, высота —
   `WindowInsets.statusBars` сверху, цвет `Theme.background` с альфой из одной
   константы. Сейчас альфа `0.7` (исходно `0.6`, пробовали `0` — см. раздел 4,
   пункт 4). Подложка лежит
   поверх `ScreenRoot`, но под оверлеями блокировки и приватности.

`MainActivity.onResume()` и `configureWindow()` перестают безусловно прятать бар:
после возврата в приложение применяется то же правило (текущее значение
`visible` хранится в поле активности и переприменяется в `onResume`).

### 3.4. Уборка разбросанных скрытий

Удаляются вызовы `hide(WindowInsetsCompat.Type.statusBars())`:
- `MainActivity.onResume()`, `MainActivity.configureWindow()`;
- `OrientationAndSystemBarsEffect` (X) — четыре вызова;
- `LandscapeOrientation` (`core`, сейчас не используется) — один вызов.

Управление нижней панелью навигации и ориентацией в этих местах не меняется.

### 3.5. Отступ сверху

`getTopInsetDp()` возвращает большее из верхнего выреза и верхнего инсета
статус-бара:

```kotlin
max(WindowInsets.displayCutout.getTop(this), WindowInsets.statusBars.getTop(this)).toDp()
```

Бар скрыт — инсет статус-бара 0, значение прежнее. Бар виден и выше выреза —
контент начинается под баром, а не под подложкой.

### 3.6. Откат градиента

Удаляется `core/.../common/ui/atom/CutoutPlate.kt`; 11 файлов L, где стояла
плашка, возвращаются к исходным распоркам цвета фона.

## 4. Известные ограничения

1. **Индикатор трафика** (`AppNetworkSpeedMonitorLite`, правый верхний угол)
   наложится на системные значки. Оставлено решением владельца.
2. **Панели с `windowInsetsPadding(displayCutout)`** отступают строго по вырезу.
   Если на устройстве статус-бар выше выреза, они на несколько dp зайдут под
   подложку. Правится после проверки на устройстве, если проявится.
3. **Диалоги** — отдельные окна, правило на них не действует.
4. **HyperOS сама красит значки.** На HyperOS 3 (Android 16) системный
   `StatusBarRegionSamplingInteractor` замеряет яркость картинки под прозрачным
   статус-баром и переключает значки в чёрный над светлым контентом, игнорируя
   запрос приложения на белые (проверено `dumpsys`: `AppearanceRegion
   isLight=false` при `mDarkIntensity=1.0`). Документированного отключения из
   приложения не найдено. Поэтому подложка не прозрачная: альфа `0.7` держит
   замер тёмным. Порог Xiaomi закрыт; если значки всё же переключаются над белым
   контентом — поднять альфу.

## 5. Проверка

**Юнит-тест:** `shouldShowStatusBar` — вырез есть/нет × заявок 0/1/2.

**На устройстве с вырезом:**
- списки L, X, R, меню, настройки — бар виден, подложка полупрозрачная, контент
  при прокрутке просвечивает под ней;
- канал X — баннер под баром;
- просмотр картинок L, полноэкранная лента R, плеер X в альбомной — бар скрыт;
- возврат с каждого из них — бар возвращается;
- переход с одного полноэкранного экрана сразу на другой — бар не мигает;
- локальный плеер X: в портретной бар виден, в альбомной скрыт (вырез сбоку);
- свернуть и развернуть приложение на обычном и на полноэкранном экране;
- экран блокировки приложения.

**На устройстве без выреза:** бар скрыт везде, как раньше.
