# Спецификация декомпозиции экранов Compose: Atomic UI и стандарты код-ревью

> **Статус:** Согласовано (Brainstorming Complete) · **Дата:** 30.09.2026  
> **Область действия:** `:feature-x`, `:feature-r`, `:feature-l`, `:app`

---

## 1. Резюме понимания задачи (Understanding Summary)

- **Цель:** Исключение монолитных «god-файлов» экранов (500–1000+ строк), снижение когнитивной нагрузки и ускорение разработки через жесткую структуризацию UI на уровне файловой системы.
- **Принцип «1 компонент = 1 файл»:** Имя файла `Xxx.kt` обязано строго совпадать с именем функции `@Composable fun Xxx(...)`.
- **Двухуровневая классификация UI:**
  - `atom/`: неделимые базовые примитивы без вложенных кастомных виджетов экрана (чипы, аватары, кнопки, бейджи, плашки).
  - `molecule/`: составные блоки, собирающие несколько атомов (карточки видео, шапки, тулбары, панели фильтрации, диалоги).
- **Обязательные легковесные `@Preview`:** Каждый файл атома и молекулы обязан содержать минималистичное `@Preview` без тяжелых обёрток тем для быстрой отрисовки в панели Preview IDE.
- **Очистка файла экрана:** В корневом файле экрана (`Screen<Name>.kt`) размещается только класс Voyager `Screen`, привязка `ScreenModel`, сбор состояний и корневой `ScreenContent`, компонующий молекулы. Приватные вспомогательные Composable-функции запрещены (Hard Gate на код-ревью).
- **Массовый охват:** Проведение полного рефакторинга всех существующих экранов во всех модулях приложения (`:feature-x`, `:feature-r`, `:feature-l`, `:app`).

---

## 2. Допущения (Assumptions)

1. Общие UI-компоненты модуля, используемые более чем на одном экране, размещаются в `common/atom/` и `common/molecule/`.
2. Компоненты, специфичные для конкретного экрана, размещаются строго в локальных поддиректориях этого экрана (например, `screens/channel/atom/` и `screens/channel/molecule/`).
3. Превью используют минимальный набор моковых данных с пустыми обработчиками `{}` по умолчанию.

## 3. Журнал архитектурных решений (Decision Log)

| Решение | Рассмотренные альтернативы | Обоснование выбора |
|---|---|---|
| **Локальный Atomic Design для каждого экрана** | Глобальная библиотека компонентов модуля (`ui/atom`, `ui/molecule`), плоская папка `components/` | Локальная структура обеспечивает максимальную связность (high cohesion), изолирует экраны друг от друга и делает навигацию по проекту интуитивной. |
| **Двухуровневая модель (`atom` + `molecule`)** | Полный Atomic Design с `organism` | Уровень `organism` избыточен для мобильных экранов Compose и создаёт субъективность («это сложная молекула или организм?»). Двух уровней достаточно. |
| **Легковесные минималистичные `@Preview`** | Обязательная полная обёртка в `XvideosTheme(darkTheme = true)` и темный фон | Легковесные превью рендерятся в Android Studio мгновенно, не перегружая память IDE и ускоряя работу разработчика. |
| **Строгий запрет инлайн-компонентов (Hard Gate)** | Рекомендательный характер или разрешение функций до 15 строк | Исключения быстро приводят к разрастанию файлов экрана обратно до 500+ строк. Только строгий запрет гарантирует чистоту архитектуры. |
| **Сквозной рефакторинг всех модулей по фазам** | Рефакторинг только будущих экранов или только пилотного модуля `:feature-x` | Пользователь явно запросил полный охват всех существующих экранов. Поэтапное выполнение по модулям обеспечивает стабильность и отсутствие регрессий. |

## 4. Архитектурный регламент для `GEMINI.md`

```markdown
## Архитектура экранов Compose (Atomic UI & Code Review Rules)

### 1. Принцип «Один компонент — один файл»
- Каждая независимая Composable-функция должна располагаться в собственном `.kt`-файле.
- **Имя файла обязано строго совпадать с именем Composable-функции**: например, `@Composable fun ChannelSortBar` располагается в `ChannelSortBar.kt`.

### 2. Запрет монолитных экранов (Hard Gate на код-ревью)
- В корневом файле экрана (`Screen<Name>.kt`) размещаются **исключительно**:
  1. Voyager-класс экрана `class Screen<Name> : Screen`.
  2. Привязка `ScreenModel`, подписка на `StateFlow`/состояния и маппинг навигационных колбэков.
  3. Корневая функция компоновки экрана (`@Composable fun Screen<Name>Content`), которая только собирает готовые молекулы и макет верхнего уровня.
- **Любые вспомогательные, приватные или секционные Composable-функции запрещены в файле экрана** и обязаны выноситься в подпапки `atom/` или `molecule/`. Нарушение этого правила блокирует прохождение код-ревью.

### 3. Классификация компонентов
- **`atom/`**: неделимые базовые примитивы без вложенных кастомных виджетов экрана (чипы, аватары, бейджи рейтингов, кнопки, плашки таймингов).
- **`molecule/`**: составные блоки, собирающие несколько атомов или реализующие функциональную секцию экрана (карточка видео, шапка профиля, строка поиска, панель фильтров).

### 4. Обязательные легковесные `@Preview`
- Каждый файл в `atom/` и `molecule/` обязан содержать превью-функцию:
  ```kotlin
  @Preview
  @Composable
  private fun ComponentNamePreview() {
      ComponentName(...)
  }
  ```
- Превью оформляется **минималистично** (без громоздких обёрток тем и фонов), чтобы панель Preview в IDE открывалась и рендерилась максимально быстро.
```

## 5. Пошаговый план массового рефакторинга

### Фаза 1: Модуль `:feature-x`
1. `screens/channel/`: вынос `ChannelVideoItem`, `ChannelCollapsingLayout`, декомпозиция на `atom/` и `molecule/`.
2. `screens/search/`: вынос компонентов подсказок, истории и результатов из `ScreenXSearchTab.kt`.
3. `screens/actresses/`: разделение сетки, карточек и фильтров каталога актрис.
4. `screens/videoplayer/`: очистка экрана видеоплеера от инлайн-компонентов оверлеев и контролов.
5. `screens/dashboards/`: декомпозиция контролов и списков видео дашбордов.
6. `screens/subscriptions/`, `screens/history/`, `screens/favorites/`: приведение к стандарту.

### Фаза 2: Модуль `:feature-r`
1. `ui/profile/`: декомпозиция экрана профиля и его атомов.
2. `ui/niche/`: декомпозиция экрана категорий и ниш.
3. `ui/explorer/`: разделение вкладок гифок, ниш, создателей и загрузок.
4. `ui/fullscreen/`: декомпозиция оверлея полноэкранного плеера.
5. `ui/manager_block/`, `ui/root/`: приведение корневых экранов к стандарту.

### Фаза 3: Модуль `:feature-l`
1. `ui/screens/screenAlbum/`: разделение шапки альбома, сетки изображений и действий.
2. `ui/screens/screenAlbumList/`: карточки и списки альбомов.
3. `ui/screens/explorer/`: вкладки сохраненного, серверных лайков и подписок.
4. `ui/screens/screenFullScreen/`: компоненты постраничного просмотра.

### Фаза 4: Модуль `:app`
1. `MainActivity`, корневые контейнеры навигации и экраны настроек/блокировки.

## 6. Контроль качества (Quality Gates)

На каждом шаге каждой фазы в обязательном порядке выполняется:
```bash
./gradlew :<module>:detekt :<module>:testDebugUnitTest
```
Рефакторинг считается успешно завершенным только при условии:
- 0 замечаний Detekt.
- 100% прохождение всех модульных тестов.
- Соответствие всех затронутых экранов правилу «1 файл = 1 Composable + @Preview».
