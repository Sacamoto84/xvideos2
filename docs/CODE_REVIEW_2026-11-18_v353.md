## Находки

### C1 — Сохранение на телефоне может удалить закладку на сервере

Высокая серьёзность. Открыть работу из серверного избранного без локального импорта и нажать закладку. Локально работа добавится, а запрос `toggleServerFavorite` снимет уже установленную серверную отметку. Результат запроса игнорируется. Для синхронизации нужно передавать желаемое состояние и учитывать подтверждённое сервером значение. [ScreenNGallerySM.kt, строка 103](../feature-n/src/main/java/com/client/xvideos/n/ui/screens/gallery/ScreenNGallerySM.kt#L103)

### C2 — Удаление из устаревшего списка может вернуть закладку на сервер

Средняя серьёзность. Если после загрузки списка закладку удалили на другом устройстве, команда удаления выполнит повторное переключение. Даже при ответе `favorited = true` обработчик покажет «Удалено из избранного на сервере». Операция должна приводить к состоянию «удалено», а сообщение должно соответствовать ответу. [ScreenNServerFavoritesSM.kt, строка 120](../feature-n/src/main/java/com/client/xvideos/n/ui/screens/explorer/tab/saved/serverFavorites/ScreenNServerFavoritesSM.kt#L120)

### C3 — Удалённая манга остаётся в сетке и счётчике

Средняя серьёзность. В режиме «Сначала новые» удалить запись долгим нажатием. `FileDB.refresh()` обновляет тот же `SnapshotStateList`, а `remember(favorites, order)` возвращает старую копию, созданную `reversed()`. То же происходит при сортировке по названию и числу страниц. Ключом может служить `favorites.toList()`, который меняется вместе с содержимым. [N_ScreenSavedMangaTab.kt, строка 76](../feature-n/src/main/java/com/client/xvideos/n/ui/screens/explorer/tab/saved/manga/N_ScreenSavedMangaTab.kt#L76)

### C4 — Порядок «Сначала новые» и «Сначала старые» перепутан

Средняя серьёзность. Сохранить две работы в разное время и открыть список. `FileDB.refresh()` уже [сортирует файлы от новых к старым](../core/src/main/java/com/client/xvideos/common/fileDB/FileDB.kt#L235). `NEWEST` разворачивает этот порядок, `OLDEST` сохраняет его. Тест `NSortedSavedMangaTest` подаёт готовый список и закрепляет обратное поведение. [nSortedSavedManga.kt, строка 10](../feature-n/src/main/java/com/client/xvideos/n/ui/screens/explorer/tab/saved/manga/model/nSortedSavedManga.kt#L10)

### C5 — Фильтр поиска недоступен для выдачи из одной страницы

Средняя серьёзность. При первом входе или после запроса с одной страницей обе кнопки открытия фильтра скрыты вместе с пагинацией. Пользователь не может выбрать язык до первого запроса или уточнить короткую выдачу. Доступность фильтра должна быть независимой от числа страниц. [N_ScreenGallerySearch.kt, строка 208](../feature-n/src/main/java/com/client/xvideos/n/ui/screens/explorer/tab/search/N_ScreenGallerySearch.kt#L208)

### C6 — Переход на следующую страницу использует текст из поля ввода

Средняя серьёзность. Найти A, набрать B без отправки и перейти на страницу 2 выдачи A. Экран загрузит страницу 2 для B, хотя пользователь ещё не запускал этот поиск. Для пагинации нужно хранить последний отправленный запрос отдельно от редактируемого текста. [N_ScreenGallerySearchSM.kt, строка 111](../feature-n/src/main/java/com/client/xvideos/n/ui/screens/explorer/tab/search/N_ScreenGallerySearchSM.kt#L111)

### C7 — Пустой запрос оставляет результаты предыдущего поиска

Средняя серьёзность. Очистить поле после поиска и нажать поиск на клавиатуре. Ранний выход сохраняет карточки, номер страницы и пагинацию. Если старый запрос ещё выполняется, он также сможет опубликовать результат. При пустом эффективном запросе нужно отменить загрузку и восстановить начальное состояние. [N_ScreenGallerySearchSM.kt, строка 121](../feature-n/src/main/java/com/client/xvideos/n/ui/screens/explorer/tab/search/N_ScreenGallerySearchSM.kt#L121)

### C8 — Некорректный ответ сервера выглядит как пустое избранное

Средняя серьёзность. Если HTTP 200 содержит HTML или повреждённый JSON, `parseGalleryPageJson` вернёт пустую страницу по умолчанию. `getFavoritesPage` объявит успех и пропустит запасную загрузку. Стоит различать корректный ответ с пустым массивом и ошибку разбора. [NRepository.kt, строка 99](../feature-n/src/main/java/com/client/xvideos/n/repository/NRepository.kt#L99)

### C9 — Повтор поиска после сбоя открывает первую страницу

Низкая серьёзность. При ошибке на странице 3 кнопка повтора и завершение проверки доступа вызывают `search()`, который запускает `loadPage(1)`. Следует повторять запрос для страницы, на которой произошёл сбой. [N_ScreenGallerySearch.kt, строка 78](../feature-n/src/main/java/com/client/xvideos/n/ui/screens/explorer/tab/search/N_ScreenGallerySearch.kt#L78)

### C10 — Ошибка записи отображается как успешное локальное сохранение

Средняя серьёзность. При заполненном хранилище `FileDB.insert` возвращает `Result.failure`. `toggleFavorite` всё равно возвращает `true`, вследствие чего экран включает отметку и при активном входе отправляет изменение на сервер. В ветке удаления аналогично теряется ошибка `db.delete`. Публиковать новое состояние следует после успешной операции с файлом. [NFavoritesRepository.kt, строка 51](../feature-n/src/main/java/com/client/xvideos/n/saved/NFavoritesRepository.kt#L51)

### T1 — Импорт страницы избранного блокирует интерфейс

Средняя серьёзность. `screenModelScope` Voyager использует главный диспетчер. `importFavorites` синхронно проверяет и записывает файлы, затем `FileDB.refresh()` читает и десериализует весь каталог закладок. При большой коллекции обработка касаний и отрисовка задерживаются на всё время импорта. Файловую часть следует перенести на `Dispatchers.IO`. [ScreenNServerFavoritesSM.kt, строка 88](../feature-n/src/main/java/com/client/xvideos/n/ui/screens/explorer/tab/saved/serverFavorites/ScreenNServerFavoritesSM.kt#L88)
