# Код-ревью: Итерация 122 (2026-09-19)

**Фокус ревью:** `:core` (`com.client.xvideos.common.webserver`), `:app` (`WebServerSettingsSection.kt`).
Подсистемы: локальный HTTP-сервер (Ktor CIO), автоопределение локального IP-адреса и режима точки доступа (Hotspot), безопасность маршрутизации и предотвращение Path Traversal, разрешение медиафайлов коллекций Luscious/RedGifs/Xvideos, асинхронный рендеринг QR-кода и отказоустойчивость сервиса `WebServerService`.

---

## 1. Контекст и цели

1. **[T48] Исправление сброса `_lastError` в `WebServerState`**:
   При сбое запуска Ktor сервера метод `LocalWebServer.start` вызывал `WebServerState.setError(err.message)` и затем `WebServerState.updateRunning(false)`. Однако внутри `updateRunning` содержалась строка `if (!running) { _lastError.value = null }`, которая мгновенно стирала только что сохранённый текст ошибки. В результате пользователь в UI экрана настроек никогда не видел причину сбоя (занятый порт, ошибка биндинга сокета, конфликт прав).
2. **[C38] Корректное определение IP-адреса при раздаче интернета через Wi-Fi Hotspot**:
   В `NetworkIpHelper.getLocalIpAddress` первоочередной опрос `ConnectivityManager.activeNetwork` при включённом мобильном интернете (LTE/5G) возвращал IP-адрес сотового оператора (10.x.x.x или CGNAT, проходящие проверку `isSiteLocalAddress`). При этом сканирование локальных сетевых интерфейсов пропускалось, и на экране генерировалась ссылка на внешний/сотовый IP, к которому подключённый по Hotspot ноутбук не имел доступа. Необходимо отдавать приоритет `activeNetwork` только при наличии локального транспорта (`TRANSPORT_WIFI` / `TRANSPORT_ETHERNET`), а в остальных случаях принудительно опрашивать интерфейсы точек доступа (`ap*`, `softap*`, `swlan*`, `wlan*`).
3. **[S14] Защита от Path Traversal и поддержка точек в именах папок L в `LocalLibraryProvider`**:
   - `SAFE_ID_REGEX = Regex("^[a-zA-Z0-9_-]+$")` использовался в `resolveLMedia` и `resolveLCollectionMedia` для проверки имени папки элемента (`folderName` / `itemFolderName`). Имена папок в Luscious строятся генератором `lBuildFolderName` и часто содержат точки (от исходных имен файлов или версий). Из-за запрета точек в `SAFE_ID_REGEX` такие папки отсекались и сервер возвращал 404.
   - В `LocalWebServer.kt` маршрут `/assets/{path...}` проверял безопасность лишь наивной проверкой `contains("..")`. Заменить на `SafePath.normalizeRelativePath(path)` из `SafePath.kt`.
   - В `resolveLFolderUrls` добавить URL-экранирование названий папок и файлов.
4. **[P49] Устранение блокировки главного потока генерацией QR-кода**:
   В `WebServerSettingsSection.kt` генерация QR-кода происходила через синхронный `remember(serverUrl) { QrCodeGenerator.generateImageBitmap(...) }`. Расчёт матрицы ZXing и создание битмапа 480x480 (230 400 итераций) на Main-потоке вызывали пропуски кадров UI при запуске сервера. Перевести на `produceState` с расчётом в `Dispatchers.Default`.
5. **[T49] Защита `WebServerService` и `LocalWebServer` от сбоев**:
   - В `WebServerService` защитить чтение `Settings.web_server_port` и `Settings.web_server_keep_awake` проверкой `Settings.isInitialized`.
   - При сбое старта из-за `BindException` выдавать пользователю понятную ошибку («Порт $port уже занят другим приложением») и гарантированно останавливать наполовину инициализированный Ktor engine.
6. **[T50] Покрытие юнит-тестами**:
   Создать модульные тесты для `WebServerState` и безопасности резолва путей `LocalLibraryProvider`.

## 2. Выявленные замечания и исправления

### [T48] Стирание текста ошибки в WebServerState
- **Проблема:** В [WebServerState.kt](file:///g:/xvideos2/core/src/main/java/com/client/xvideos/common/webserver/WebServerState.kt) в методе `updateRunning`:
  ```kotlin
  if (!running) {
      _lastError.value = null
  }
  ```
  При любой ошибке старта `LocalWebServer.start` вызывал `setError(...)`, а следующей строчкой `updateRunning(false)`, что обнуляло `_lastError` обратно в `null`. Сообщение об ошибке никогда не отображалось в `WebServerSettingsSection`.
- **Решение:** Очищать `_lastError.value = null` только когда `running == true` (успешный повторный запуск очищает предыдущую ошибку).
- **Статус:** Исправлено.

### [C38] Ошибочный IP оператора связи вместо точки доступа Hotspot
- **Проблема:** В [NetworkIpHelper.kt](file:///g:/xvideos2/core/src/main/java/com/client/xvideos/common/webserver/NetworkIpHelper.kt) `ipFromActiveNetwork` считывал IP из `cm.activeNetwork`. При активной сотовой сети (LTE) `activeNetwork` принадлежит мобильному оператору. Многие операторы выдают серые IP (10.x.x.x), которые удовлетворяют условию `it.isSiteLocalAddress`. Телефон выводил на экран адрес `http://10.x.x.x:8080`, к которому подключённый по Wi-Fi Hotspot компьютер подключиться не может.
- **Решение:**
  - Проверять тип транспорта активной сети: извлекать `ipFromActiveNetwork` только если активная сеть имеет `TRANSPORT_WIFI` или `TRANSPORT_ETHERNET`.
  - При активной сотовой связи переходить к сканированию интерфейсов, где высшим приоритетом обладают интерфейсы точек доступа (`ap*`, `softap*`, `swlan*`, `wlan*`), а сотовые интерфейсы (`rmnet*`, `ccmni*`, `pdp*`, `tun*`, `dummy*`) исключаются.
- **Статус:** Исправлено.

### [S14] Защита от Path Traversal и поддержка точек в именах папок L
- **Проблема:**
  - В [LocalLibraryProvider.kt](file:///g:/xvideos2/core/src/main/java/com/client/xvideos/common/webserver/LocalLibraryProvider.kt) регулярное выражение `SAFE_ID_REGEX = Regex("^[a-zA-Z0-9_-]+$")` не допускало точек. При этом генератор папок Luscious `lBuildFolderName` сохраняет папки вида `album_hash_title.01`, из-за чего методы `resolveLMedia` и `resolveLCollectionMedia` возвращали `null` (404 Not Found) на вполне валидные сохранённые файлы.
  - В `sanitizeFileName` проверка не запрещала одиночную точку `.`.
  - В [LocalWebServer.kt](file:///g:/xvideos2/core/src/main/java/com/client/xvideos/common/webserver/LocalWebServer.kt) маршрут `/assets/{path...}` проверял только `contains("..")`, пропуская потенциальные обходы с кодированием или разделителями.
- **Решение:**
  - Добавлена функция `sanitizeFolderName(raw: String)` с паттерном `Regex("^[a-zA-Z0-9_.-]+$")`, явно отвергающая сегменты `.` и `..` и разделители.
  - В `resolveLMedia` и `resolveLCollectionMedia` проверка папок переведена на `sanitizeFolderName`.
  - В `LocalWebServer.kt` в маршруте assets задействована `SafePath.normalizeRelativePath(raw)`.
  - В `resolveLFolderUrls` пути экранируются через `encodePathSegment`.
- **Статус:** Исправлено.

### [P49] Блокировка Main UI потока при генерации QR-кода
- **Проблема:** В [WebServerSettingsSection.kt](file:///g:/xvideos2/app/src/main/java/com/client/xvideos/screenSettings/section/WebServerSettingsSection.kt) `val qrBitmap = remember(serverUrl) { ... }` выполнял генерацию QR-кода синхронно на UI-потоке в фазе композиции Compose.
- **Решение:** Заменить `remember(serverUrl)` на `produceState<ImageBitmap?>(initialValue = null, serverUrl)` с вычислениями в пуле `Dispatchers.Default`.
- **Статус:** Исправлено.

### [T49] Защита от падений при неинициализированных Settings и понятные ошибки занятого порта
- **Проблема:**
  - В [WebServerService.kt](file:///g:/xvideos2/core/src/main/java/com/client/xvideos/common/webserver/WebServerService.kt) чтение `Settings.web_server_port.field.value` и `Settings.web_server_keep_awake.field.value` без проверки `Settings.isInitialized` приводило к риску краша `UninitializedPropertyAccessException`.
  - При занятости порта Ktor выбрасывал `BindException`, что для пользователя отображалось как неинформативная строка стека.
- **Решение:**
  - Обернуть чтение настроек в `if (Settings.isInitialized) ... else 8080` и дефолты.
  - При `BindException` устанавливать текст ошибки «Порт $port уже занят другим приложением» и останавливать Ktor engine в блоке очистки.
- **Статус:** Исправлено.
