## Что подтверждено

### ⛔ Порядок инициализации не сломан (A1)

`App.onCreate` переписан: `App.instance` удалён, `StorageCleanupGate` и монитор
трафика берутся через `EntryPointAccessors` после `AppPath.init()`. Ошибка
здесь стоила бы старта приложения.

- Холодный старт: `topResumedActivity=.MainActivity`, процесс жив.
- `logcat` по pid: `FATAL EXCEPTION` — **0**.
- `crash.log` не изменился.

Точка входа — `SplashActivity`; `MainActivity` не exported, запускать её
напрямую через `am start` нельзя (Permission Denial).

### ⛔ `StorageCleanupGate` действительно отрабатывает (A1, задача 1)

Прямое свидетельство: `files/store/inbox` и `outbox` имеют метку времени
**момента запуска приложения**, а не более раннюю. Значит
`cleanupTransientDirs()` был вызван через gate и пересоздал staging-папки.

Это то, ради чего `App.instance` вообще существовал, — теперь ожидание
инжектируется как обычная зависимость.

### ⚠️ Хранилища читаются, числа сходятся с диском (A2, C2)

| Источник | Лог приложения | Файлов на диске |

### ⛔ Троттлинг код-доступа: полный цикл (S3)

Код-доступа на устройстве до проверки не было — пользователь включил его
специально. Пройден весь сценарий:

| Шаг | `failed_attempts` | `lockout_until` | `lockout_until_elapsed` |
| --- | --- | --- | --- |
| попытки 1-4 | 1 → 4 | `0` | `0` |
| попытка 5 | 5 | `1787084870665` | `530279162` |
| после истечения | 5 | срок в прошлом | срок в прошлом |
| верный код | ключей нет | ключей нет | ключей нет |

Записываются **оба** срока — это и есть суть правки. Блокировка включилась
ровно на пятой попытке (`FREE_ATTEMPTS = 4`), длилась 30 секунд
(`BASE_LOCKOUT_MS`), истекла, а верный код стёр счётчик и оба срока
(`resetFailedAttempts`).

**Почему перевод часов больше не помогает.** На момент замера остаток
блокировки составлял 4139 мс по настенным часам и 4062 мс по монотонным. Сдвиг
системного времени на сутки вперёд обнуляет только первый; `remainingMillis`
берёт максимум из двух и вернёт 4062 мс — лок продержится. До правки хранился
только настенный срок, и обнуление было бы полным.

Системное время устройства **не переводилось**: это изменение настроек чужого
телефона. Сценарий покрыт семью тестами `AppLockThrottleTest`, включая
перезагрузку (монотонные часы обнуляются, настенный срок держит).

### ▫️ Keystore не стёр учётные данные (S4)

`shared_prefs/secure_credentials.xml` на месте после нескольких запусков.
Правка различает повреждённый keyset и временно недоступный Keystore — второй
случай больше не ведёт к `deleteSharedPreferences`.

### ▫️ Манифест бэкапа — валидный JSON (C4)

Проверен файл из архива, созданного на устройстве 19.08.2026:

```json
{
  "schemaVersion": 1,
  "createdAt": "2026-08-19T04:57:45Z",
  "sections": ["X", "L", "R"],
  "paths": ["L", "R", "X"],
  "modes": { "L": "FULL", "R": "FULL" }
}
```

`schemaVersion` — число, `createdAt` в UTC, все поля на месте. Это выдача Gson
вместо прежней склейки строками: путь с кавычкой или бэкслешем теперь
экранирует библиотека, а не удача.

## Регрессия, найденная во время проверки

**Миграция A3 ломала приём коллекций от старой версии.** Дефект внесён
`31d8122`, исправлен `d10cfc9`.

Gson по умолчанию **не сериализует null-поля**. Значит сборки до перехода на
kotlinx писали манифест `L_COLLECTION` и `R_COLLECTION` вообще без ключа
`metadataFileName` — он там всегда `null`. В новой модели поле было объявлено
`String?` без значения по умолчанию, а для kotlinx это **обязательное** поле:

```
kotlinx.serialization.MissingFieldException
```

То есть бандл коллекции от старой сборки новая версия отвергала бы целиком.

**Почему тест на совместимость это пропустил.** При миграции я написал тест на
«манифест от Gson-версии», но составил его JSON вручную — с явным
`"metadataFileName":null`. То есть проверял формат kotlinx, выдавая его за
формат Gson. Тест был зелёным и не значил ничего.

Урок общий: тест на совместимость с чужим форматом должен опираться на
фактическое поведение источника, а не на представление о нём. Если источник
недоступен (как здесь — старая сборка), надо явно выписать его правила
(«Gson опускает null») и проверять по ним.

Сейчас в `P2pManifestCodecTest` 14 тестов, среди них разбор манифеста **без**
ключа `metadataFileName`.
