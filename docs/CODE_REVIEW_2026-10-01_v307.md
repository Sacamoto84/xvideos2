## Находки

### C1 — Сбой разбора страницы канала выглядит как «нет видео». Средняя.

[parserChannel.kt:405](../feature-x/src/main/java/com/client/xvideos/x/parcer/parserChannel.kt:405)

`parserChannelVideosResult` ловит любое исключение разбора и возвращает пустой
результат. Сменилась схема ответа или пришла страница вместо JSON — страница
ложится в `pagesCache` пустой, пейджер показывает «У этого канала пока нет
опубликованных видео», повтора нет до переоткрытия экрана. Тот же класс
дефекта, что C1 прохода 171, только на слое разбора.

### C2 — Повтор или пропуск id в ответе канала роняет сетку. Средняя.

[ChannelVideosPager.kt:141](../feature-x/src/main/java/com/client/xvideos/x/screens/channel/molecule/ChannelVideosPager.kt:141)

Сетка ключуется по `it.id`, а разбор не отсекает повторы и не проверяет id:
у DTO `id` по умолчанию `0L`. Два ролика без id или один ролик дважды на
странице — `IllegalArgumentException` о повторном ключе в `LazyVerticalGrid`.

### C3 — Профиль из каталога всегда открывается как модель. Низкая.

[ScreenX_ActressesIndex.kt:62](../feature-x/src/main/java/com/client/xvideos/x/screens/actresses/ScreenX_ActressesIndex.kt:62)

Каталог открывается и из рейтингов канала, но переход из него всегда передаёт
`isModel = true`, хотя у карточки есть `profileUrl`. Для канала это значит
адрес `/models/…`, параметр фильтра для модели и подписку в списке моделей
(если разбор шапки не переопределит тип).

Чего нет: формат ссылок рейтинга у канала на сайте не проверен.

### R1 — Нормализация slug профиля скопирована в пять мест. Низкая.

[ScreenX_ChannelSM.kt:71](../feature-x/src/main/java/com/client/xvideos/x/screens/channel/ScreenX_ChannelSM.kt:71)

Своя версия есть в `ScreenX_ChannelSM.cleanSlug`, `ChannelCollaborator.cleanSlug`,
`TagsMainUploaderPornstar.cleanHref`, `toSubscriptionItem`,
`SavedX_Subscriptions.cleanSlug` и в обработчиках поиска. Наборы префиксов
разные: у экрана канала нет одного из четырёх префиксов профиля и отсечения
хвоста пути и запроса, поэтому ссылка с этим префиксом даёт адрес вида
`/models/<префикс>/<имя>`.

### S1 — Флаги состояния канала больше никто не читает. Низкая.

[ChannelModel.kt:233](../feature-x/src/main/java/com/client/xvideos/x/model/ChannelModel.kt:233)

После `0222cb9b` экран не читает `isLoadingInitial`; `isLoadingMore` никогда не
становится `true`, `isEndReached`, `isEmpty`, `isSuccess` нигде не
используются. ScreenModel поддерживает состояние, которое ничего не показывает.

### S2 — Комментарий подгрузки каталога устарел. Низкая.

[ScreenX_ActressesIndexSM.kt:163](../feature-x/src/main/java/com/client/xvideos/x/screens/actresses/ScreenX_ActressesIndexSM.kt:163)

«Следующая прокрутка повторит запрос» — после `0222cb9b` повтор идёт только по
«Повторить» (`loadMoreError`).

### U1 — Фильтр моделей молча обрезает список до 60. Низкая.

[ChannelModelDropdownMenu.kt:135](../feature-x/src/main/java/com/client/xvideos/x/screens/channel/molecule/ChannelModelDropdownMenu.kt:135)

`take(60)` без подсказки: у студии с сотней моделей 61-я и дальше видны только
через поиск, а пользователь не знает, что список неполный.

### E1 — Разбор аватара компилирует регулярные выражения на каждую карточку. Низкая.

[parserActressesIndex.kt:130](../feature-x/src/main/java/com/client/xvideos/x/parcer/parserActressesIndex.kt:130)

Три `Regex(...)` создаются заново для каждой карточки без `src`; на странице
каталога их десятки. Вынести в `private val` верхнего уровня.

## Что осталось открытым

Все находки закрыты в `330d1385`.

Изменения поведения:

- Если на «чужой» префикс адреса ленты сайт отвечает не 404, а HTML-страницей,
  канал теперь показывает ошибку с повтором вместо «нет видео». Переход на
  второй префикс по-прежнему срабатывает только на пустой ответ; как отвечает
  сайт, не проверено.
- Ключи сохранённых подписок не меняются: имена записей FileDB не могут
  содержать `/`, и `xProfileSlug` возвращает для них прежний slug.

Отрицательные результаты:

- Регрессий `0222cb9b` не найдено: при неудачной первой загрузке страница 0
  показывает ошибку, повтор перезапускает `loadInitial`; отменённая первая
  загрузка не снимает отметку новой (проверка владельца в `finally`); при
  сбое следующей страницы каталога автоподгрузка ждёт «Повторить».
- Подписка: `isSubscribed` и `toggleSubscription` берут тип и slug по одному
  правилу, проверка реактивна (`mutableStateSetOf`).
- Смена сортировки и фильтра моделей отменяет задачи страниц прежней выборки;
  вытеснение кэша страниц затрагивает только страницы дальше 8 от загруженной,
  то есть не составленные пейджером.
- Состояния прокрутки сеток канала сбрасываются при смене выборки и
  создаются заново при повторном составлении страницы.
