### C1 — Клиент R повторяет безнадёжные запросы. Средняя.

[feature-r/.../network/http/ApiClient.kt:62](../feature-r/src/main/java/com/client/xvideos/r/network/http/ApiClient.kt:62)

`HttpRequestRetry` — три повтора по любому исключению с экспоненциальной
задержкой при таймаутах 30 секунд. Без сети лента показывает ошибку после
четырёх попыток с паузами, секунд через семь; при зависшем сервере четыре
таймаута дают около двух минут индикатора. В L тот же дефект закрыт в проходе
175: повтор только после обрыва работавшего соединения.

### C2 — Сбой поиска авторов оставляет результаты прошлого запроса. Средняя.

[feature-r/.../tab/search/ScreenRedExplorerSearchSM.kt:64](../feature-r/src/main/java/com/client/xvideos/r/ui/explorer/tab/search/ScreenRedExplorerSearchSM.kt:64)

При сбое список авторов не очищается, ошибка только пишется в лог. Поиск «abc»,
затем «xyz» без сети — под текстом «xyz» остаются авторы по «abc», сообщения
нет.

### C3 — Сбой загрузки профиля автора не показывается. Низкая.

[feature-r/.../profile/ScreenRedProfileSM.kt:161](../feature-r/src/main/java/com/client/xvideos/r/ui/profile/ScreenRedProfileSM.kt:161)

Ответ `readCreator()` разворачивается через `getOrNull()`: отказ сети становится

автора пустая, повторить нечем. В самой ветке `catch` `e.message.toString()`
даёт снекбар «null» для исключений без текста.

### C4 — Сбой загрузки ниши не виден и обрывает остальные запросы. Низкая.

[feature-r/.../niche/ScreenNicheSM.kt:93](../feature-r/src/main/java/com/client/xvideos/r/ui/niche/ScreenNicheSM.kt:93)

Метаданные ниши, похожие ниши и топ авторов грузятся подряд в одном
`launchCatching` без `onError`. Первый запрос упал — второй и третий не
выполняются, экран остаётся без шапки, сообщения и повтора нет. Три независимых
запроса к тому же идут последовательно.

### C5 — Открытие профиля перезаписывает сохранённую настройку вида. Низкая.

[feature-r/.../profile/ScreenRedProfileSM.kt:156](../feature-r/src/main/java/com/client/xvideos/r/ui/profile/ScreenRedProfileSM.kt:156)

`init` вызывает `setSelector(2)`, который пишет в настройку
`red_profile_selector`; других вызовов `setSelector` в коде нет. Настройка с
умолчанием 1 никогда не действует, а каждое открытие профиля пишет файл
настроек. Либо это константа и настройка лишняя, либо выбор вида должен
сохраняться и сброс его ломает.

### C6 — Название сайта и поисковый запрос в логе. Низкая.

[feature-r/.../pagin/ItemTopPagingSource.kt:51](../feature-r/src/main/java/com/client/xvideos/r/common/pagin/ItemTopPagingSource.kt:51)

### C7 — Индикатор обновления ленты — таймер на 500 мс. Низкая.

[feature-r/.../lazyrow123/LazyRow123.kt:122](../feature-r/src/main/java/com/client/xvideos/r/ui/ui/lazyrow123/LazyRow123.kt:122)

Жест обновления поднимает `isRefreshing`, ждёт 500 мс и сбрасывает его, не
глядя на состояние загрузки. На медленной сети индикатор исчезает раньше
данных, при сбое показывает «готово».

### C8 — `getRefreshKey` несовместим с `prevKey = null`. Низкая.

[feature-r/.../pagin/ItemTopPagingSource.kt:103](../feature-r/src/main/java/com/client/xvideos/r/common/pagin/ItemTopPagingSource.kt:103)

Три источника (лента, профиль, ниша) возвращают из `getRefreshKey` текущую
страницу, но всегда отдают `prevKey = null`; ветка `prevKey?.plus(1)`
недостижима. Обновление не с первой страницы начнёт список со страницы N:
страницы выше пропадут. Сейчас обновление запускается только жестом у верха
списка, дефект скрытый — любой программный `refresh()` его проявит.

### A4 — User-Agent R — зашитая версия браузера. Низкая.

[feature-r/.../network/http/ApiClient.kt:33](../feature-r/src/main/java/com/client/xvideos/r/network/http/ApiClient.kt:33)

Клиент R представляется одной фиксированной строкой, клиент L берёт строку из
общего `UserAgentProvider`. Строка устаревает вместе с версией браузера.

Чего у находки нет: блокировка по этой причине не наблюдалась.

### Проверено, находок нет

- **`BearerAuth`.** Токен запоминается до запроса; после 401 вход выполняется
  один раз на всех, повтор запроса — один; отмена пробрасывается.
- **Источники пагинации.** Отказ сети становится `LoadResult.Error`, конец
  ленты определяется по числу страниц из ответа, блокировки отсекаются набором.
- **Подсказки поиска.** Пауза ввода и отмена незаконченного запроса на месте.
- **Стек поиска.** Доступ под `synchronized`, глубина ограничена.
