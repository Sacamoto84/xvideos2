## Summary of Passes (809–816)

### Pass 809 — `:feature-l` (`Repository.kt`)
- **Finding:** In `deleteCache(data: String, config: RepositoryUriConfig)`, `data.toMD5()` was computed unconditionally even when `config == RepositoryUriConfig.DIRECT`, wasting MD5 hash calculation cycles.
- **Fix:** Added `if (config == RepositoryUriConfig.DIRECT) return` prior to computing the MD5 key.

### Pass 810 — `:feature-r` (`GifsInfo.kt`)
- **Finding:** `List<GifsInfo>?.sanitizeGifsInfoList()` allocated a `HashSet` and a new `ArrayList` even for single-element lists (common when requesting or updating a single GIF). Furthermore, `sanitizeTagsList` used verbose null/empty checks.
- **Fix:** Added a fast-path `if (this.size == 1) return listOf(this[0].sanitizeOrNull() ?: return emptyList())`, and updated `sanitizeTagsList` to use `safeTags.isNullOrEmpty()` and return `emptyList()` when empty.

### Pass 811 — `:feature-r` (`RedApi_Search.kt`)
- **Finding:** `searchGifs(searchText, ...)` dispatched network requests to RedGifs search endpoints for blank or whitespace-only queries, returning unbounded results or errors.
- **Fix:** Defined `EMPTY_MEDIA_RESPONSE = MediaResponse()` and added an early return `val trimmed = searchText.trim(); if (trimmed.isEmpty()) return Result.success(EMPTY_MEDIA_RESPONSE)`.

### Pass 812 — `:feature-r` (`RedApi.kt`)
- **Finding:** Niche retrieval methods (`getNiche`, `getNiches`, `getNichesRelated`, `getNichesTopCreators`, `getNichesTopTags`) sent network requests with blank niche placeholders if given blank strings.
- **Fix:** Added early trimmed checks returning empty results or failure before dispatching to the network client.

### Pass 813 — `:core` (`FileSearchHistoryStore.kt`)
- **Finding:** In `trim(limit)`, `table.all()` was unconditionally sorted and dropped even when the number of items was already below `limit`. In `refresh()`, empty tables still performed sorting and mapping.
- **Fix:** Added `if (all.size <= limit) return` in `trim`, and added fast return in `refresh()` if `all.isEmpty()`.

### Pass 814 — `:core` (`FolderTable.kt`)
- **Finding:** `all()` used `tableDir.listFiles { ... }?.mapNotNull { readRecord(it) }`, causing dynamic list growth during disk record loading.
- **Fix:** Added `if (dirs.isNullOrEmpty()) return@withLock emptyList()` and pre-sized `ArrayList<FolderRecord>(dirs.size)`.

### Pass 815 — `:core` (`AppDns.kt`)
- **Finding:** During DNS cache size limit eviction, `cache.keys.take(excess)` allocated an intermediate `List<String>` before iterating to delete entries.
- **Fix:** Used in-place iterator removal `val it = cache.keys.iterator(); while (it.hasNext() && count < excess) { it.next(); it.remove(); count++ }` avoiding collection allocation.

### Pass 816 — `:feature-x` (`SavedX_Downloads.kt`)
- **Finding:** In `loadFromDisk()`, `infos.mapNotNull { ... }.filter { it.id in videoIds }` created two sequential intermediate lists. Empty directories also performed unnecessary collection processing.
- **Fix:** Added fast exit when `allFiles.isEmpty()`, and fused `mapNotNull` and `filter` into a single loop appending directly into a pre-sized `ArrayList<ItemsX>(infos.size)`.
