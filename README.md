# xvideos2

Android-клиент для трёх сайтов сразу, с офлайн-библиотекой и передачей
сохранённого между телефонами напрямую.

| раздел | что умеет |
|---|---|
| **X** | ленты и поиск, теги, каналы и модели с подписками, избранное, история с позицией просмотра, плеер с превью кадра при перемотке, скачивание |
| **L** | альбомы и поиск, вход в аккаунт, лайки, коллекции, полноэкранный просмотр |
| **R** | ленты и поиск гифок, ниши, профили, лайки, коллекции, подписки, скачивание, блокировки |

Поверх разделов:

- **P2P-обмен** через Nearby Connections — без сервера и без интернета;
- **бэкап** всей библиотеки в ZIP;
- **код доступа** на вход, с маскировкой под калькулятор;
- **DNS-over-HTTPS** для сетевых запросов, картинок, видео и загрузок (кроме
  страниц, которые X грузит через WebView);
- **складные телефоны**: раскладка подстраивается под ширину окна;
- **плашка «сайт на техобслуживании»**, когда сайт раздела отвечает 503.

## Сборка

```bash
./gradlew :app:assembleDebug
```

Приложение ставится и запускается без настройки. Для релизной подписи положите
`keystore.properties` в корень (файл в `.gitignore`) — без него release
собирается debug-ключом, и публиковать такой APK нельзя. С этим файлом тем же
ключом подписывается и debug: сборки ставятся на устройство друг поверх друга
без удаления приложения. Обратная сторона — отлаживаемый debug-APK встаёт
поверх релизного с сохранением данных, поэтому наружу его не отдают.

### Проверки

```bash
./gradlew testDebugUnitTest detekt :app:lintRelease
```

Это гейт перед каждым коммитом (на Windows — `gradlew.bat`). Красный lint —
красный гейт, как и упавший тест.

- **1612 юнит-тестов** в 288 файлах (на 21.10.2026), включая сторожей архитектуры
- **detekt** — во всех пяти модулях, `ignoreFailures = false`
- **lint** — с `checkDependencies = true`, то есть смотрит и библиотечные модули

## Модули

```
:app          точка сборки: Activity, навигация, экран настроек, бэкап, замок
:core         базовый слой: тема, плеер, Coil, сеть и DoH, P2P, файловая БД, настройки
:feature-x    раздел X
:feature-l    раздел L
:feature-r    раздел R
build-logic   convention-плагин xvideos.android-library
```

Разделы не знают друг о друге и не знают про `:app`; общее живёт в `:core`.
Правило не на честном слове — его держат тесты в `:app`:

- `ModuleBoundariesTest` — границы между разделами;
- `LayerBoundariesTest` — слои внутри раздела: `model` → `network` → `common` → `ui`;
- `AdaptiveLayoutTest` — ширина и колонки только через `core/.../common/ui/adaptive/`.

У первых двух пустой BASELINE, и они падают в обе стороны: и на новом
нарушении, и на записи, которая больше не нарушается.

Общая настройка библиотечных модулей — `compileSdk`, `minSdk`, Java 17,
Compose, detekt — лежит в `build-logic/src/main/groovy/xvideos.android-library.gradle`,
а не дублируется по четырём файлам сборки.

## Где лежат данные

Всё во внутренней памяти, в `filesDir/store` — каталог недоступен другим
приложениям и файловым менеджерам. Файлы при этом не зашифрованы: код
доступа закрывает экраны, а не данные на диске (решение по S4 прохода 193).
Цена внутренней памяти: данные стираются вместе с приложением, и
единственный способ их сохранить — бэкап.

Дерево, форматы и порядок восстановления — в [docs/backup-format.md](docs/backup-format.md).

## Соглашения

**Комментарии и коммиты по-русски.** Комментарий объясняет **почему** так, а не
что делает код: чем это было раньше, каким симптомом обернулось, почему
выбранный вариант. Из-за этого в проекте много «надгробий» — записей о том, что
на этом месте стояло и почему ушло.

**Названия сайтов не пишутся** ни в коммитах, ни в логах, ни в документации —
только X / R / L.

**detekt с baseline.** `config/detekt/baseline.xml` — список принятых замечаний.
Он должен уменьшаться. Добавлять туда новое — крайняя мера; обычный путь —
починить.

**Ничего не считается работающим, пока не проверено.** Зелёная сборка не
доказывает поведение: юнит-тесты идут на десктопной JVM, и, например,
регулярное выражение, которое там компилируется, на Android может не
скомпилироваться — так уже случалось. Отсюда проверка на устройстве, в том
числе на складном, и привычка сверять API живыми запросами.
