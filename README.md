# xvideos2

Android-клиент для трёх сайтов сразу, с офлайн-библиотекой и передачей
сохранённого между телефонами напрямую.

| раздел | сайт | что умеет |
|---|---|---|
| **X** | xvideos | лента, теги, избранное, плеер, скачивание |
| **L** | Luscious | альбомы, лайки, коллекции, полноэкранный просмотр |
| **R** | RedGifs | ленты и поиск гифок, ниши, профили, лайки, подписки |

Поверх разделов: **P2P-обмен** через Nearby Connections (без сервера и без
интернета), **бэкап** всей библиотеки в ZIP, **код доступа** на вход,
локальный **журнал ошибок** для релизной сборки.

---

## Сборка

```bash
./gradlew :app:assembleDebug
```

Приложение ставится и запускается без настройки. Для релизной подписи положите
`keystore.properties` в корень — без него release собирается debug-ключом
(публиковать такой APK нельзя, ключ общеизвестен).

### Проверки

```bash
./gradlew testDebugUnitTest detekt :app:lintRelease
```

- **149 юнит-тестов** в 34 файлах, включая сторожей архитектуры
- **detekt** — во всех пяти модулях, `ignoreFailures = false`
- **lint** — с `checkDependencies = true`, то есть смотрит и библиотечные модули

## Модули

```
:app          точка сборки: Activity, навигация, экран настроек, бэкап
:core         базовый слой: тема, плеер, Coil, P2P, файловая БД, настройки
:feature-x    раздел xvideos
:feature-l    раздел Luscious
:feature-r    раздел RedGifs
build-logic   convention-плагин xvideos.android-library
```

Разделы не знают друг о друге и не знают про `:app`; общее живёт в `:core`.
Правило не на честном слове — его держат два теста в `:app`:
`ModuleBoundariesTest` (границы между разделами) и `LayerBoundariesTest`
(слои внутри раздела: `model` → `network` → `common` → `ui`). Оба с пустым
BASELINE, и падают в обе стороны: и на новом нарушении, и на записи, которая
больше не нарушается.

Общая настройка библиотечных модулей — `compileSdk`, `minSdk`, Java 17,
Compose, detekt — лежит в `build-logic/src/main/groovy/xvideos.android-library.gradle`,
а не дублируется по четырём файлам сборки.

## Где лежат данные

Всё во внутренней памяти, в `filesDir/store` — каталог недоступен другим
приложениям и файловым менеджерам, поэтому код доступа закрывает не только
экраны, но и сами файлы. Цена: данные стираются вместе с приложением, и
единственный способ их сохранить — бэкап.

Дерево, форматы и порядок восстановления — в [docs/backup-format.md](docs/backup-format.md).

## Соглашения

**Комментарии и коммиты по-русски.** Комментарий объясняет **почему** так, а не
что делает код: чем это было раньше, каким симптомом обернулось, почему
выбранный вариант. Из-за этого в проекте много «надгробий» — записей о том, что
на этом месте стояло и почему ушло.

**detekt с baseline.** `config/detekt/baseline.xml` — список принятых замечаний.
Он должен уменьшаться. Добавлять туда новое — крайняя мера; обычный путь —
починить.

**Ничего не считается работающим, пока не проверено.** Зелёная сборка не
доказывает поведение: юнит-тесты идут на десктопной JVM, и, например,
регулярное выражение, которое там компилируется, на Android может не
скомпилироваться (так и случилось — см. «Запуск 1» в `DEVICE_CHECK`). Отсюда
отдельный чек-лист устройства и привычка сверять API живыми запросами.
