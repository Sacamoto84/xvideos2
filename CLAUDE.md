# Правила проекта для Claude

Общие правила проекта живут в GEMINI.md и действуют для Claude без изменений:

@GEMINI.md

## Уточнения поверх GEMINI.md

- **Проверка перед коммитом — все модули, а не два.** Команда из GEMINI.md
  (`:feature-x` и `:app`) пропускает тесты `:core`, `:feature-l`, `:feature-r`.
  Перед коммитом запускать:
  `./gradlew testDebugUnitTest detekt` (на Windows — `gradlew.bat`).
  В отчёт и в сообщение пользователю пишется фактический результат, а не
  «должно быть зелёным».
- **Названия сайтов не пишутся** ни в коммитах, ни в логах, ни в документации:
  только сокращения модулей X / R / L. Это соглашение кодовой базы, а не
  обход фильтров.
- **Реактивность при выносе кода в atom/molecule.** `SnapshotStateList` и
  `mutableStateListOf` сравниваются по ссылке, поэтому
  `remember(list, id) { list.any { … } }` не пересчитывается при изменении
  списка. Производное от изменяемого списка — только через
  `remember(id) { derivedStateOf { … } }` или прямое чтение без `remember`.
  Перенос `derivedStateOf` в `remember` с ключом-списком — регрессия.
- **Молекулы и атомы не принимают ScreenModel** (`*SM`, `ViewModel`), даже
  nullable: экран сам разворачивает состояние в параметры и колбэки.

## Код-ревью

- Отчёт создаётся по [шаблону](docs/CODE_REVIEW_TEMPLATE.md), строка в
  [индексе](docs/README.md) добавляется сразу со статусом «открыт».
- Находка закрыта только с sha коммита. «Рабочий срез» вместо sha — статус
  «открыт».
- Ревью проверяет поведение, а не только раскладку по файлам: для
  рефакторинга-переноса сравнивать удалённые и добавленные строки и
  отдельно читать всё, что не является дословным переносом.

## Проверка на устройстве

- **P2P (отправка и приём) и «Поделиться» на устройстве не проверяются.**
  Владелец уже проверил эти сценарии. Их не включают в план ручной проверки
  и в списки ручных сценариев отчётов, по ним не запрашивают подтверждение и
  не помечают их как непроверенные.
