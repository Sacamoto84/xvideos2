# Правила проекта для Claude

Общие правила проекта живут в GEMINI.md и действуют для Claude без изменений:

@GEMINI.md

## Уточнения поверх GEMINI.md

- **Проверка перед коммитом — команда из GEMINI.md целиком:**
  `./gradlew testDebugUnitTest detekt :app:lintRelease` (на Windows —
  `gradlew.bat`). Сокращать её до одного-двух модулей или до отладочного lint
  нельзя: прежняя короткая команда пропускала тесты `:core`, `:feature-l` и
  `:feature-r`, а lint, пока его не было в гейте, молча не проходил (проход 193:
  правила извлечения данных без `domain`, принятые при чтении за исправные;
  ссылка на отсутствующий класс в release-манифесте, которую `lintDebug` не
  видит).
  В отчёт и в сообщение пользователю пишется фактический результат, а не
  «должно быть зелёным».
- **Названия сайтов не пишутся** ни в коммитах, ни в логах, ни в документации:
  только сокращения модулей X / R / L. Это соглашение кодовой базы, а не
  обход фильтров.
- **Реактивность при выносе кода в atom/molecule.** `SnapshotStateList` и
  `mutableStateListOf` сравниваются по ссылке, поэтому
  `remember(list, id) { list.any { … } }` не пересчитывается при изменении
  списка. Производное от изменяемого списка — только через
  `remember(id) { derivedStateOf { … } }` или прямое чтение без `remember`.
  Перенос `derivedStateOf` в `remember` с ключом-списком — регрессия.
- **Молекулы и атомы не принимают ScreenModel** (`*SM`, `ViewModel`), даже
  nullable: экран сам разворачивает состояние в параметры и колбэки.

## Складные телефоны

Приложение обязано корректно выглядеть и на раскрытом складном телефоне:
внутренний экран ~700–880dp, почти квадратный. При `targetSdk 37` система на
дисплеях от 600dp игнорирует портретный замок и запросы ориентации, так что
такое окно приложение получает всегда. Подробности — в
[спеке](docs/superpowers/specs/2026-10-14-foldable-adaptive-layout-design.md).

- **Ширина и колонки — только через `core/.../common/ui/adaptive/`:**
  `adaptiveGridColumns()`, `adaptiveUserGridColumns()`, `rowItemWidth()`,
  `adaptiveListPadding()`, `Modifier.adaptiveContentWidth()`,
  `currentWidthClass()`. Не `GridCells.Fixed(<число>)`, не
  `GridItemSpan(<число>)` (полная строка — `maxLineSpan`), не
  `screenWidthDp` и не ориентация — это держит сторож `AdaptiveLayoutTest`.
- **На Compact (< 600dp: телефон, внешний экран) разметка не меняется ни на
  пиксель.** Лимит уже 640dp (форма замка, клавиатура) — только через
  `capOutsideCompactDp`, иначе он сработает и на широком телефоне.
- **Новый экран или блок:** сетка — адаптивные колонки; ленивый список на всю
  ширину — `contentPadding = adaptiveListPadding(...)`, чтобы свайп работал
  по всей ширине; шапки, поля и ряды панелей — `adaptiveContentWidth()` в
  цепочке **после** фона, чтобы фон оставался на всю ширину. Исключение —
  лента страниц X (`BottomListDashBoardNavigationButtons2`): она на всю ширину,
  а на широком окне показывает больше номеров (`visiblePageNumbers`: 5 / 9 / 11).
- **Ряды, собранные вручную** (`chunked`, `FlowRow`), держат позицию по
  номеру ряда: при смене числа элементов в ряду позицию пересчитывать через
  индекс элемента, неполную строку `FlowRow(SpaceBetween)` добивать пустыми
  местами (`sectionRowFillers`).

## Дизайн-система

- **Ряд выбора одного варианта** (отбор, порядок, переключатель режимов) —
  только `ChoiceRow` из `core/.../common/ui/choice/`, не
  `SingleChoiceSegmentedButtonRow` напрямую. Стиль (`ChoiceRowStyle`)
  закрепляется за экраном в коде и выбирается владельцем; акцентный цвет
  передаёт экран. Сейчас «Лайки» и открытая коллекция L — `TABS` (C).
  Фильтры альбомов L, резервная копия и настройки пока на прямом Material3:
  их переводят на `ChoiceRow`, когда владелец назовёт стиль.

## Код-ревью

- Отчёт создаётся по [шаблону](docs/CODE_REVIEW_TEMPLATE.md), строка в
  [индексе](docs/README.md) добавляется сразу со статусом «открыт».
- Находка закрыта только с sha коммита. «Рабочий срез» вместо sha — статус
  «открыт».
- Ревью проверяет поведение, а не только раскладку по файлам: для
  рефакторинга-переноса сравнивать удалённые и добавленные строки и
  отдельно читать всё, что не является дословным переносом.

## Проверка на устройстве

- **Изменения раскладки проверяются и на складном** — AVD `Pixel_10_Pro_Fold`:
  внешний экран (как на телефоне), внутренний в портрете и в альбомной,
  Medium (`adb shell wm density 475`, потом `wm density reset`), раскрытие и
  сложение посреди прокрутки — позиция и вкладка сохраняются.
- **P2P (отправка и приём) и «Поделиться» на устройстве не проверяются.**
  Владелец уже проверил эти сценарии. Их не включают в план ручной проверки
  и в списки ручных сценариев отчётов, по ним не запрашивают подтверждение и
  не помечают их как непроверенные.
